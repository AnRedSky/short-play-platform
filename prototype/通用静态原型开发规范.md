# 通用静态原型开发规范

> 适用范围：以"可交互静态原型"为目标的任意 B 端 / C 端 Web 项目。原型用于演示导航架构、页面布局、业务流程、状态流转与角色权限差异，不连接真实后端、不承担生产交付。本规范沉淀自多模块 Hash 路由 SPA 原型的落地经验，新项目可按业务需要裁剪，但分层、命名、回归与交付口径保持一致。

## 一、原型定位与边界

1. **原型回答的问题**：信息架构是否完整、页面布局是否成立、核心流程是否闭环、不同角色看到的功能是否有差异。
2. **原型不做的事**：不接真实数据库与接口、不做账号鉴权与持久化、不做性能优化、不追求像素级视觉还原、不实现真实计算与算法。
3. **数据与状态性质**：列表、图表、详情均为演示数据；筛选、页签、表单、审核/处置结论、角色切换等状态仅存页面内存，刷新或切页后不保留。
4. **演示优先**：空态、加载态、错误态、权限不足态等关键状态要在原型中可演示；被省略的细节须在 README 或页面备注中写明。

## 二、技术选型基线

| 项 | 默认基线 | 可选调整 |
|---|---|---|
| 运行形态 | 纯静态站点，HTTP 静态服务访问，禁止 `file://` 双击打开 | 可由任意静态服务器托管 |
| 页面框架 | Hash 路由单页应用（SPA），路由切换不刷新浏览器 | 若项目团队熟悉，可替换为 Vue/React 轻量框架，但分层口径不变 |
| 脚本 | 原生 JavaScript（兼容 ES2019），无打包、无构建步骤 | 引入框架时须保持模块目录与职责分层 |
| 依赖 | 默认零第三方运行时依赖；图表、图标用内联 SVG 手绘 | 离线环境同样可跑；确需库时锁定版本并本地化，不依赖公网 CDN |
| 样式 | 原生 CSS，设计令牌（CSS 变量）集中管理 | 可用 SCSS/Tailwind，但令牌与组件分层保留 |
| 数据 | 内联 Mock 字典，不发网络请求 | 允许读取本地 JSON，但不区分前后端工程 |

## 三、通用目录结构

```
<project>-prototype/
├── index.html                  # 唯一入口：骨架容器 + 脚本/样式引用与加载顺序
├── README.md                   # 项目原型说明：运行方式、导航清单、角色与权限对照、边界
├── start.ps1 / start.sh        # 本地静态服务启动脚本（端口独立规划，避免冲突）
│
├── assets/
│   ├── css/
│   │   ├── base.css            # 设计令牌（颜色/尺寸/圆角/阴影/断点）、重置、布局骨架
│   │   └── components.css      # 通用组件样式：卡片、表格、表单、按钮、徽章、图表、弹窗、页签
│   │
│   └── js/
│       ├── data.js            # 数据层：全局 Mock 字典、演示身份、角色与枚举定义
│       ├── ui.js              # 组件层：无状态渲染助手，输入数据、返回标记/模板
│       └── app.js             # 应用层：路由注册表、导航、框架装配、内存态、权限判定、反馈组件
│
├── modules/                    # 业务域目录，一域一目录，目录名与路由前缀一致
│   ├── <domain-a>/pages.js     # 该域全部页面路由与渲染函数
│   ├── <domain-b>/pages.js
│   └── ...
│
└── docs/                       # 原型评审记录、业务对照清单、遗留问题（可选）
```

- 新增业务域：在 `modules/` 下新建同名目录与 `pages.js`，并在 `index.html` 脚本列表登记。
- 目录名、路由前缀、模块分组键三者一致，使用小写中划线（kebab-case）。
- 不按"页面类型"（列表页/详情页）拆目录，按业务域聚合；跨域复用的组件进 `ui.js`，不复制到模块内。

## 四、分层与职责边界

全局只暴露三个核心对象，职责单向依赖：数据层 → 组件层 → 应用层 → 模块层。

| 全局对象 | 所在文件 | 职责 | 禁止事项 |
|---|---|---|---|
| `DB`（或 `Data`） | `data.js` | 只读业务字典、演示身份、角色定义、枚举映射 | 不在渲染时改写数据；不引用组件层常量（加载顺序在后） |
| `UI` | `ui.js` | 纯渲染助手：卡片、指标、表格、图表、徽章、表单、空态等 | 不持有业务状态，不直接操作页面容器，不调用应用层 |
| `App` | `app.js` | 路由注册与匹配、导航、侧边栏/顶栏装配、内存态、权限判定、Toast/弹窗/筛选 | 不内联业务 Mock；业务页面逻辑下沉到模块文件 |

依赖方向：模块页面可调用 `DB`、`UI`、`App`；`UI` 不反向依赖 `App`；`DB` 不依赖任何上层。跨模块复用的数据与组件必须上收，禁止在多个模块文件内复制同一段字典或标记结构。

## 五、路由与模块注册规范

### 5.1 模块注册

每个模块文件通过注册表登记：

```js
AppModule.register({
  group: '<domain-a>',          // 分组键，与目录名、路由前缀一致
  label: '业务域中文名',         // 导航分组标题
  icon: '<icon-key>',           // 图标键，取组件层已登记图标
  routes: [
    {
      path: '<domain-a>/<page>', // 路由：域前缀/页面键，全局唯一，kebab-case
      title: '页面中文名',       // 菜单与面包屑标题
      icon: '<icon-key>',
      badge: '',                 // 可选角标文本
      render(params) {           // 返回当前页面视图（字符串或框架节点）
        return `...`;
      }
    }
  ]
});
```

### 5.2 路由规则

- 路由格式统一为 `域/页面`；带参数的详情页用查询参数（`?id=`），不在路径中塞动态段，避免注册表膨胀。
- 一条路由对应一个页面；页面内子视图用页签或内存态切换，不另开路由。
- 注册表在应用初始化时一次性装配；侧边栏从注册表派生，不手写第二份菜单结构。
- **兜底视图**：未匹配路由渲染"页面不存在（404）"；已匹配但当前身份无权访问渲染"暂无权限（403）"，两者文案、返回入口分开。

## 六、页面渲染规范

1. **视图结构统一**：页头（标题 + 描述 + 页面操作区）→ 卡片/栅格内容 → 表格/图表/时间线/空态；操作按钮置于页头操作区，行内动作用行内按钮。
2. **组件优先复用**：先查 `UI` 助手是否已有等价组件；新增通用组件补进 `ui.js` 与 `components.css`，不为单个页面复制样式结构。
3. **表格**：列定义与行数据分离，列可配自定义渲染；行点击跳转在配置中返回路径，不散落内联事件。
4. **图表**：数据序列、标签、配色显式传入；量级差异大的序列用双轴；图表助手处理刻度、图例、空数据兜底。
5. **事件绑定**：带表单、二次确认、状态流转的动作挂在模块内全局动作对象上（如 `XxxActions`），由动作函数调用 `App` 方法；**禁止**把多层引号嵌套的表达式写进内联事件属性，避免转义崩溃。
6. **内存态**：筛选条件、当前页签、处置/审核标记等存入应用层状态对象，按域命名隔离；刷新不保留属于预期行为。
7. **占位禁忌**：页面不允许出现 `undefined`、`null`、`NaN`、`[object Object]`、空字符串标签；派生数据取值须兜底默认值。

## 七、Mock 数据规范

- 业务字典统一上收数据层，按域分组命名（如 `orders / events / users / tenants`）；模块文件只保留临时派生与排序结果。
- 字段命名小驼峰；枚举值与字典键在全项目内一致（情感、状态、等级、渠道等映射集中定义）。
- 演示数据须自洽：名称、渠道、状态、时间、量级、归属关系前后能对上；同列表内不出现互相矛盾的状态。
- 身份、角色、套餐、租户等演示实体独立成组，不与业务内容字典混用；新增演示身份不要复用既有业务账号字典键。
- 数据量以能演示版式与状态为准（每类 5–15 条典型样本），不编造批量假数；涉及敏感信息用虚构主体。

## 八、样式规范

- **设计令牌集中**：主色、辅助色、中性色、风险/情感色、间距、圆角、阴影、字号、侧栏宽、顶栏高、断点全部定义在 `base.css` 的令牌层；组件与页面只引用变量。
- **类名**：kebab-case，轻量 BEM 分层（`card`、`card-head`、`card-title`、`stat-delta`）；不使用标签选择器覆盖通用组件。
- **文件分工**：令牌、重置、应用骨架进 `base.css`；可复用组件进 `components.css`；模块专属的局部覆写才允许内联或模块样式。
- **响应式**：至少定义桌面 / 中屏 / 窄屏三档断点；指标卡、双栏栅格、导航在窄屏按既有方式收窄；移动端抽屉导航属于未实现项时在 README 注明。
- **深色/浅色**：如项目需要双主题，令牌同时定义两套取值；原型阶段只做一套主题时不预留切换入口。

## 九、角色与权限演示规范

原型的权限差异用于演示"不同身份看到的菜单、页面、操作不同"，不实现真实鉴权。

### 9.1 身份与视角解耦

- **权限身份（RBAC）**：决定菜单可见性、页面可达性、操作入口显隐，挂角色码与权限码。
- **业务视角**（如部门视角、场景视角）：只调整页面文案与关注侧重，不参与权限拦截。
- 两套概念分开维护，避免"视角切换"被误当作权限控制。

### 9.2 三层权限判定

1. **身份层**：演示身份列表集中在数据层，含名称、角色码、是否平台级、权限码集合；顶栏提供身份切换下拉，状态存内存。
2. **路由层**：路由权限表集中在应用层（平台专属 / 限定角色 / 默认可见），不在各页面散落判定；侧边栏按身份过滤，组内无可见条目整组隐藏。
3. **按钮层**：操作入口用权限码条件渲染；无权限身份对应按钮不展示，而非置灰后点击报错。

### 9.3 权限口径

- 平台级身份自动放行全部路由；租户身份按角色码匹配路由表；业务角色按权限码控制动作。
- 新增受限路由：先登记路由表，再验证侧边栏过滤与 403；新增动作权限：先在身份权限集合登记，再接按钮判定。
- README 须列出各身份可见范围对照；原型边界注明：权限为前端内存态，不接后端鉴权、租户数据隔离与字段级权限。

## 十、交互反馈规范

| 反馈 | 要求 |
|---|---|
| 轻提示 | 操作成功/失败/信息用统一 Toast，文案为结果描述，不暴露技术细节 |
| 弹窗 | 标题、内容、底部动作区结构统一；遮罩点击可关闭；动作按钮绑定在动作对象 |
| 二次确认 | 不可逆操作（删除、提交、归档、开通）走确认弹窗，确认后执行并提示结果 |
| 筛选 | 查询/重置走统一筛选助手，条件存入内存态；无结果展示空态 |
| 页签 | 切换状态记忆在内存；默认选中项在路由或配置中显式指定 |
| 空态 | 无数据、无结果、无权限均有独立空态/引导入口，不留白屏 |
| 加载/错误 | 原型阶段可用占位文案呈现；真实项目接入后替换为加载与错误组件 |

## 十一、版本、回归与交付

### 11.1 版本与缓存

- 静态资源引用统一带版本号查询参数（`app.js?v=N`）；改动 JS/CSS 后递增版本号，避免浏览器复用旧缓存。
- 入口 HTML 不被强缓存；脚本加载顺序固定：数据层 → 组件层 → 应用层 → 模块层。

### 11.2 回归清单（交付前必须通过）

1. **语法检查**：全部脚本通过语法解析，零报错。
2. **全路由遍历**：逐一打开注册表内每条路由，页面非空、无占位文本、无报错；图表、表格、时间线正常渲染。
3. **角色遍历**：逐演示身份切换，核对菜单可见范围、受限路由 403、按钮显隐与权限表一致。
4. **控制台检查**：浏览器控制台零错误；告警记录但不阻断。
5. **主流程走查**：导航 → 筛选 → 详情 → 操作 → 反馈闭环可走通；弹窗、页签、跳转无阻塞。
6. **边界视图**：404、403、空态至少各抽查一条路径可正常展示并有返回入口。

### 11.3 交付物

- 可静态托管的原型目录；`README.md` 写明启动方式、端口、路由清单、角色对照、未实现项与原型边界。
- 提交信息遵循 Conventional Commits：`feat(proto):`、`fix(proto):`、`docs:`、`style:`、`refactor:`；批次主题进正文要点。
- 旧版本目录只读留档，不在其上直接改造；新版本在副本目录演进。

## 十二、新增页面 Checklist

- [ ] 在所属模块 `routes` 登记 `path / title / icon / render`，路径前缀与分组一致
- [ ] 数据先入数据层字典，页面只做读取与派生；字段与枚举口径一致
- [ ] 复用既有 `UI` 组件与设计令牌，不新造同类组件、不硬编码主题色
- [ ] 受限页面登记路由权限表；操作按钮接权限码判定
- [ ] 动作挂全局动作对象，弹窗表单不使用内联嵌套事件
- [ ] 页头 / 内容 / 空态结构完整，无占位文本，图表刻度与配色合规
- [ ] 升资源版本号，语法检查通过，全路由 + 全身份回归零报错
- [ ] README 路由清单、角色可见范围与未实现项同步更新

## 十三、常见禁忌（反模式）

- 在模块文件内复制另一个模块的字典、组件结构或样式；应上收复用。
- 把业务 Mock 写进应用层或组件层；三层职责混杂导致后续无法替换真实接口。
- 侧边栏菜单与路由注册表各写一份，两处口径漂移。
- 无权限按钮置灰后仍可点击报错；权限不足应在入口处不展示或直接进 403。
- 弹窗事件内联多层引号；事件函数与 DOM 结构混在字符串里难以维护。
- 依赖公网 CDN 或未锁定版本的库，导致离线演示或版本漂移。
- 改动样式/脚本不升版本号，回归通过但演示环境跑的是旧缓存。
- 把原型状态当持久化实现：页面刷新后状态丢失属于预期，不在原型内补本地存储持久化。
