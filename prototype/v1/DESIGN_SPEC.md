# 系统原型设计说明（Design Spec）

> 版本：v1.2 · 2026-11-18  
> 对应产物：`prototype/`（22 个业务页面 + 1 个状态规范页）  
> 依据：`docs/01-architecture/PRODUCT_FUNCTIONAL_DESIGN.md`、`IMPLEMENTATION_BASELINE.md`、`docs/02-requirements/FEATURE_INTERACTION_SPEC.md`、`docs/04-api/API_COVERAGE_MATRIX.md`  
> 定位：界面契约与验收参照。本文描述的是**目标交互**，不代表仓库当前已实现；页面内的状态变更只发生在浏览器 `sessionStorage`。

---

## 1. 设计判断

平台是一个**长时间驻留的生产控制台**，不是展示型站点。因此原型的取舍是：

1. 信息密度优先。表格、清单、键值对承载事实；装饰性图形一律不加。
2. 一屏一任务。每个页面只有一个主任务，次要动作降到工具栏与抽屉。
3. 状态诚实。无法由服务端确认的结果不显示为成功；未建设的指标不展示伪造数字。
4. 版本可见。凡是引用，界面上都能看到"引用了哪一版"以及"上游变了以后下游会怎样"。
5. 风险外显。阻断项、预算、失败原因、权限不足必须出现在视线内，而不是折叠在设置里。

对应到视觉：深色导航明确"我在哪个空间"，暖白画布降低长时间阅读疲劳，唯一强调色只分配给主操作与当前位置，状态色只表达状态。

## 2. 信息架构

### 2.1 四层结构

```text
企业层（组织边界）
├── 登录与会话
├── 企业工作台        跨项目运营视图：进度、待审、任务健康、预算、审计
├── 项目空间          项目列表 / 创建 / 生命周期
└── 企业设置          成员 · 角色与权限 · 部门与组织

项目生产层（project_id 为授权与数据边界）
├── 制作流程          7 步向导：设定 → 剧本 → 资产与分镜 → 画面 → 配音 → 质检审核 → 时间线与导出
├── 创意与立项        创意池 / 评分 / 通过立项生成项目草稿
├── 生产概览          七阶段链路、分集进度、阻塞、依赖影响
├── 故事圣经          版本化世界观与人物关系
├── 剧集与剧本        集次 / 场次 / 对白 / 剧本版本
├── 资产库            角色 · 场景 · 道具 · 参考素材 + 不可变版本
├── 分镜与镜头        Storyboard / Shot / Shot Contract
├── 生产流水线        WorkflowRun / NodeRun / 显式审核 gate
└── AI 任务           GenerationTask / Attempt / 成本

专项工作区（沉浸式单任务）
├── 质量与审核        QA 结果 + 人工决定 + 返工
├── 时间线            多轨编排 + 精确时码 + 版本
├── 成片导出          ExportJob + 校验 + 交付产物
└── 项目设置          成员 / 生成 / Profile / 预算 / 危险操作

配置与运营层
├── 能力与 Provider   capability 与默认模型绑定、secret 引用、健康检查
├── 用量与成本        区间成本结构、项目明细、预算阈值
└── 审计日志          只追加日志、筛选与导出
```

### 2.2 导航模型

- **侧栏**承担空间切换：工作台 / 项目 / 企业 / 配置与运营 / 原型规范。
- **顶栏**承担上下文：面包屑、项目选择器（带 `NYJM-26` 编码）、通知、当前用户与角色。
- **项目模块页签**只在项目上下文出现，13 个模块平铺，避免把生产流程藏进二级菜单；「制作流程」固定在首位，作为标准操作入口。
- 切换项目时前端必须清理上一项目的查询缓存、编辑草稿与任务订阅，并要求服务端重新下发权限上下文（原型中以项目选择器上的提示表达）。

### 2.3 角色与可见性

| 角色 | 主战场 | 默认可做 |
|---|---|---|
| producer | 工作台 / 生产概览 | 项目生命周期、成员、预算授权、交付确认 |
| writer | 故事圣经 / 剧集剧本 | 故事与剧本版本、场次与对白 |
| director | 分镜与镜头 | 确认 Shot Contract、审核决定 |
| artist | 资产库 / 分镜 | 上传资产、维护参考图、版本 |
| editor | 时间线 / 成片导出 | 编排、保存版本、创建导出 |
| reviewer | 质量与审核 | 运行检查、通过/拒绝、创建返工 |

导航只展示可访问的功能，但**服务端授权是最终边界**；原型中 403 页明确区分于空列表。

## 3. 页面职责卡

### 00 制作流程（推荐入口）
- 主任务：在不理解后台结构的情况下，把一集短剧从设定做到成片。
- 关键内容：7 步步骤条（每步标模型与状态）、当前步骤的输入表单、输出产物、模型与参数（Provider / 计费 / 耗时 / 失败策略）、本集产物、人工 gate、会话日志；第 3 步同时生成资产参考图与 Shot Contract，第 7 步先自动装配时间线再编码发布。
- 关键交互：单步生成（`待生成 → 生成中 → 已生成`，成功解锁下一步）；一键跑完整集（串行执行，遇人工审核停下）；质检后「审核通过 / 退回重跑」；画幅改为 16:9 生成返回 `QA_FRAME_RATIO_MISMATCH`，改回 9:16 可重跑；点产物看调用明细；重置演示。
- 约束：所有步骤只读上一步已冻结的产物；审核一次通过即生效，无多级会签、无 WAIVED；导出必须等 QA 与人工审核都完成。
- 契约：`GET /projects/:id/workflow-runs` 聚合 + 各步骤既有域接口；原型为**目标编排**，不新增后端。

### 01 登录与会话
- 主任务：进入工作空间。
- 关键内容：组织与环境标识、账号、密码、会话有效期说明。
- 异常：密码错误（含 `request_id`）、连续失败锁定、续期失败回到登录并保留原路由。
- 契约：`POST /auth/login`、`/auth/refresh`、`/auth/logout`、`GET /auth/me`。

### 02 企业工作台
- 主任务：判断"今天哪里需要我"。
- 关键内容：进行中项目、近 7 日任务、待审核、预算消耗；项目生产看板；最近任务；待审核队列；Provider 与队列健康；审计事件。
- 明确不显示：未接入的指标、估算为事实的数字。
- 权限：只读聚合，按组织与项目成员关系裁剪。

### 03 项目空间
- 主任务：选对项目进入生产。
- 关键内容：项目编码、状态、生产阶段、成员、集数/镜头、预算、最近活动。
- 关键交互：状态筛选 chip、创建项目（编码唯一，冲突 409）、进入真实 `project_id`。
- 空态：无任何项目成员关系时给出"申请加入"而不是"新建项目"。

### 04 成员
- 主任务：维护组织成员与其项目角色。
- 关键内容：部门、组织角色、项目角色、状态、最近登录。
- 生命周期：`invited → active → suspended → deactivated`。
- 高危动作：禁用、撤销会话、角色变更，全部写审计；撤销后 60 秒内新请求不可访问。

### 05 角色与权限
- 主任务：搞清"谁能做什么"。
- 关键内容：10 个权限码 × 6 个角色模板矩阵。
- 契约：矩阵必须与 `roles/constants.py` 的 `PERMISSION_CATALOG` / `ROLE_TEMPLATES` 一致；新增权限码需同步矩阵、OpenAPI 与负向测试。
- 边界：前端隐藏不是授权；跨项目读取、跨项目引用、URL 复用下载均为 403/401。

### 06 部门与组织
- 主任务：维护组织结构与项目归属。
- 关键内容：部门、负责人、成员数、在跑项目、邀请状态。
- 边界：私有化单组织，不做多租户计费、SSO/SCIM（本期）。

### 07 生产概览
- 主任务：一屏看清项目卡在哪。
- 关键内容：七阶段链路（设定/剧本/资产与分镜/画面/配音/质检审核/时间线与导出）、分集进度、阻塞与依赖 stale、成员、预算、里程碑。
- 关键交互：点击阻塞项进入对应模块；stale 影响分析抽屉展示受影响对象与三个动作（保留 / 重新生成 / 重新审核）。
- 数据：全部来自各域快照聚合，不是独立事实源。

### 08 故事圣经
- 主任务：把设定与人物关系定稿成可引用版本。
- 关键内容：版本列表、世界观、人物、关系、冲突、来源追溯（原文定位率、低置信度条目）。
- 关键交互：新建版本（`base_version` + 冲突 409）、与上一版对比、导出 JSON/PDF。
- 规则：已批准版本不可原位编辑；设定冲突只输出 issue，不自动合并。

### 09 剧集与剧本
- 主任务：按集次推进剧本与场次。
- 关键内容：集次列表、剧本正文（场次/动作/角色/对白）、场次与对白绑定率、版本历史。
- 关键交互：保存生成新版本；离开未保存提示保存/丢弃/取消；409 展示双方差异并允许比较合并。
- 规则：对白角色引用有效率要求 100%，未绑定阻断批准。

### 10 资产库
- 主任务：找到并固定可复用的资产版本。
- 关键内容：类型筛选、资产卡（版本、状态、引用数）、详情抽屉（元数据、checksum、版本、引用影响）。
- 关键交互：上传进入隔离区 → 扫描 → 探测 → checksum → 登记版本；被引用资产禁止物理删除（409）。
- 规则：资产必须 `project_id`；跨项目引用 403；撤回触发下游 hold。

### 11 分镜与镜头
- 主任务：把场次拆成可生成的镜头合同。
- 关键内容：分镜板（镜头卡：编号、时长、景别、状态）、Shot Contract 全字段（时长/景别/机位/运镜/画幅帧率/动作/对白）、锁定资产版本、连续性约束、生成面板、Attempt 记录。
- 关键交互：提交生成（幂等键 + 预算校验 + 输入快照）、未配置态展示、修订合同产生新版本。
- 规则：合同变更是新版本，不改变运行中任务的输入；必填缺失或引用版本不存在则拒绝提交。

### 12 AI 任务
- 主任务：判断任务为什么没出结果，以及下一步做什么。
- 关键内容：任务统计、任务表（能力/对象/状态/Attempt/耗时/成本）、详情抽屉（输入快照、Attempt 列表、错误码、产物可用性）。
- 关键交互：重试（新建 Attempt）、取消（`cancel_requested`，供应商不支持时记录真实结果）、未配置态切换。
- 规则：查询快照是最终事实；任务成功必须有已校验产物；失败区分可重试与不可重试。

### 13 质量与审核
- 主任务：对具体版本作出可追溯的决定。
- 关键内容：待审队列、对象版本、QA 三级结论、问题分级与证据（detector / score / span）、审核表单（决定/审核人/原因）、审核历史、门禁规则。
- 关键交互：通过并记录、拒绝并返工、单项转返工。
- 规则：决定绑定 `subject_version_id`，不可篡改；不提供 WAIVED；新版本不继承旧结论。

### 14 时间线
- 主任务：把已过审素材排成可导出的结构。
- 关键内容：预览屏与走带、时间线版本元数据（时长/帧率/time_base/采样率/引用数/审核态）、三轨（V/A/S）、片段属性（`timeline_start` / `source_in` / `source_out` / 帧区间）。
- 关键交互：播放头按 30fps 推进并联动时间码与 PTS；保存生成新版本；素材撤回后禁止新导出。
- 边界：明确声明不是专业 NLE；不支持转场、调色、关键帧动画。

### 15 成片导出
- 主任务：拿到可交付、可追溯的成片。
- 关键内容：导出队列（进度/阶段/状态）、交付产物（MP4/SRT/probe report + checksum）、Profile 白名单、ffprobe 校验清单、失败诊断（退出码/阶段/日志摘录/是否可重试）。
- 关键交互：新建导出（冻结快照；快照含撤回素材时 409 阻断）、取消、下载（短时签名，每次重鉴权）。
- 规则：校验全部通过才 succeeded；失败不提供半成品下载；重试使用新 Attempt。

### 16 创意与立项
- 主任务：把一句话卖点变成可执行的项目草稿。
- 关键内容：创意池（评分、来源、状态、目标集数）、立项字段映射（名称/编码/形态/集数）、前置条件与合规提示、评审意见。
- 关键交互：master-detail 切换；通过立项（生成 `draft` 项目、状态转 `approved`、计数更新）；退回（写原因）；AI 扩写；新建创意。
- 规则：立项前不产生资产、任务与费用；创意与项目一一对应，立项后创意只读。

### 17 生产流水线
- 主任务：判断一次编排跑到哪、卡在哪个 gate。
- 关键内容：WorkflowRun 列表（模板/触发/进度/状态/开始时间）、NodeRun DAG（六节点、状态色、耗时）、场景映射、节点事件、输入快照。
- 关键交互：切换 Run 重绘 DAG；暂停 / 恢复 / 取消变更 Run 状态与统计；新建 Run 入列；节点失败可重试。
- 规则：节点只消费已冻结输入；人工审核是显式 gate，不通过不自动放行；取消不回收已产出节点。

### 18 能力与 Provider
- 主任务：确认每个生成能力绑到了哪个模型、缺什么配置。
- 关键内容：六项能力目录（默认 Provider/模型、状态、p95、单价）、右侧配置表单（endpoint、secret_ref、超时、并发、单价）、未配置横幅、错误语义与成本说明。
- 关键交互：点行回填配置；保存改变行状态与已配置计数；测试连接按 `secret_ref` 是否存在返回不同结果；新增 Provider。
- 规则：`secret_ref` 只存引用不回显明文；未配置时任务失败关闭（`PROVIDER_NOT_CONFIGURED`），禁止回退 Mock。

### 19 用量与成本
- 主任务：看清钱花在哪、还能花多少。
- 关键内容：周期成本、调用量、单集均价、月底预测、成本结构（按能力）、项目用量明细、预算与 80% 预警。
- 关键交互：本月 / 上月 / 近 7 天切换重算数字与条形；保存预算并即时校验；恢复默认；导出 CSV。
- 规则：失败调用不计费；预算只影响后续任务校验，不回溯已产生费用；总额以服务端计费快照为准。

### 20 审计日志
- 主任务：还原"谁在什么时候改了什么"。
- 关键内容：八类动作日志（时间/动作/操作人/资源/结果/request_id）、kind chips、关键词与操作人 / 结果筛选、详情抽屉（payload、IP、request_id）、保留策略。
- 关键交互：筛选即时收窄列表；点行回填抽屉；导出当前筛选结果为 CSV。
- 规则：日志只追加不修改；敏感字段脱敏；审计查询必须带 `project_id` 或组织授权，禁止跨项目检索。

### 21 项目设置
- 主任务：维护项目边界与交付配置。
- 关键内容：基本信息（名称/编码/画幅/帧率/集数/时长上限/描述）、成员与项目角色、生成配置、导出 Profile、预算、危险操作。
- 关键交互：六个分页切换；添加成员；新建 Profile；归档 / 转移 / 删除需输入项目名确认。
- 规则：项目编码不可改（资产与导出文件名依赖）；跨项目复制必须先导出再导入并重新审核；删除为软删除，已导出产物保留。

## 4. 全局交互契约

| 主题 | 契约 |
|---|---|
| 版本 | 编辑对象保存即产生不可变版本；`current_version` 只是便捷指针；界面必须显示当前版本号 |
| 并发 | 保存携带 `base_version` / `If-Match`；冲突 409 展示差异，允许载入最新或比较合并，本地内容可存草稿 |
| 长任务 | 创建返回 `task_id` / `run_id`；页面轮询或 SSE 更新快照，断线后重拉；不阻塞页面 |
| 幂等 | 命令支持 `Idempotency-Key`；重复提交不产生第二个业务对象 |
| 权限 | 服务端二次校验身份、项目成员关系、资源 `project_id`；403 不伪装成空列表 |
| 失败 | 展示错误分类、`request_id`、是否可重试、允许的动作；不泄露堆栈 |
| stale | 上游新版只标记下游；已审核/已交付版本保持有效；不自动无限重跑 |
| 成功 | 只有服务端确认后提示；生成类必须有真实 Artifact / AssetVersion |
| 删除 | 默认软删除或归档；有引用时 409；撤回触发下游 hold |
| 原型态 | 页面内交互由 `assets/interactions.js` 驱动：`[data-open]` 回填、`[data-act]` 动作总线、`form[data-form]` 提交总线；变更写入 `sessionStorage`（`sp_proto_v2`），仅用于评审回放 |

## 5. 状态规范

每个列表/详情/编辑页必须实现以下 11 种状态，视觉与判据见 `pages/states.html`：

`loading` · `empty` · `error` · `forbidden(403)` · `not_found(404)` · `conflict(409)` · `stale` · `processing` · `success` · `unsaved` · `offline`

配套矩阵（页面 × 状态）已写入状态页，可直接作为前端验收清单；`●` 为必须实现，`○` 为视场景。

## 6. 设计语言

## 7. 与实施阶段的衔接

| 阶段 | 按原型接线的内容 |
|---|---|
| R1 身份与项目授权 | 登录/会话、成员、角色矩阵、项目上下文与 403/404 负向态 |
| R2 创作真实化 | 创意立项、故事圣经、剧本与场次、分镜；保存新版本与 409 冲突 |
| R3 资产加固 | 上传隔离、不可变版本、引用影响与删除 409 |
| R4 Mork 与生成 | 任务表、Attempt、重试/取消、`PROVIDER_NOT_CONFIGURED`、流水线与能力配置 |
| R5 QA/审核/返工 | 审核台、决定留痕、返工与 stale 传播 |
| R6 时间线/导出 | PTS 时码、TimelineVersion、ExportJob、ffprobe 校验 |
| R7 生产验收 | 概览页聚合、工作台指标、审计与导出交付闭环 |

前端接线顺序（与 `FEATURE_INTERACTION_SPEC.md` 一致）：项目上下文与统一错误/权限态 → stories/episodes/storyboards → assets → tasks → reviews → editor/exports → 移除演示数据。新增的 ideas / workflows / providers / usage / audit / settings 按同一顺序并入对应阶段，不单独开接线通道。

## 8. 评审待决

1. 「生产概览」是否作为独立页面（本原型假设是）；若并入工作台，需定义项目级入口。
2. 剧本编辑器是否需要场次视图与原文视图双模式（原型已可切换，但未做动效）。
3. 审核台采用"队列 + 工作台"双栏（原型方案）还是逐条全屏审阅，取决于单条审核内容量。
4. 时间线的片段属性面板是否需要常驻；原型假设常驻右栏。
5. 导出是否需要"交付确认"角色动作（当前仅 producer 有交付确认权限假设）。
6. 创意与立项是否独立成页，还是并入项目空间的"新建项目"流程（当前独立成页，先验证字段量）。
7. 生产流水线是否允许人工拖动节点顺序（当前固定模板，仅展示与暂停/取消）。
8. 用量与成本是否需要财务口径的对账单导出（当前只演示 CSV 明细）。
9. 「制作流程」是否成为真实前端的唯一标准路径（专业页只做下钻与例外处理），还是仅作为演示向导保留。
