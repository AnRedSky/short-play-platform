# v9.3.2 真实业务一致性审计

审计目标：原型不能只“看起来像产品”，每个按钮都必须对应真实业务动作，页面数据必须来自当前项目，刷新后状态不能丢。

## 本轮确认并修复

### 1. 剧本审核不能跨项目

- `creation/review` 改为按 `query.id` 取项目内剧本；没有剧本时显示空态，不再回退到全库第一条。
- 分集覆盖、待审状态、锁定状态、历史审核均按项目过滤。
- 提交审核、通过、退回按按钮携带的剧本 ID 执行，不再默认操作 SP-26031。
- 锁定版本只保留“查看正式版本 / 发起局部修改”，不能再重复提交审核。

### 2. 剧本工作台与拆解页必须显示当前项目

- `creation/script` 使用真实镜头数据生成场次、镜号、时长、状态、版本与审核基准，不再固定 8 场 20 镜。
- `creation/breakdown` 改为按项目渲染：集数、场次、人物、场景、道具、镜头、资产确认、引用链、自检项全部来自当前项目。
- 生产中的项目不再显示“重新拆解”，改为“查看制作流水线”，避免绕过冻结计划再次拆解。
- 时长自检按 10%（最低 5 秒）容差，避免把系统性时长偏差误报为数据错误。

### 3. 导演规划不能写死一个项目

- `director/plan` 的 24 集表、KPI、生产门禁、待处理资产、链路阶段均按当前项目计算。
- 生产中项目隐藏“固化生产计划”，改为“查看生产流水线”；导航按钮统一携带项目 ID。
- `director.freezePlan` / `director.replan` 按项目 ID 执行，不再默认操作第一个项目。

### 4. 局部修改必须限定影响面

- `creation.partialScript` 要求指定剧本所属项目与集号，只影响该集已通过镜头。
- 无集号、集号越界、没有已通过镜头、未勾选保留镜头都会被拦截。
- 创建局部修订任务，同时把该集质检置为进行中、时间线标脏；不再改动其他项目。

### 5. 后期页面动作要落到真实入口

- `post.openTimeline` 从 Toast 改为进入 `post/timeline` 并带上集号。
- `post.reviewHistory` 从 Toast 改为真实审核抽屉，按当前项目过滤。
- 时间线页只列当前项目的时间线；标题跟随所选集，不再固定显示 E17。
- 时间线轨道按当前集分镜重建：视频轨 18 个镜号、对白/音效按该集镜头过滤，切换集次会换内容。
- 直接打开 `?ep=16` 也能生效，输出成片按 URL 集次执行，不再被上一次内存状态覆盖。

### 6. 清理重复演示动作

- 删除 `post.*` 与 `cost.adjustBudget` 的早期演示实现，保留真实业务层。
- 全库仍有同名动作重复注册，当前依靠后注册覆盖先注册，功能未冲突，但属于结构性风险，列入待清理项。

## 仍未闭环的部分

1. `director/storyboard`、`director/shots`、`director/cast`、`director/world`、`video/*` 仍以 SP-26031 为主，跨项目进入时可能显示旧项目数据。
2. `post/timeline` 已按集重建轨道，但剪辑操作（裁切、顺序调整、替换片段）仍未实现。
3. `creation/partialScript` 只创建修订任务，尚未实现“生成修订稿 → 审核 → 受影响镜头重生成”的完整回流。
4. `finishPost` 把处理中的字幕直接置为已通过，缺少独立字幕校对动作。
5. `resolveTimeline` 只更新版本号与标脏计数，没有替换标脏片段对象。
6. 51 个同名动作尚未系统清理。
7. `INTERACTION-SPEC.md`、`DESIGN-REVIEW-V9.1.md`、`TRACEABILITY.md` 尚未同步到 v9.3.2。
