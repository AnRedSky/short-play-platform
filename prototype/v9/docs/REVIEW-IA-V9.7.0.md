# 工作台首页 vs 项目列表：功能冗余与内容错乱评审

- 评审对象：v9.6.0 静态交互原型（`prototype/v9`）
- 评审范围：`workspace/home`（工作台首页）、`workspace/projects`（我的项目）、`projects/list`（项目列表）、`projects/workflow`（制作流水线）
- 结论：**不是"轻量重复"，而是三个项目清单页 + 一个首页复制了流水线核心内容，并伴随 9 处口径不一致。建议按方案 A 做结构收敛，不建议只改文案。**

---

## 一、结论摘要

1. 项目这个实体有 **3 个清单页**（工作台首页的项目区、我的项目、项目列表）、**4 个"新建项目"入口**、**3 种粒度的"下一步"**、**3 个互相打架的"待办数"**。用户在同一套菜单里做同一件事，要判断三次"我该点哪个"。
2. 工作台首页的 13 个区块里有 **4 对 1:1 重复**（指标卡与其正下方的明细卡各算一遍同一件事），并有 **3 块内容与制作流水线完全同源**（8 阶段链路、分集板、下一步），首页实质上成了流水线的第二份渲染。
3. 更严重的是"乱"：**同一屏出现两个不同来源的"预算已用 %"、"可见项目成本"标签下装的是"我负责/我参与"的合计、待决策数三个算法并存且其中一个从未被渲染**。这类问题改样式改不掉，必须统一取数口。
4. 权限设计也错位：`workspace/home` 用 `analytics.own`（"个人产出统计"）做门禁，导致企业管理员、部门管理员、审计、运维 **四个身份看不到"工作台首页"**——而它本应是全员首屏。

## 五、方案 A：分层收敛（推荐，改动可控）

### 5.1 三页各答一个问题

| 页面 | 唯一职责 | 一句话判据 |
| --- | --- | --- |
| 工作台首页 | **今天我要做什么** | 只出现"当前这一部戏的下一步 + 待我处理的事 + 还剩多少钱"，不出现任何项目清单与生产板 |
| 项目列表 | **我有/能看哪些戏，各自到哪了** | 唯一项目清单，吸收"我的项目"的关系筛选 |
| 制作流水线 | **这部戏具体走到哪一步** | 唯一制作现场，8 阶段、集板、门禁只在这里 |

### 5.2 菜单调整

| 现状 | 调整后 |
| --- | --- |
| 创作工作台 / 工作台 / 工作台首页 | 创作工作台 / **我的工作台** / **今日工作台**（原首页） |
| 创作工作台 / 工作台 / **我的项目** | **删除**（关系筛选并入项目列表） |
| 创作工作台 / 工作台 / 指令式生产助手 | 保留 |
| 短剧制作 / 立项与项目 / 项目列表 | 保留，成为唯一清单 |
| 短剧制作 / 立项与项目 / 新建项目 | 保留为菜单项（页面内表单仍是唯一立项入口） |

改动量：路由 66 → 65，删除 `workspace/projects` 路由与 `workspace.tab` 动作（309 → 308），菜单 owner 可见链接 49 → 48。

### 5.3 首页区块去留（13 → 7）

| 区块 | 处置 |
| --- | --- |
| work-hero（当前项目） | **保留**。三个跳转按钮收为 1 主（继续这一集）+ 1 次（打开流水线），删掉"查看生成结果""剧本与分镜"（下一步面板已覆盖） |
| next-panel（下一步） | **保留**，收为 3 条，主 CTA 用 `workflow.next[0]`，底部两个按钮只留"打开制作流水线" |
| 生产链路（8 阶段） | **删除**，移入流水线（已存在） |
| 工作台入口（九模块 chip） | **降级**为 hero 下方一行纯文本链接（业务方案 §20.2 要求入口，但不该占一张卡片的标题位） |
| 分集 ep-strip | **删除**，集维度只在流水线集板出现 |
| 待我决策 | **合并**进"待我处理"（见 5.5） |
| 最近产出 | **保留**（3 张缩略） |
| 成本与风险（4 mini KPI） | **保留**，但只保留"成本/预算"一项口径，附带 1 条风险 notice |
| 4 个 metric | **合并**为一行 4 项汇总，每项带下钻链接 |
| 待审核事项卡 / 最近交付卡 / AI 消耗卡 / 个人资源卡 | **删除**（各与上面的 metric 1:1 重复），信息由 metric 下钻承接 |

结果：13 → 7 个区块，首屏即可看到"下一步 + 待处理"，符合单人主线。

### 5.4 项目清单合并规则（`projects/list` 单页承载）

顶部两级筛选，互不干扰：

1. **关系**：我负责 / 我参与 / 待我审核 / 全部可见（末项仅 admin、dept、auditor 可见，满足"可见≠拥有"）
2. **状态**：全部 / 进行中 / 待我审 / 异常 / 已交付 / 草稿（沿用现有 seg-chips）

字段合并（取"我的项目"的准字段 + "项目列表"的视觉）：

| 字段 | 取值 |
| --- | --- |
| 封面 + 项目名 + 编号 + 题材 | 卡片头（沿用现有 project-cover） |
| 状态 pill / 负责人 / 我的角色 tag | 卡内 meta；角色只在非负责人时显示 |
| 阶段 phase + 已通过质检 X / 总 Y 集 | 替换掉现在的"完成 %"单值，避免两套进度口径 |
| 预算 miniBar + ¥/¥ | 统一 miniBar，数字放在 title |
| 下一步（`wf.next[0].title`） | 保留，这是列表页相对首页的唯一价值锚点 |
| 操作 | 主 CTA「继续制作」→ 流水线；次「项目档案」→ 详情 |
| 底部两块（状态分布环图、状态机提示） | 环图压成工具栏右侧一行小统计；状态机提示移入 `projects/lifecycle` |

### 5.5 统一取数口（`derived.js`）

新增 / 修改三个函数，页面不再自己拼条件：

```js
derived.duties(me)      // 待我处理：合并 通知(owner=我) + 审核节点 + 质量待判断，返回 {items, count}
derived.home(me)        // 只返回 counts，明确标注 scope: "mine"；不再返回未被使用的 decisions
derived.budgetOf(scope) // scope = "mine" | "visible"，标签与取数同源，禁止一页两种 scope
```

配套硬规则（写进 README 派生数据章节）：

- 一页之内同一个指标只能有一个 scope；
- "待办数""待审核数""质量待判" 一律走 `duties()`；
- 首页当前项目规则固定为 `顶栏上下文 → 最近更新的我负责项目 → 空态`，**删除 `生产中` 与 `mine[0]` 隐式回退**（`workspace/pages.js:25`）。
- 预算百分比统一用 `workflow(p).bgPct`（项目预算），首页如需多项目合计，标签必须写"我负责项目合计"。

### 5.6 权限修正

`workspace/home` 权限码由 `analytics.own` 改为 `project.read`（或新增 `workspace.read` 并授予 admin / dept / auditor）。理由：它是全员首屏，不是个人统计；`analytics.own` 只应属于 `analytics/me`。改后 owner 49 条不变，admin 33 → 34，auditor 24 → 25。

## 六、方案 B：整体调整（改动大，收益更高）

如果这一版要一并解决"实体归属"，做下面四步：

1. **一级菜单重构**：`创作工作台` 改名为 **`我的工作台`**，只保留"今日工作台 + 待办与通知"；生产流程的整体入口全部收进 **`短剧制作`**。
2. **项目提升为流程起点页**：`短剧制作` 的第一个二级改为 **`项目`**，其下三级只有 项目列表 / 制作流水线 / 新建项目 / 项目详情（hidden）/ 生命周期；`项目列表` 作为进入"短剧制作"的默认落地页。
3. **首页降级为待办台**：首页不再有任何项目卡片区，只保留"今日这一部戏"的一行摘要 + 待办 + 审核 + 预算风险 + 最近产出，全部带下钻。项目相关判断一律回清单页做。
4. **顶栏项目上下文收敛**：切换抽屉保留，但"流水线"快捷入口与首页的项目摘要共用同一个 `App.currentProject()`，不再有第二套 feat 选取逻辑。

A 与 B 的取舍：

| 维度 | 方案 A | 方案 B |
| --- | --- | --- |
| 改动面 | 删 1 路由 + 改 2 页 + 3 个 derived 函数 | 菜单重构 + 4 页重排 + 顶栏逻辑 + 全部审计文档重写 |
| 风险 | 低，回归可覆盖 | 中，`regress / _smoke / _e2e / TRACEABILITY` 需整体重跑 |
| 解决冗余 | 解决清单三份、指标四对、链路两份 | 在 A 基础上再解决"项目归属跨域"与"首页越权承载生产现场" |
| 建议 | **先做 A，观察一轮走查** | 若这一版是交付前最后一次 IA 调整，直接做 B |

## 八、验收标准

1. 全站只有一个项目清单页；`#/workspace/projects` 返回 404 或重定向到 `projects/list`。
2. 首页不出现任何多项目列举、集卡、阶段链路；区块 ≤ 7。
3. 首页任一同屏指标不出现两个来源：预算、待办、质量三项各自唯一。
4. 六种身份都能进入首页；管理员在清单页可见"全部可见"筛选，"我负责"为空时给出解释文案。
5. "下一步"只在两个页面出现：首页（1 主 2 备）、流水线（1 主 3 备）；清单页只展示标题，不带可执行动作。
6. 4 个 metric 与明细卡不再成对出现（0 对）。
7. 回归脚本全绿，动作注册无重复、无失效内链、26 个项目域页面阻断不变。

## 九、明确不建议的做法

- **不建议把首页做成"数据大屏"**：单人主线的最短路径是"点下一步"，KPI 越多首屏越慢。
- **不建议"我的项目"与"项目列表"都保留只改文案**：两份实现必然再次漂移，这正是 R2/R3/R4 的成因。
- **不建议删掉"九模块入口"**：业务方案 §20.2 有明确要求，改为一行链接即可。
- **不建议在首页保留"8 阶段链路"以替代流水线页**：首页没有门禁与集板，替代不了，只会变成第三个半成品流水线。
