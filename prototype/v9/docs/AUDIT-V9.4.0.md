# V9.4.0 审查记录：项目上下文、菜单链路与真实数据流

审查对象：`prototype/v9` 全站 17 个模块、65 条路由。默认身份 `i-owner`（林知远，项目负责人）。按真实短剧生产顺序「项目 → 创意/剧本 → 导演 → 视频 → 音频 → 后期 → 质量 → 审核交付 → 任务/资产/成本 → 通知/经营/合规」逐组检查入口、数据归属、动作落点与页面跳转。

## 本轮结论

- `App.currentProject(query)` 已成为唯一项目解析入口：带 `?id=` 时同时校验存在性与可见性；无 id 时按可见 `wfCurrent` → 我负责的项目 → 可见项目依次回退；任何分支都不返回不可见项目。
- 清理 43 处硬编码 `SP-26031` 与旧 `wfCurrent` 回退，覆盖 10 个模块的页面与动作层；历史遗留不可见 `wfCurrent` 不再把项目数据带进导演、视频、创意、音频、后期、质量、成本、合规、资产与任务页面。
- 创意设定由「原地覆盖版本号」改为「追加新版本、旧版本保留」：新版本继承来源、生成人与项目关系，旧版标记「已被替代」；提交前校验项目阶段，锁定项目不会产生半写入。
- 项目流水线 8 个阶段节点从静态展示改为可点击入口，点击后带当前项目 id 进入对应阶段页；阶段状态与 `Derived.workflow()` 同源，不另造进度。
- 菜单组名与页眉章节名统一：项目流水线归「项目中心」，`post` 时间线 / 分集成片 / 版本链归「后期与剪辑」。
- 全局页（任务、资产、成本、通知、合规、作品库）只列当前身份可见项目；从全局页进入业务页时才按页面类型携带项目 id，平台配置页不被强塞项目上下文。

## 页面跳转规则

1. **项目页**：`?id=` 优先；无 id 用可见当前项目；项目 id 不可见时直接显示阻断页，不回退到 `D.projects[0]`。
2. **全局页**：任务、资产、成本、通知、合规、作品库只聚合可见项目；进入具体业务页时才携带当前项目 id。
3. **平台页**：模型供应商、路由策略、组织与平台管理不携带项目上下文，按角色权限独立访问。
4. **上下文页**：`projects/new`、`projects/detail`、`orgs/member` 不进一级菜单，只能由业务动作进入。
5. **动作层**：页面按钮携带 `pid / id / ep / shot / task` 等定位参数；动作执行前再次校验项目与对象归属。
