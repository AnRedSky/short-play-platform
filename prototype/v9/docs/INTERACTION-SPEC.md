# V9.1 交互规格说明（前端实现参考）

适用范围：`prototype/v9`。本文描述**已实现**的交互规则，不是规划稿；每一节都能在对应路由上按步骤复现。
数据边界：全部业务数据为虚构示例，存于内存（`assets/js/data.js` 初始态 + `assets/js/store.js` 业务状态层），刷新即回到初始态；页面互不调用真实模型、存储或账单服务。

---

## 0. 全局交互约定

### 0.1 三层结构

| 层 | 文件 | 职责 | 允许改状态 |
| --- | --- | --- | --- |
| 数据层 | `assets/js/data.js` | 初始字典、枚举、角色与权限码 | 否 |
| 业务状态层 | `assets/js/store.js` | 状态机、门禁、校验、副作用（审计/通知/成本/资产/返工台账） | **唯一允许** |
| 派生数据层 | `assets/js/derived.js` | 数据范围与跨页指标（可见项目/成员/成本/预算、首页 KPI、项目事实汇总） | 否 |
| 组件层 | `assets/js/ui.js` | 纯函数渲染组件 | 否 |
| 应用层 | `assets/js/app.js` | 路由、权限、弹窗、异步作业、Toast、身份切换 | 仅界面态 |
| 模块层 | `modules/<域>/pages.js` | 注册路由与动作；动作只调 `DB.ops` / `App.*` | 否 |

模块动作统一写作 `App.on("域.动作", (el) => …)`，按钮通过 `data-action="域.动作"` 触发；需要的业务参数放在 `data-*` 上。

### 0.2 权限与数据范围

权限判定顺序：**身份 → 数据范围 → 路由 → 按钮 → 动作兜底**。

1. 顶栏切换身份后，侧栏菜单按 `DB.permissions` 重新派生；无权限路由整页渲染 403 文案，并给出「返回可用首页 / 切换身份查看」两个出口。
2. 数据范围由 `Derived` 统一计算：管理员/审计=企业全量（审计只读）；部门管理员=本部门项目、成员、预算与成本；项目负责人/普通员工=本人负责或被授权的项目；运维=无业务数据权限（空态）。
3. 越界访问项目详情、员工档案等对象返回 403 页面，不渲染任何对象内容；成本、预算、质量、风险、审核、交付记录随项目范围同步收窄。
4. 按钮级：无权限的动作不渲染；对象状态不满足前置条件（如「已交付」项目）的动作同样不渲染，而不是点击后才报错。
5. 动作级：每个写动作首行 `if (!App.guard("权限码")) return;`，即使绕过界面直接触发也会被拦截并提示「无权执行」。

常用权限码：`project.create` `project.manage` `creation.write` `script.review` `production.write` `post.write` `quality.operate` `task.operate` `delivery.execute` `final.review` `notify.handle` `compliance.write` `asset.manage` `cost.manage` `models.manage` `org.manage` `grant.manage` `platform.config`。审计员为只读，以上写权限全部缺失。

### 0.2.1 单人主线（V9.1 定稿口径）

产品主线是「一名项目负责人 + AI 独立跑完整部短剧」，因此：

1. 默认身份固定为项目负责人（`i-owner`），导航按生产链路排序（工作台 → 项目 → 创意/剧本 → 导演规划 → 视频 → 音频/字幕 → 后期/交付 → 质量 → 任务 → 资产 → 模型 → 成本 → 通知 → 分析 → 合规 → 组织 → 平台）。
2. 审批节点 A/B 保留，但负责人可同时作为审核人完成确认，不强制第二人；部门、企业、授权、移交等能力是可选的协作层，放在导航末尾。
3. 顶栏身份切换标注为「评审模式」，仅用于评审角色权限与数据范围，不作为产品功能；不提「切换身份」就能完成主线的暗示。

### 0.2.2 界面文案规范（全中文）

1. 页面标题、页眉、按钮、表头、说明文字、抽屉标题、Toast 与通知统一用中文；页眉固定为「业务域 / 子页」，例如「创意与剧本 / 创意设定」。
2. 不使用英文词作功能名：创意 brief 统一称「创意设定」，Attempt 称「尝试」，FAIL / PASS / REVIEW_REQUIRED 在界面上分别显示为「未通过 / 通过 / 需人工判断」。
3. 供应商与模型使用中文代号（视频供应商 A、视觉供应商、推理模型 R1、质检模型 Q1）；MP4、WAV、H.264、AAC、SRT、LUFS 等格式与单位标识按行业惯例保留。
4. 路由、动作名与数据字段仍用英文内部标识（如 `creation/brief`、`D.briefs`），只改展示层，避免破坏深链、动作注册与状态判断；原始状态枚举不改写，由 `UI.esc()` / `UI.text()` 统一映射为中文。

### 0.2.3 小说导入改编（创意环节入口）

入口：`creation/brief` 主按钮「导入小说改编」，右栏卡片「从小说导入改编」。

1. 表单字段：小说名（即项目名）、原著作者、改编忠实度、题材、受众、画面风格、集数、单集时长（秒）、项目预算、归属部门、原文文件（仅本机读取，≤2MB，可自动填书名与字数）、小说原文、改编授权确认。
2. 校验：小说名 2–20 字且不与现有项目重名；作者必填；原文不少于 300 字；必须勾选改编授权；集数 4–60；预算不得超过部门与企业可用余额（`总额 - 已用 - 预留`）。
3. 执行：建草稿项目 → 创意设定置为「已确认 / 小说改编」并记录忠实度与章节数 → 状态迁移「创意策划中 → 剧本创作中」→ 生成候选剧本 `SCR-<项目号>-V1`（待审核）→ 建「小说改编」任务（推理模型 R1）→ 记文本成本 → 状态迁移「待剧本审核」→ 写审计与待审通知。
4. 结果：跳转项目详情显示当前阶段「改编稿待审核」；剧本审核页自动选中该候选版本，通过并锁定后项目进入「生产准备中」。
5. 章节统计优先识别「第 X 章 / 回 / 节」，缺失时按空行分段；改编稿的集数、场次、镜头与对白行数按集数估算，用于原型演示。

### 0.3 表单：字段级校验

`App.modal({ title, sub, body, submitText, onSubmit, validate })` 生成 `#app-form`（`novalidate`）。提交时执行：

1. 清空上次错误；
2. 内置规则：`required`（必填）、`min/max`（数值范围）、`minlen`（字符下限）、`pattern`（正则）、`rule: date|money|code`；
3. 自定义 `validate(data) → {字段: 文案, _: 表单级文案}`；
4. 有错：字段下方显示 `.field-error`、加红框、聚焦第一个出错字段、表单底部 `.form-error` 汇总并 Toast，**不关闭弹窗、不调用业务层**；
5. 通过：调用 `onSubmit`。返回 Promise 时按钮进入「处理中…」禁用态；返回 `{ok:false}` 时保留表单、把 `fields` 回填到对应字段、`msg` 写入表单级错误并 Toast；返回 `false` 只关闭弹窗不做业务。

### 0.4 异步作业（loading 与成败反馈）

`App.job({ title, sub, steps, run, after, refresh })`：

- 全屏遮罩 + 步骤列表，按 420ms/步依次点亮；同一时刻只允许一个作业，重复触发提示「上一个操作尚未完成，请稍候」；
- `run()` 在最后一步执行，异常被捕获为 `{ok:false,msg}`；
- 完成后自动清遮罩；`refresh !== false` 时调用 `App.refresh()`，页表单类动作传 `refresh:false` 以保留用户输入；再按 `ok` 弹成功或失败 Toast，最后执行 `after(out)`；
- 遮罩挂在独立的 `#job-root` 层，不占用弹窗的 `#overlay-root`：作业结束时弹窗保持打开，失败可继续改字段重提，只有成功分支才关闭弹窗；
- 业务失败不会伪造成功：`DB.ops` 返回 `{ok:false,msg,fields}` 时，Toast 显示原因，表单场景回填字段级错误（`.field.invalid` + `.field-error`）与表单级错误（`.form-error`）。

所有写操作必须放入 `App.job`，标题用业务动作名，`steps` 用真实步骤（校验前置 → 提交/调用 → 落库/写台账 → 联动/通知）。

### 0.5 其它反馈

- `App.toast(msg, kind)`：成功默认、失败 `bad`、提醒 `warn`；失败必须说明**为什么不能做**与**下一步怎么办**。
- `App.drawer(title, html)`：详情与行内操作，抽屉内的按钮同样走 `data-action`。
- `App.confirm`：只用于高影响/不可逆操作，文案说明影响面，不替代业务校验。

## 1. 项目域（projects）

路由：`projects/list` `projects/new` `projects/detail` `projects/lifecycle`。权限：`project.create`（新建/草稿）、`project.manage`（暂停/终止）。

### 1.1 新建项目 / 保存草稿（页表单，唯一入口）

入口：`projects/new` 页面的「创建并入工作台 / 保存草稿」。页面即表单，不再弹二次收字段的弹窗。

1. 页面字段即提交数据：项目名称（必填）、题材、目标受众、计划集数（4–60）、单集时长、画幅、语言、所属部门、预算（金额格式）、交付格式、风格、内容禁忌、创意内容、输入方式。
2. 读取与校验：`App.collect(view)` 读取全部 `[name]` 控件；`App.validateFields(view, data)` 校验必填、数值范围、金额格式，错误回填到字段并汇总到页内 `.form-error`，**输入保留**。
3. 业务校验（`DB.ops.createProject`）：名称必填/2–20 字/企业内不重复；集数 4–60；部门预算与企业预算按「总额 − 已用 − 预留」校验余额，不足时回填预算字段；通过后分配 `SP-26032+` 编号。
4. 作业：`App.job({ refresh:false, run, after })`——成功才 `App.go("projects/detail",{id})`；失败不刷新页面，保留已填内容并把原因与字段错误回填。
5. 数据变更：新增项目（状态「草稿」、负责人=当前员工、成员含本人）、项目预算台账、首版 brief、审计记录、通知；草稿不占用生产资源。
6. 边界：`保存草稿` 允许名称留空（自动取「未命名项目 N」）以先存后补，但预算/集数仍走 Business 层默认值；创建成功后刷新或切换身份会重置内存数据。

### 1.2 暂停 / 恢复 / 终止

- 暂停：选项目 → 原因（≥8 字）→ `Store.pause` 校验项目处于可暂停状态 → 状态转「已暂停」、写生命周期记录、通知负责人；已有运行中任务按供应商能力收口，不重复扣费。
- 恢复：只处理「已暂停」项目；逐项恢复并汇报，重复点击不产生第二条恢复记录。
- 批量恢复/批量暂停：先按状态筛出目标集合，逐条调用并列出被跳过原因；批量暂停要求勾选「已通知相关负责人」。
- 终止：选未进入终态的项目 → 原因（≥10 字）→ 勾选下游影响确认 → 状态转「已终止」，取消未执行的下游计划与任务，保留已完成资产、任务记录与已发生费用；终态不可回到进行中。

## 2. 创意与剧本（creation）

路由：`creation/brief` `creation/plan` `creation/script` `creation/review` `creation/breakdown`。权限：`creation.write`、`script.review`（审核/锁定）。

### 2.1 提交创作 brief

1. 填写项目、输入方式、资料来源、创作意图（≥40 字）。
2. 校验：资料来源必须来自已登记来源，手填未登记来源被拦截并提示去合规页登记；创作意图含禁止词（血腥/赌博/毒品/色情）直接拒绝并回填字段。
3. 数据变更：brief 版本写入并置「已确认」；项目「草稿」→「创意策划中」；审计记录。
4. 作业：确认 brief → 生成候选方案（同一次作业内两步，结果写入 `creativePlans`）。

### 2.2 方案选择

- 方案必须勾选「已阅读并确认方向」才能选择；未勾选时按钮拦截。
- 选择后写 `chosenPlan`、项目转「剧本创作中」，其余方案保留可追溯。

### 2.3 生成 / 修改 / 审核剧本

1. 生成候选剧本：作业 → 产出 `SCR-xxxx-Vn`（待审核，未锁定）。
2. 派生 brief 新版本：基于当前 brief 递增版本，保留旧版本。
3. 局部改写：范围（单场/单集/全剧）+ 定位 + 正文（≥30 字）+ 原因；生成候选版本，状态「待审核」。
4. 提交审核：候选版本进入 `creation/review`，状态「待审核」。
5. 审核通过：需填版本号、覆盖位置、依据（≥10 字）；通过后剧本锁定，项目转「生产准备中」。
6. 审核驳回：位置 + 原因 + 建议，建立修订任务，状态回「剧本创作中」。
7. 锁定：仅「待审核」可锁定；已锁定版本禁止再改，下游以锁定版本为准。
8. 重新拆解：需在剧本锁定后执行；作业写分镜结果，已通过的镜头标「需复核」。

## 3. 导演规划（director）

路由：`director/plan` `director/cast` `director/world` `director/shots` `director/storyboard`。权限：`production.write`（规划固化、提交生产）。

### 3.1 固化分镜方案

前置门禁清单逐项展示（剧本锁定、镜头契约齐备、角色/场景资产确认、授权、预算）；全部满足才可固化。固化说明 ≥10 字，成功后项目「生产准备中」→「生产中」，并跳转 `video/production`。门禁未过：列出未满足项，不写状态。

### 3.2 资产确认与版本

- 角色/场景/道具详情抽屉内确认：参考图不足（角色 <3 张、场景 <2 张）前端拦截，提示补参考后再确认。
- 新增角色/场景/道具：名称必填，参考图 0 张可建立但状态「待确认」，不可提交生产。
- 角色升版：版本号递增、旧版本保留、受影响已通过镜头标「需复核」并生成复核提示。
- 追加参考资产：写资产引用与数量，同步刷新可提交状态。

### 3.3 镜头与提交

- 新建镜头：编号符合 `^CH-[0-9]{2} v[0-9]+`，时长 2–12 秒；不合法字段级拦截。
- 提交单个镜头：已通过 / 排队中 / 执行中 / 未选模型 四种情况均阻断并给出原因。
- 批量提交：逐个提交，汇总成功数，并列出每个被拦镜头及原因（不静默跳过）。
- 重生成：新建尝试并保留原结果；选择候选：写入采用版本，质量报告记录采用依据。
- 重新规划：重排场次与镜头，需说明范围；已通过镜头标「需复核」。
- 抽检：按 20% 抽检生成质量报告，问题写入 `qualityIssues`。

## 4. 视频生产（video）

路由：`video/production` `video/results` `video/preview`。权限：`production.write`。

任务行操作列：`详情` 固定；`执行` 仅在「排队中/待执行/失败（可重试）/待质检/待人工处理」出现；`处理` 仅在「待人工处理」出现。

### 4.1 执行单任务

1. 点击「执行」→ 作业四步：校验资源与依赖 → 提交供应商调用 → 下载并持久化结果 → 镜头级质量检测。
2. 前置校验：依赖任务未完成、资源/模型未选、镜头已通过、镜头正在执行，均在 `run()` 内返回失败原因（如「前置任务未完成：T-8842」），状态与 Attempt 不变、不扣费。
3. 成功：任务「成功」、镜头「待质检」→ 质检后写质量报告；镜头「已通过」或「需复核」。计费写入成本台账与用量台账（Attempt 失败也计费）。
4. 「待质检」任务点「执行」只跑质检，不重新生成、不重复扣生成费。

### 4.2 新建批次

1. 选集次（排除已全部通过的集）+ 并行上限（1–4）+ 批次说明（≥8 字）。
2. 逐镜头处理：已「待质检」→ 直接质检；已有排队任务 → 加入队列不重复提交；其它 → 提交 → 执行 → 质检。
3. 汇总：通过数 / 待判断数 / 已排队数 / 被拦原因 + 本次扣费金额。

### 4.3 失败处理（五分支）

「改提示词重试 / 换参考重试 / 切备用模型（先做兼容校验）/ 接受并记录（写质量报告与审计）/ 取消任务」，每支都要求填写说明；切换模型若兼容校验不通过，字段级报错并保留表单。

### 4.4 队列与取消

- 暂停队列：把「排队中」任务转「已暂停」，可恢复；恢复后回「排队中」。
- 取消任务：原因 + 说明，任务「已取消」，镜头解除占用，已发生费用保留。
- 采用候选 / 接受现状：理由 ≥8/≥10 字，写质量报告与审计。
- 预览页：不内置视频文件，以画幅占位 + 契约摘要呈现；页面明确标注为静态展示态，避免把占位当真实产出。

## 5. 音频与字幕（audio）

路由：`audio/dialogue` `audio/voice` `audio/bgm` `audio/subtitle`。权限：`production.write`。

- 试听：不播放音频，打开「对齐元信息」抽屉（音色、语速、音量、ASR 置信度、版本），并提供「重生成」入口；页面标注静态原型不内置媒体文件。
- 重生成对白：版本 +1、ASR 回听结果写入、下游口型标「需重做」、按条扣费。
- 批量生成对白：逐条校验音色已启用；停用音色被拦并列出条目，不静默跳过。
- 音色档案：新建需授权依据必填；停用/启用切换状态并影响可提交性；详情抽屉展示参数与授权期限。
- 授权：续期（`RT-xx` + 回执）、替换音色（新档案校验后批量标需重做）、授权复核（读授权台账统计阻断与临期项）。
- BGM 素材：登记（来源 + 授权必填，状态「待确认」）；确认后可用于混音；替换使用（`RT-03` 替换后重混，解除交付阻断）。
- 字幕：校对提交真实递增版本并转「待复核」；生成字幕产出 `SUB-17 v2` 并扣费；口型批量对齐需选择范围，重做需对白已生成。

## 6. 后期与交付（post）

路由：`post/timeline` `post/episodes` `post/review` `post/delivery` `post/works` `post/versions`。权限：`post.write`、`final.review`、`delivery.execute`。

### 6.1 时间线

- 新建：集次重复、该集无分镜均拦截；成功写轨道与片段数。
- 输出：三重前置（标脏片段 = 0、字幕已通过、该集质检 PASS）；任一不满足列出原因并阻断；成功后冻结该版本。

### 6.2 分集质检

抽屉展示镜头状态计数（通过/需复核/失败/未生成）；执行集级质检时，未通过镜头逐个列出并阻断，不允许“整集跳过”。通过后集状态 `qc=PASS`。

### 6.3 终审（节点 B）

1. 选审核范围（按已完成集次）；整剧齐备时连推「后期制作中 → 质量检测中 → 待最终审核」；不齐时只写审核记录并提示走分批交付。
2. 通过：仅「待最终审核」可过；必须勾选清单项并填说明；通过后项目「已完成」。
3. 不通过：选位置 + 原因 + 返工要求；位置格式 `E17 / S02 / SH-05`，不符合则字段报错；系统定位真实镜头、标「需返工」、建返工任务并通知责任人。

### 6.4 交付

- 整剧齐备（项目「已完成」）：走 `Store.generateDelivery`，生成正式交付包。
- 集数未齐：允许「分批交付」，但需终审通过记录、无授权阻断、无待核验交付包；范围自动取已完成集次（如 E01–E16），填接收方与交付说明（≥10 字），生成 `DP-26031-0x`（待核验）。
- 确认接收：粘贴校验和前缀，与记录比对，不一致字段报错并保留表单；一致则冻结交付包、项目转「已交付」、作品状态更新。
- 作废交付包：填原因，状态「已作废」，不删除记录。
- 归档：仅「已交付」可归档，归档后项目转「已归档」，不可再回退。
- 其它抽屉：作品详情、版本链（剧本→镜头→时间线→成片→交付）、引用检查（按 `refs` 显示阻断/可删）。

## 7. 质量与返工（quality）

路由：`quality/gates` `quality/reports` `quality/rework`。权限：`quality.operate`。

- 报告详情：逐条检测项 + 接受/返工/驳回三个裁决入口。
- 接受现状：理由 ≥8 字（空理由字段拦截）；写 `decision/note/by/at`，同步审计。
- 返工：建返工台账（目标、轮次、成本、旧值），通知责任岗位。
- 驳回：阻断下游使用，需重新生成后再次送检。
- 重跑：合规类返工**禁止**自动重跑；已修复项拦截；每次重跑轮次 +1 并扣费；重跑依据 ≥8 字。
- 发起返工：对象须匹配 `SH|DL|AU|SC|TL|EP` 前缀且真实存在，且关联报告存在；合规类必须人工决策。

## 8. 任务队列（tasks）

路由：`tasks/list` `tasks/queue` `tasks/attempt`。权限：`task.operate`。

任务 11 状态：待提交 / 排队中 / 执行中 / 成功 / 质量检测中 / 失败（可重试）/ 失败（不可重试）/ 待人工处理 / 已取消 / 已暂停 / 已跳过。

- 详情抽屉：内嵌执行、人工决策、取消、切换模型、查看 Attempt 记录。
- 执行：与视频域同一套前置校验；失败计入 Attempt，达上限转「待人工处理」，不自动重试。
- 批量重试：跳过合规类与不可重试项，逐条调用并汇总成功/失败；可选「重试后自动执行并质检」。
- 切换模型：先做兼容校验，不兼容字段报错。
- 暂停队列：按池筛出「排队中」→「已暂停」，恢复时回「排队中」。
- 人工决策三分支：切换模型 / 跳过此镜头（下游时间线需调整并留审计）/ 修正后重试；每支要求填写说明。
- 取消：原因必填；并发设置：视频/音频/文本三个池分别设定上限。

## 9. 通知与异常（notify）

路由：`notify/inbox` `notify/incidents`。权限：`notify.handle`。

- 处理：抽屉展示项目、触发原因、阻塞影响、建议动作、责任人、状态；出口为「去业务页处理 / 转待办 / 记录处理结论 / 升级」。
- 关闭：必须选结论类型 + 结论（≥10 字），写回 `state=已处理`、`unread=false`；只关通知不处理业务对象视为未闭环。
- 转待办：真实创建 `TD-xxxx` 待办，负责人与截止时间必填。
- 升级：写异常台账（`IN-00xx`）、通知企业管理员、审计记录。
- 异常处置：五种方式（局部暂停并重生成 / 接受并记录理由 / 替换素材后重跑 / 指派他人处理 / 升级企业管理员）；合规类禁止纯自动重跑，必须填写验证方式；涉及镜头的同时标「需返工」。

## 10. 合规与授权（compliance）

路由：`compliance/rights` `compliance/risks` `compliance/audit`。权限：`compliance.write`。

- 授权详情：主体、类型、权利人、证明、使用范围、地区、期限、商用性、限制、复核、状态；提供续期/替换/停用。
- 续期：选 `RT-xx` + 新到期日 + 回执号；格式错误字段拦截；成功后状态回「有效」，解除相关阻断。
- 替换：新素材须存在，替换后下游时间线标脏，需重混与复检。
- 停用：填原因，状态「已停用」，阻断依赖该授权的交付。
- 风险闭环：结论 ≥8 字 + 验证方式必填；未填不放行。
- 升级风险：写异常台账并通知；新增风险：等级、位置、责任人必填，生成 `RK-01xx`。

## 18. 边界场景清单（验收时逐条验证）

1. 空表单提交 → 字段级错误 + 聚焦，弹窗不关闭、无数据写入。
2. 名称重复 / 编号格式错误 / 数值越界 → 字段错误回填，保留已填内容。
3. 前置任务未完成时执行任务 → 状态与 Attempt 不变、不扣费、提示具体前置任务。
4. 项目未到「待最终审核」时终审 → 拒绝，并提示分批交付路径。
5. 无终审记录时整剧交付 → 拒绝；分批交付允许但状态为「待核验」。
6. 校验和不一致时确认接收 → 字段错误，交付包不冻结。
7. 授权阻断时交付 / 生产 → 门禁列出阻断授权编号并拒绝。
8. 预算低于已用金额时调整预算 → 拒绝并显示已用金额。
9. 空理由/过短理由的质量裁决、通知关闭、返工重跑 → 全部拦截。
10. 合规类返工自动重跑 → 拒绝，必须人工决策与验证方式。
11. 无权限身份点击写操作 → 提示无权执行，数据不变。
12. 连续触发两个异步作业 → 第二个提示「上一个操作尚未完成」，不并发写状态。
13. 刷新页面 → 回到初始示例数据（内存态），不残留上次操作。
14. 所有成功/失败均必须有反馈；失败文案包含原因与下一步，不使用「演示/模拟/跳过」式占位动作。
