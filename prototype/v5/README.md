# 长夜制作台 · V5 静态交互原型

面向企业内部影视创作与制作团队的**私有化 AI 短剧生产管理平台**原型：在一条 12 集竖屏短剧的完整制作链路上，叠加私有化部署所需的用户、组织、角色、项目授权、Provider 凭据、数据外发、用量预算与审计能力。

- 产品边界：私有化部署、单企业主体；不做 SaaS 多租户、租户计费、席位与自助开通，也不接外部业务系统、Webhook 或公开 API Key。
- 技术栈：原生 HTML + CSS + JavaScript，无框架、无第三方库、无构建步骤。
- 架构：`index.html` 单入口 + Hash 路由 + 按业务域拆分的页面模块；`DB / UI / App` 三层。
- 状态：纯内存态。所有演示数据在页面加载时深拷贝生成，刷新即恢复初始值，不使用 `localStorage` / `sessionStorage`。
- 运行要求：必须通过 HTTP 静态服务访问，不要直接双击 `index.html`（`file://` 不属于规范支持路径）。

## V5 优化依据与范围

V5 在 V4 基线（24 条路由）之上，对照 GitHub 主流短剧平台开源项目完成一轮竞品梳理与原型优化。竞品清单见：[`docs/15-competitor/COMPETITOR_ANALYSIS.md`](../../docs/15-competitor/COMPETITOR_ANALYSIS.md)。

竞品调研归纳出两类主流布局范式（阶段向导式、无限画布式）、异步任务与候选确认流的通用交互、Provider 能力解耦与状态驱动推进等共性能力。V5 据此补齐 V4 缺口，新增 4 个模块：

| 新增路由 | 模块 | 对应竞品能力 | 优化要点 |
| --- | --- | --- | --- |
| `overview/playground` 独立生成台 | 总览 | LumenX 的 Studio / Playground 双模块分离 | 脱离剧本上下文的图 / 视频 / 语音即开生成；能力 tabs 切换后参数随模型能力联动；生成历史可收入资产库并建立引用关系；专职 Agent 卡横排展示职责、运行状态与近任务量 |
| `production/canvas` 分镜画布 | 制作 | Toonflow 的资产 / 节点画布、Jellyfish 的实体关系编排 | 角色 / 场景 / 道具 / 镜头四类节点绝对定位，SVG 百分比连线表达引用与生成关系；右侧节点详情栏与关联节点回链；与分镜台网格视图互为补充 |
| `production/dubbing` 配音台 | 制作 | aid-studio 的角色音色绑定与对口型、Jellyfish / Toonflow 的 TTS 环节 | 本地音色库按角色绑定；配音行回写时间线对白轨；对口型状态随画面生成结果更新；支持试听、重合成与批量合成待办 |
| `review/preview` 成片预览 | 审核 | aid-studio 成片预览、C 端客户端竖屏播放交互 | 9:16 竖屏沉浸式播放器；版本上下切换与全部版本网格；批注回写质量门禁；收藏便于复核；明确不提供付费解锁、公开播放与外部分发 |

同时在数据层增补专职 Agent、提示词模板 / 风格快照、音色库、配音行、画布节点与连线、成片版本、独立生成历史八组演示数据。竞品中的计费、充值、VIP、分销、邀请激励、公网多租户与公开插件市场能力**不纳入**本平台，仅作业务闭环与交互参考。

在功能模块补齐之后，V5.1 对界面骨架做了一轮布局重构：业务导航按生产链路分组直出，系统治理入口收敛为可折叠的「系统管理」分组；账号信息、身份切换与配置入口统一迁入侧栏左下方的「账号与配置」面板；顶栏移除重复的身份选择器，保留面包屑、全局搜索、任务入口与通知；统一顶栏控件高度、圆角与配色，并补齐搜索触发按钮的基础样式。V5.1.1 进一步精简侧栏：取消分组小标题，业务组之间以细分割线区分，条目采用线条图标加文字的圆角块高亮，系统管理折叠头与一级条目同构。全部 28 条路由与既有业务能力保持不变。

## 启动

Windows PowerShell：

```powershell
cd prototype\v5
.\start.ps1
```

macOS / Linux：

```bash
cd prototype/v5
./start.sh
```

默认地址：<http://127.0.0.1:4173/index.html>

可选参数：

```powershell
.\start.ps1 -Port 8080        # 指定端口
.\start.ps1 -NoBrowser        # 不自动打开浏览器
```

```bash
./start.sh 8080               # 指定端口
```

启动脚本优先使用 Python 的 `http.server`，没有 Python 时回退到 `serve.js`（Node 内置 `http` 模块，零依赖）。也可以使用任意静态服务器托管本目录，例如：

```bash
python -m http.server 4173 --bind 127.0.0.1
```

## 私有化权限模型

系统采用**系统 RBAC + 项目成员授权**双层校验；组织与部门只用于人员组织和管理，不等同 tenant。

- **系统 RBAC**：身份关联系统角色，角色提供权限集合（`project:read`、`provider:manage`、`audit:read` 等）与系统范围（全组织 / 本部门）。
- **项目成员授权**：项目资源还要求当前用户同时出现在 `projectIds` 与项目 `memberIds` 中；即使拥有 `project:read`，未加入项目也看不到该项目。
- **路由级权限**决定 403，模块级权限决定侧栏与搜索展示，操作级权限决定按钮与事件；三者共用 `app.js` 的 `ROUTE_PERMS` 与 `App.hasPerm`。
- **资产边界**：资产只归属单一 `project_id`，禁止跨项目搜索、引用、共享；项目切换会清空当前项目缓存。
- **服务端预期**：读取、修改、生成、审核、导出都应在服务端校验 `project_id` 与项目访问权限；原型只演示前端可见结果。

## 界面与导航结构

- **侧栏主导航**按生产链路分组直出：总览、故事、制作、生成与审核、交付；每组内一级入口直达对应页面，候选确认与状态回跳在页面内完成。
- **系统管理**为可折叠分组，默认收起；当前路由落在系统治理页时自动展开并高亮当前项，避免治理入口挤占业务导航。
- **左下配置区**：用户行（头像 / 姓名 / 角色）与设置齿轮并列于侧栏底部。点击用户行打开「账号与配置」面板，内含演示身份切换、账号信息与按权限过滤的配置 / 治理入口；点击齿轮打开同一面板并定位到配置区。面板入口按 `ROUTE_PERMS` 过滤，无权限的治理页面不展示。
- **顶栏**保留面包屑、全局搜索（⌘K）、运行中任务入口与通知中心；身份切换已从顶栏移入左下配置面板，避免入口重复。
- 响应式：≤980px 侧栏转为抽屉，顶栏菜单钮唤起；≤640px 面包屑项目名、搜索文案与任务文案自动精简，配置面板全宽呈现。

## 建议演示路径

1. 在工作台查看今日待办，点「新建短剧」，分别体验「一句话原创」与「导入小说」两种模式。
2. 进入独立生成台，切换图像 / 视频 / 语音能力，调整参数生成一条试验记录；将一条已完成记录「收入资产库」，失败记录重试；查看四张专职 Agent 卡的职责与运行状态。
3. 进入故事圣经，打开周砚的设定卡，修改描述并保存，观察版本从 `REF v3` 升为 `REF v4`、状态变为待审核。
4. 进入小说改编，载入示例文本，依次完成 4 步向导，生成 12 集计划后自动跳到分集页。
5. 打开 EP01 剧本编辑正文，保存后用「保存新版本」创建 `v7`；在资产库与分镜台完成参考生成、锁定和送审。
6. 进入分镜画布，点击角色 / 场景 / 道具 / 镜头节点查看详情与关联节点；再到配音台为角色绑定音色，试听并对未完成配音行执行合成 / 重合成。
7. 到 AI 任务中心重试失败任务；在质检页体验「标记 FAIL → 重新质检 → 记录 PASS」；进入成片预览切换版本、查看批注并收藏；最后在时间线与导出页完成版本保存和成片导出。
8. 用系统管理员进入「我的权限」，查看 32 项权限与 28 条路由，提交一条「申请额外权限」，观察企业概览待办增加。
9. 进入「企业概览」，批准唐宁的项目访问；再进入「组织架构」查看部门树与项目成员映射。
10. 进入「用户与成员」，邀请一名编剧、打开成员详情调整系统角色 / 部门 / 项目成员角色 / 项目授权，并体验停用与恢复。
11. 进入「角色与权限」，选中导演角色，清空一个权限组并保存，观察角色卡人数与权限项同步变化。
12. 进入「安全与访问」，保存会话策略、运行数据外发自检；在「审计日志」筛选并导出 CSV。
13. 进入「Provider 与模型」查看 Mork 凭据掩码、轮换与测试、能力路由；在「用量与预算」调整组织预算并导出 CSV。
14. 切换到项目负责人林珊，确认只能看到被授权项目；切换到外部审片成员许知，确认系统治理页返回 403。

```text

├── README.md
├── assets/
│   ├── css/
│   │   ├── base.css           # 设计令牌、骨架、侧栏、顶栏、响应式
│   │   └── components.css      # 业务组件、企业治理组件、V5 新增组件与页面级样式
│   ├── img/                   # 3 张 9:16 电影感场景图（PNG）
│   └── js/
│       ├── data.js            # DB：演示数据种子 + 深拷贝（私有化企业模型 + V5 增补数据）
│       ├── ui.js              # UI：无状态 HTML 片段与图标
│       └── app.js             # App：路由、权限、身份、项目授权、弹层、审计、下载
└── modules/
    ├── overview/pages.js      # 工作台、项目总览、独立生成台
    ├── story/pages.js         # 故事圣经、小说改编
    ├── production/pages.js    # 分集、剧本、资产、分镜台、分镜画布、配音台
```

加载顺序固定为 `data.js → ui.js → app.js → modules/* → App.init()`。各业务模块只注册路由，不直接操作全局骨架。

- 企业初始规模：15 名成员（13 正常 / 1 待接受 / 1 停用）、9 个角色、9 个部门、9 个演示身份、7 组 32 项权限、20 条审计、3 条访问申请、2 个 Provider、7 个模型、6 条能力路由、4 个项目。
- 生产 Provider 默认为 Mork，凭据引用 `secret://provider/mork`；Mock 仅用于 CI / 显式演示，默认停用。
- 用量初始值：2026-11 组织预算 ¥50,000、已用 ¥28,640、预计月末 ¥40,800、80% 预警、100% 阻止新生成任务。
- 业务初始规模：6 个角色、12 项制作资产（共 18 项设定）、12 个镜头、8 条 AI 任务、EP01 的 8 场剧本、4 轨 18 段时间线、4 条历史导出。
- V5 增补演示数据：4 个专职 Agent、4 条提示词模板 / 风格快照、5 个本地音色、EP01 的 6 条配音行、8 个画布节点与 8 条连线、3 条成片版本、4 条独立生成历史。
- 质量门禁固定为 `PASS / REVIEW_REQUIRED / FAIL`，MVP 不提供 `WAIVED`；只有 `PASS` 解锁时间线与导出。
- 所有“生成 / 质检 / 导出 / Provider 测试”都是前端 `setTimeout` 模拟，不调用真实模型、凭据服务或 ffmpeg。
- 下载文件（质量门禁报告、SRT、交付清单、审计 CSV、用量 CSV、项目状态 JSON）由浏览器端 Blob 即时生成。
- 邀请、角色变更、成员停用、访问审批、安全策略、Provider 轮换、预算调整等操作都会写入内存审计；刷新页面后恢复初始值。
- 刷新页面会丢弃所有修改，可在「系统设置 → 数据与演示」或「项目设置 → 演示数据」主动重置。

## 浏览器与可访问性

- 目标浏览器：Chrome / Edge / Firefox / Safari 的近两个大版本。
- 响应式断点：`1180px`、`980px`、`640px`；窄屏下侧栏变为抽屉，表格、组织树、画布与时间线在容器内横向滚动。
- 弹层支持 `Esc` 关闭；剧本编辑器支持 `Ctrl/Cmd + S` 保存；全局搜索支持 `Ctrl/Cmd + K` 唤起与方向键选择。
- 原型以键盘可操作和清晰焦点为主要目标，未做完整 WCAG 审计。

## 静态资源版本

`index.html` 中 CSS / JS 引用统一带 `?v=5.1.1` 查询参数。修改资源后请同步提升版本号，避免浏览器缓存旧文件。
