# 企业内部 AI 短剧制作系统——完整项目业务方案

- 文档类型：产品业务方案与需求基准
- 适用范围：单一企业内部私有化部署
- 核心模式：企业统一管理、员工单人独立制作、AI 完成全流程专业生产
- 当前规划原则：按明确业务流程和功能模块建设，不引入智能体（Agent）架构，不以智能体、技能（Skill）作为系统功能组织方式
- 文档状态：后续 PRD、原型、数据模型、研发任务和验收的统一业务基准

---

## 1. 项目定位与建设目标

### 1.1 产品定位

建设一套服务于单一企业内部的 AI 短剧制作系统。企业通过系统管理员工、组织、角色权限、项目归属、预算制度、合规规则和经营数据；每位员工使用自己的账号及个人 AI 资源配置，独立完成从创意输入到短剧交付的完整制作流程。

本系统不是面向多个互不关联企业提供注册、租户入驻和订阅服务的 SaaS 平台，不建设企业之间的租户隔离、套餐订阅或平台商业运营体系。企业内部可以按实际组织结构管理部门、团队和成员，但这些组织单元不是 SaaS 租户。

### 1.2 核心业务原则

1. 系统只服务于一个企业主体，企业是组织管理和业务数据的根边界。
2. 企业内部有多个员工账号，员工通过单一账号即可独立完成整部短剧制作。
3. 不采用编剧、导演、摄影、配音、剪辑等传统岗位分工作为生产前提。
4. AI 模型和生产服务承担专业生产执行；员工负责创意输入、关键审核和异常决策。
5. 每位员工自主维护自己的模型供应商、API Key、模型选择、模型路由和生产资源。
6. 企业管理员不默认配置、查看或共享员工个人 API Key；敏感凭据加密保存，企业管理人员不可读取明文。
7. 企业可制定预算、合规和资源使用制度，但员工个人资源仍由员工本人配置和授权。
8. 任务、模型调用、生成资产、审核、交付和费用必须有真实记录；供应商成功回执不等于资产已下载、验证并持久化成功。
9. 预计成本与实际成本分开；失败、取消和重试产生的费用均需保留。
10. 项目移交不转移个人 API Key，不改变历史执行人、资源配置人和历史费用归属。
11. 生产链路优先自动衔接，正式人工审核节点为剧本审核和最终成片审核；其他人工介入仅针对异常决策。
12. 不引入智能体平台、Agent 编排、Skill 市场或智能体生命周期管理。本期按确定的业务模块、状态机、任务依赖和规则调度实现自动化。

### 1.3 建设目标

- 企业组织、员工、角色、权限和项目归属清晰可管。
- 员工个人 AI 资源可独立配置、验证、路由和追溯。
- 员工可在统一工作台完成创意、剧本、导演分镜、视觉、视频、音频、后期、审核和交付。
- AI 生产任务具备真实状态、依赖、重试、暂停、取消、异常恢复和结果回收。
- 数字资产支持版本、来源、授权、复用、引用和归档。
- 企业能够按员工、项目、集数、镜头、任务、模型能力统计真实产出、质量、效率和成本。
- 企业人员变动时，项目、资产、版本、任务和历史数据连续可追溯。

## 2. 业务边界与角色职责

### 2.1 企业管理边界

企业管理功能包括：企业基础信息、组织部门、员工账号、角色权限、项目归属与授权、项目负责人分配、预算制度、合规制度、资产归档、经营统计和审计。

企业管理不包括替员工配置其个人模型供应商、API Key 或默认生产模型，也不意味着企业管理员可以读取员工个人凭据明文。

### 2.2 员工个人生产边界

员工个人工作台包括：个人模型供应商与 API 配置、模型能力映射、个人路由策略、项目创意、剧本、分镜、人物与场景资产、视频音频生产、后期、质量检查、审核、交付和个人产出统计。

员工只需掌握业务目标和审核结果，不需要具备专业影视制作技能。

### 2.3 角色定义

| 角色 | 主要职责 | 主要权限边界 |
|---|---|---|
| 系统运维管理员 | 部署、运行、备份、监控、故障处理 | 基础设施权限；默认不读取业务内容 |
| 企业管理员 | 企业组织、员工、角色、项目、预算制度、合规和经营管理 | 企业范围；个人密钥明文不可见 |
| 企业管理人员 | 查看授权项目、生产进度、产出和经营指标 | 按授权范围查看，不默认拥有内容修改权 |
| 项目负责人 | 项目推进、项目成员授权、关键审核、异常决策 | 负责项目范围 |
| 普通员工 | 独立制作短剧、维护个人 AI 资源、审核和交付 | 本人及被授权项目 |
| 审计人员 | 查询操作、调用、成本和交付追溯记录 | 只读审计范围 |

同一员工可兼具多个业务角色，但权限通过角色和项目授权共同判定。不得以“专业制作岗位”作为必须分配的权限角色。

### 2.4 权限基本规则

- 企业数据按企业根边界组织；员工仅访问本人或明确授权的项目。
- 企业管理员可按管理职责查看企业项目及经营数据，但个人凭据明文始终不可见。
- 项目负责人可管理项目内授权成员，但不能读取其他员工的个人密钥。
- 普通员工只能使用自己配置并授权的 AI 资源；项目协作不等于共享资源凭据。
- 资产、任务、成本和审计记录继承企业、项目、创建人、执行人等必要归属字段。
- 导出、删除、移交、归档、密钥变更和权限调整必须记录审计事件。

### 3.1 核心对象

| 对象 | 说明 |

| ModelProfile | 员工配置的模型能力与参数 |
| RoutePolicy | 员工个人模型路由规则 |
| Story / ScriptVersion | 故事及剧本版本 |
| Episode / Scene / Shot | 集、场、镜头生产单元 |
| Character / Location / Prop / Costume | 人物、场景、道具、服装资产 |

| AuditEvent | 审计事件 |

### 3.2 归属关系

企业 → 部门（可选）→ 员工；企业 → 项目 → 剧本版本、生产计划、任务、资产、审核和交付。项目负责人、创建人、执行人、资源配置人和费用承担方分别记录，不得混用一个 user_id 代替所有归属关系。

个人模型配置归属于员工账号，不归属于企业项目。任务执行时记录实际执行员工、所用个人配置 ID、模型标识、供应商任务 ID 和实际费用。项目移交后，新负责人使用自己的个人资源继续执行。

## 4. 端到端业务流程

### 4.1 标准生产主流程

1. 员工登录并检查个人 AI 资源配置。
2. 创建短剧项目，填写创作目标、题材、受众、集数、单集时长、画幅、风格、预算和交付要求。
3. 选择创意输入方式，形成创意需求记录。
4. AI 生成创意方案、故事大纲、人物关系、分集规划和候选剧本。
5. 员工审核剧本；不通过则填写修改意见并由 AI 生成新版本，通过后锁定正式剧本版本。
6. AI 解析剧本，形成集、场、人物、场景、道具、对白和镜头生产计划。
7. AI 生成并校验人物、场景、服装、道具等视觉参考资产。
8. AI 根据镜头生产单元调用视频能力生成镜头素材。
9. AI 生成角色对白、旁白、配乐、音效、字幕和口型同步素材。
10. AI 执行剪辑、时间线编排、混音、字幕合成和分集输出。
11. AI 执行镜头级、单集级和整剧级质量检查；不合格内容定位后局部返工。
12. 员工审核最终成片；通过后生成正式交付包并归档。
13. 系统更新项目、员工、企业的真实产出和成本统计。

### 4.2 人工审核节点

**剧本审核**：检查题材方向、故事逻辑、人物关系、分集节奏、对白、内容合规和版权风险。动作包括通过、退回修改、终止项目。通过后生成不可混淆的正式剧本版本。

**最终成片审核**：检查剧情完整性、人物连续性、画面、声音、字幕、剪辑、合规和交付清单。动作包括通过交付、指定镜头/片段返工、退回后期、终止交付。审核意见必须关联具体版本和问题位置。

异常处理不扩展为常规多岗位审批。只有任务连续失败、预算策略触发、资源不可用、合规高风险、资产损坏等情况才进入待人工处理。

## 5. 创意与项目立项功能

### 5.1 创意输入方式

| 方式 | 用户输入 | 系统处理 | 输出 |
|---|---|---|---|
| 自由描述 | 自然语言描述灵感、人物、冲突或场景 | 提取题材、主题、冲突、受众和约束 | 结构化创意 brief |
| 题材/类型选择 | 题材、类型、风格标签 | 根据选择生成创作约束，不套用固定剧情 | 创意方向候选 |
| 故事梗概扩写 | 已有故事梗概或短篇内容 | 识别主线、人物、冲突、转折和结局 | 完整故事大纲 |
| 角色/关系驱动 | 人物设定、人物关系和核心矛盾 | 生成角色目标、关系变化和冲突线 | 人物关系与故事方案 |
| 场景/事件驱动 | 一个场景、事件或反转设想 | 扩展前因、冲突升级和后续影响 | 故事切入点与剧情线 |
| 参考资料辅助 | 用户有权使用的文本、图片或资料 | 提取参考特征并保留来源，不默认复制受保护表达 | 参考分析与创意建议 |
| 自定义结构化输入 | 用户自行填写题材、受众、时长、风格、禁忌等 | 校验必填项和互斥约束 | 可编辑创意 brief |

不得将上述方式实现成智能体入口或 Skill 调用；它们是创意模块内的不同业务输入路径。

### 5.2 项目创建流程

前置：员工已登录；项目创建权限有效；如需调用 AI，至少有一项匹配的个人模型配置可用。

流程：
1. 进入“新建项目”，选择空白创建或从既有项目复制非敏感配置。
2. 填写项目名称、题材、目标受众、集数、单集时长、画幅、风格、语言、预计预算、交付格式和说明。
3. 选择创意输入方式并填写内容。
4. 系统校验必填项、范围、预算格式和个人资源可用性；项目创建本身不要求模型调用成功。
5. 保存项目，生成唯一编号，归属当前企业，记录创建人和负责人。
6. 进入项目工作台，显示创意 brief、生产阶段、待办和资源检查结果。

输出：项目档案、创意 brief 初始版本、项目成员关系、操作审计记录。

状态：草稿 → 创意策划中 → 剧本创作中 → 待剧本审核 → 生产准备中 → 生产中 → 后期制作中 → 质量检测中 → 待最终审核 → 已完成/已交付；另有暂停、异常、终止和归档等独立状态。状态迁移必须由真实业务动作触发，不允许页面手工随意改状态。

异常：必填缺失时定位字段；无 AI 配置时允许保存草稿但阻止启动生成，并引导配置资源；预算规则不满足时说明原因；重复提交使用幂等键避免重复项目。

### 5.3 创意方案生成流程

1. 员工选择创意输入方式并提交 brief。
2. 系统将 brief 版本化，记录操作者和输入资料来源。
3. 检查文本模型能力、上下文长度、结构化输出和个人配置状态。
4. 生成题材定位、核心卖点、故事主题、世界观、人物关系、主线冲突、分集方向和风险提示。
5. 展示多方案比较，员工选择、编辑或要求调整。
6. 保存选定方案为项目创意版本。
7. 生成故事大纲和分集结构，交给剧本生成流程。

失败处理：调用失败保留原输入和失败记录；重试需生成新的调用记录；切换模型前验证能力和输出结构兼容。禁止把模型请求发出或供应商返回成功直接标记为创意资产成功，必须校验结果并保存。

## 6. 剧本创作与审核功能

### 6.1 剧本生成

输入：已确认创意方案、项目规格、集数、单集时长、人物设定、内容边界和格式要求。

处理：
1. 故事结构拆分为主线、支线、人物弧光和关键转折。
2. 生成分集大纲、每集目标、冲突、情绪变化和集尾钩子。
3. 生成场次、场景、人物、动作、对白和必要旁白。
4. 检查人物动机、时间线、设定冲突、重复对白和剧情连续性。
5. 生成结构化剧本及可阅读文本。
6. 保存候选版本、生成参数、模型调用和关联输入。

输出：剧本版本、分集大纲、场次列表、人物与场景提取结果、剧本质量检查报告。

### 6.2 剧本编辑与版本管理

- 支持按集、场、对白段落编辑。
- 每次保存形成可追溯版本或明确的修订快照。
- 展示版本差异、修改人、修改时间和修改原因。
- 版本可标记草稿、待审核、已通过、退回、已废弃。
- 已通过版本作为生产基准，不允许静默覆盖。
- 新版本通过后执行影响分析，识别受影响集、场、镜头、对白、音频和时间线。
- 只重新生产受影响内容，保留未受影响的已验证资产。

### 6.3 剧本审核流程

1. 候选剧本生成完成，项目进入待剧本审核。
2. 员工逐集预览剧本，查看人物、场景和合规提示。
3. 可提交总体意见或定位具体段落添加批注。
4. 通过：记录审核人、版本、时间、结论，锁定正式版本并进入导演规划。
5. 退回：必须填写修改意见，创建修订任务，项目回到剧本创作中。
6. 终止：记录原因和确认人，取消尚未执行的下游计划。
7. 审核历史不可覆盖；重新审核产生新记录。

## 7. AI 导演规划与视觉资产功能

### 7.1 剧本结构化拆解

流程：读取已通过剧本 → 解析集/场/人物/场景/道具/服装/对白/动作 → 建立实体引用 → 检查遗漏和冲突 → 生成镜头规划草案 → 保存导演规划版本。

输出：集场结构、场景清单、人物出场表、道具服装清单、镜头清单、镜头间连续性约束。

### 7.2 镜头与分镜规划

每个镜头至少包含：项目/剧本版本/集/场/镜头编号、场景、出场人物、景别、机位、运动、画面构图、动作、情绪、对白、声音需求、时长、前后镜头关系、参考资产、生成提示、模型能力要求和质量标准。

流程：
1. 根据场景和剧情节奏拆分镜头。
2. 规划景别、机位、运动、人物调度和时长。
3. 生成分镜图或视觉描述。
4. 检查镜头连续性、人物出入场、轴线和场景一致性。
5. 员工可在不改变正式剧本的前提下微调导演规划。
6. 固化镜头生产计划，进入视觉资产准备和视频生产。

### 7.3 人物资产

流程：提取人物设定 → 生成外貌描述与视觉特征 → 生成多角度参考图 → 检查身份一致性 → 员工选择正式参考 → 建立人物资产档案。

档案包括人物标识、姓名、年龄特征、外貌、体态、发型、服装方案、表情参考、视觉禁改特征、参考图版本、来源、模型参数和授权状态。人物资产可跨集复用，但不能因复用而重复统计生成量和成本。

### 7.4 场景、服装和道具资产

场景流程：提取场景 → 生成环境与空间描述 → 生成全景/角度参考 → 校验场景布局与光线连续性 → 固化场景版本。

服装流程：按人物、剧情时间和场次建立服装状态 → 生成参考图 → 检查跨场连续性 → 绑定人物和镜头。

道具流程：识别剧情关键道具 → 建立外观、尺寸、状态及持有关系 → 生成参考图 → 绑定场次和镜头。

## 8. 视频镜头生产功能

### 8.1 镜头生产计划

系统根据镜头清单拆分生产任务，记录前置资产、输入素材、模型能力、预计时长、预计成本、优先级、依赖关系和质量标准。可并行的镜头并行生产，存在人物/场景参考依赖的镜头等待资产就绪。

### 8.2 镜头生成流程

1. 检查正式剧本版本和镜头生产单元状态。
2. 检查人物、场景、道具等引用资产是否可用。
3. 依据员工个人模型路由，选择支持对应输入模式、时长、分辨率、参考图和商业许可的模型。
4. 估算成本并按项目预算规则检查。
5. 提交供应商任务，记录本地任务 ID、供应商任务 ID、模型配置 ID和请求摘要。
6. 轮询或接收回调更新供应商执行状态。
7. 下载生成结果，校验文件类型、大小、时长、分辨率、完整性和可播放性。
8. 保存到资产存储，生成资产版本和校验摘要。
9. 执行画面、人物一致性、动作、时长和合规检测。
10. 合格镜头进入可用素材；不合格进入局部修复或重新生成。

供应商任务成功、文件下载成功、资产持久化成功、质量检测通过是四个不同状态，不得合并成一个“成功”。

### 8.3 镜头返工

返工需指定问题镜头和问题类型，保留旧版本及其费用。重新生成创建新任务和新资产版本，成功后更新当前采用版本，不删除历史结果。不得因单个镜头问题无条件重做整集或整剧。

## 9. 音频、字幕和口型功能

### 9.1 角色声音配置

为项目人物选择员工个人可用的语音模型和声音方案，记录声音配置、语言、音色描述、语速、情绪、授权来源。真人声音克隆必须具备可核验授权；无授权不得生成或交付。

### 9.2 对白与旁白生成

读取正式剧本对白 → 识别角色和情绪 → 生成语音 → 校验音频文件 → 语音识别回听/文本比对 → 调整发音和停顿 → 保存音频资产及时间信息。

### 9.3 音乐与音效

根据场景情绪和动作生成或选择背景音乐、环境音和动作音效。记录来源、授权、使用区间、音量和混音参数。不得默认将第三方音乐视为可商用。

### 9.4 字幕与口型

由正式对白生成字幕文本和时间轴，执行 ASR 校对、错字检测、时间轴检查和角色匹配。口型同步任务需校验视频输入、语音输入和模型能力兼容性。失败时只重做受影响的对白或镜头。

## 10. 后期制作与成片合成功能

### 10.1 时间线编排

时间线按集管理视频轨、音频轨、对白轨、音乐轨、音效轨、字幕轨和特效轨。每个片段关联源资产、入点/出点、时长、顺序、转场和版本。

### 10.2 自动剪辑

流程：读取镜头顺序与时长目标 → 选择合格镜头 → 按剧情节奏编排 → 对齐对白和音频 → 生成转场 → 检查黑帧、静音、音画不同步和重复片段 → 生成预览版本。

### 10.3 合成输出

按项目规格执行画幅、分辨率、帧率、编码、码率、音频采样率和字幕烧录策略。合成任务需记录输入资产版本、处理参数、执行日志、输出文件和校验结果。

输出未通过播放完整性检查前，不得标记为正式成片。

## 11. 质量检测与局部返工

### 11.1 检测层级

- 资产级：文件完整性、格式、分辨率、时长、可播放性。
- 镜头级：画面异常、人物一致性、动作、构图、时长、音画质量。
- 单集级：剧情完整、镜头顺序、字幕、对白、音乐、混音和节奏。
- 整剧级：人物弧光、故事连续性、风格统一、集数完整、合规和交付完整性。

### 11.2 质量流程

1. 生产任务输出资产后触发对应检测。
2. 生成结构化检测项、问题位置、严重等级和建议。
3. 可自动修复的问题进入修复任务。
4. 需要重新生成的问题关联原任务和原资产，建立新任务。
5. 质量通过后才允许进入下游。
6. 质量不通过但达到自动重试上限时进入待人工处理。
7. 质量报告与被检测资产版本绑定。

质量分数只用于辅助，不替代合规、版权和最终人工审核。

## 12. 生产任务与调度功能

### 12.1 任务模型

任务字段包括任务 ID、项目、集/场/镜头、任务类型、阶段、输入资产、输出资产、依赖任务、执行人、资源配置人、模型配置、供应商任务 ID、状态、优先级、重试次数、预计成本、实际成本、开始/结束时间、错误码、错误摘要和日志引用。

### 12.2 状态定义

待执行、排队中、执行中、成功、失败、取消中、已取消、暂停中、已暂停、重试中、待人工处理。状态迁移由任务服务和供应商回执驱动；保留每次迁移记录。

### 12.3 调度流程

创建计划 → 构建依赖图 → 检查前置资产 → 选择个人模型路由 → 预算预检 → 排队 → 提交供应商 → 监控执行 → 回收结果 → 文件验证 → 质量检测 → 标记成功并释放后继任务。

### 12.4 重试与备用模型

重试前识别失败类型，区分可重试、不可重试、供应商拒绝、超时、下载失败、文件损坏和质量不合格。达到次数上限后暂停并通知员工。

切换备用模型前检查能力、输入输出模式、参考素材、时长/分辨率、商业许可、质量要求和费用。不得仅因供应商名称不同就视为兼容。每次切换创建独立调用记录。

### 12.5 暂停、取消与恢复

项目暂停时阻止新任务派发，并按供应商能力取消或等待运行中任务；取消结果以供应商确认和本地状态为准。恢复时重新计算可执行任务，不重复提交已成功任务。取消、暂停和超时产生的费用仍需入账。

## 13. 个人模型与供应商配置功能

### 13.1 个人配置边界

员工分别维护自己的供应商账号、API Key、模型、端点、参数、能力映射和路由规则。企业可以定义允许的供应商/模型范围、合规要求、费用上限和安全策略，但不得默认代替员工配置个人 API 凭据或将其共享给其他员工。

### 13.2 供应商配置流程

1. 员工进入个人模型设置，选择内置供应商适配器或自定义兼容接口。
2. 填写供应商名称、API Endpoint、认证方式、API Key/Token、区域和备注。
3. 凭据在客户端传输和服务端存储过程中保护；服务端使用密钥管理机制加密，界面仅显示脱敏信息。
4. 选择模型并声明能力类型、输入输出模式、限制和参数。
5. 发起连通性测试，验证鉴权、模型可用性和能力响应。
6. 保存配置，记录创建人、更新时间、测试结果和配置版本。
7. 员工可禁用、更新、删除或设为默认配置；被任务引用的配置保留历史快照。

### 13.3 模型能力分类

文本生成、推理、图像生成、图像编辑、视频生成、视频编辑、语音合成、语音识别、音乐生成、音效生成、口型同步、数字人、视觉理解、内容审核、视频处理和媒体转码。

### 13.4 个人路由策略

员工可按任务能力指定主模型、备用模型和参数。路由依据包括能力匹配、质量要求、成本、可用性、时延、个人偏好和项目要求。每次调用保存最终选择理由及配置版本。

### 13.5 安全和异常

API Key 不进入前端日志、普通审计详情、导出文件或项目资产。更新凭据后新任务使用新版本，历史任务保留引用标识但不回显密钥。配置失效时暂停相关任务并通知配置人；不允许静默使用其他员工密钥。

## 14. 项目、成员与移交管理

### 14.1 项目归属

项目归属于企业；创建者、负责人、执行人、项目成员分别记录。项目资产、任务和交付记录归属企业项目空间。员工个人模型配置不属于项目资产。

### 14.2 成员授权

项目负责人或有权限的企业管理员可邀请员工进入项目，指定查看、编辑、审核或管理权限。撤销授权后，员工不能再通过旧链接访问项目；历史操作记录仍保留。

### 14.3 项目移交流程

1. 管理员选择待移交项目和接手员工。
2. 检查接手员工账号状态、项目访问权限和资源配置状态。
3. 生成移交预览，列出进行中任务、待审核事项、资产、交付和风险。
4. 确认移交，更新项目负责人和成员授权。
5. 未完成任务按策略暂停或由接手人确认后恢复；不得使用原负责人的个人 API 配置继续新调用。
6. 接手员工选择自己的个人模型配置并重新进行预算预检。
7. 保留原创建人、历史负责人、执行人、调用配置引用和费用归属。
8. 写入移交审计记录。

## 15. 数字资产中心

### 15.1 分类

创意 brief、故事大纲、剧本、人物、场景、服装、道具、分镜、镜头视频、对白音频、音乐、音效、字幕、时间线、分集成片、最终成片、封面、交付包和质量报告。

### 15.2 资产详情

资产应包含类型、名称、企业/项目归属、创建人、执行人、来源、模型调用、生成参数摘要、版本、存储位置、文件摘要、格式、时长/尺寸、质量状态、授权信息、引用关系和创建时间。

### 15.3 版本和复用

- 新版本不覆盖旧版本。
- 展示版本差异和使用位置。
- 资产被镜头、时间线或交付引用时，删除前检查引用。
- 复用资产创建引用关系，不重复记生成量和成本。
- 项目移交不改变资产历史归属和来源。
- 正式交付资产锁定历史版本，后续修改创建新版本。

## 16. 用量、成本与预算中心

### 16.1 计量维度

Token、图片张数、视频生成秒数、音频时长、音乐曲目数、转码分钟、存储量和其他供应商计费单位。保留供应商原始计量和平台统一计量。

### 16.2 费用归属维度

必须分别记录资源配置人、实际执行人、项目归属、费用承担方、供应商账户归属和费用来源。费用来源区分员工个人账户实际扣费、企业承担、企业报销、赠送额度、免费额度及其他来源。不能假定所有员工个人 API 费用由企业承担。

### 16.3 成本流程

任务提交前计算预计成本 → 预算规则预检 → 调用完成后读取供应商用量/账单 → 计算实际成本 → 记录失败/重试费用 → 与项目、员工、配置人和承担方关联 → 汇总报表。

预计成本与实际成本分栏展示；未取得可靠账单时标记待核实，不得伪造实际金额。费用调整必须保留原值、调整人、原因和凭据。

### 16.4 预算规则

企业可制定员工或项目的预算制度和提醒阈值；员工可查看自己资源的可用额度。预算触发后按规则提醒、阻止新任务或要求授权；已发生费用不能因超预算而删除或归零。

## 17. 企业经营分析

### 17.1 统计维度

企业、部门、员工、项目、短剧、集、镜头、任务、模型能力、供应商、费用承担方和时间范围。

### 17.2 指标口径

- 项目创建数：成功创建的项目数。
- 有效生产项目数：至少有一项真实生产任务启动的项目数。
- 完成作品数：最终审核通过并完成交付的短剧数。
- 完成集数：最终审核通过并交付的集数。
- 生成量：真实供应商调用和实际生成资产数量。
- 任务成功率：成功任务数/终态任务数，明确是否排除取消。
- 返工率：产生返工任务的镜头或集数占比。
- 制作周期：正式生产启动至正式交付的时长。
- 实际成本：已确认供应商扣费或可核验计费金额。
- 员工贡献：按创建、执行、审核、交付等角色分别统计，不以最后负责人覆盖历史贡献。

### 17.3 统计规则

资产复用不重复计生成量；失败调用费用不丢失；同一交付版本不重复计数；项目移交不重写历史贡献；测试任务与正式生产分开统计；统计结果可下钻到任务和账单来源。

## 18. 内容合规与审计

### 18.1 合规范围

创意、剧本、人物形象、场景、道具、视频、配音、声音克隆、音乐、音效、字体、字幕、后期和最终交付均需纳入检查。

### 18.2 授权记录

记录素材来源、权利主体、授权证明、用途范围、地域、期限、商用范围、限制条件和复核状态。模型商用条款按供应商及模型版本留档。

### 18.3 审计事件

登录与身份变化、角色权限调整、项目创建/移交/归档、个人密钥配置变更（只记录元数据，不记录密钥）、模型路由变化、任务提交/重试/取消、费用修正、资产下载/删除、审核结论、交付和数据导出。

审计日志应具备时间、操作者、对象、动作、结果、来源和关联 ID，重要记录不可由普通用户修改或删除。

## 19. 通知与异常中心

通知类型：待剧本审核、生产完成、任务失败、资源失效、预算提醒、待最终审核、质量不通过、交付完成、授权到期和项目移交。

异常处理流程：识别异常 → 判断自动恢复规则 → 可自动处理则执行有限次数恢复 → 更新任务和费用记录 → 无法恢复则暂停受影响链路 → 通知项目负责人/资源配置人 → 员工作出决策 → 恢复或终止 → 记录处理闭环。

通知必须指向具体项目、任务或资产，并展示原因、影响范围和可执行动作。

## 20. 系统设置与基础设施

包括企业基础设置、账号安全、文件存储、任务队列、供应商适配器注册、模型能力字典、日志、监控、备份、恢复和数据保留策略。系统运维配置与员工个人 AI 凭据隔离。供应商适配器只提供统一调用接口，不把供应商凭据变成企业公共资源。

## 23. 阶段实施规划

### R1：企业身份、组织与项目基础

企业内部账号、组织、RBAC、项目、项目成员授权、个人供应商配置基础、加密凭据、创意输入、剧本生成、剧本版本、人工剧本审核。任务、资产、调用、费用和审计基础数据从 R1 建立。

### R2：导演规划与视觉资产

剧本拆解、集场、镜头生产单元、人物/场景/服装/道具资产、分镜、版本和一致性检查。

### R3：视频与音频生产

个人模型路由、视频任务、配音、音乐、音效、字幕、口型、任务依赖、真实回执、文件回收和质量检测。

### R4：后期、终审与交付

时间线、自动剪辑、混音、字幕合成、分集输出、质量报告、人工最终审核、交付包和资产归档。

### R5：自动化、成本与经营分析完善

任务自动调度、失败恢复、备用模型兼容检查、预算规则、实际成本核算、企业统计、员工贡献分析和全链路审计完善。

基础领域模型、状态、版本、成本归属和审计不可推迟到 R5 才设计。

## 24. 全局验收标准

- 企业内部员工可以独立登录并按权限访问系统。
- 员工可独立配置并测试自己的供应商和模型；管理员无法读取个人 API Key 明文。
- 项目创建、创意输入、剧本生成、剧本审核、导演规划、视觉资产、视频音频生产、后期、质量、终审和交付形成闭环。
- 每个生产任务具有真实状态和可追溯调用记录。
- 供应商成功、结果下载、文件校验、资产保存和质量通过分别验收。
- 失败、取消和重试费用均有记录；预计与实际成本分开。
- 单镜头可局部返工，已合格资产可复用。
- 项目移交后历史执行人、配置人、成本和资产来源不变；接手人使用自己的 AI 资源。
- 企业统计能够区分生成过程数据、项目完成数据和正式交付数据。
- 资产版本、授权、引用、审核、交付和审计记录可追溯。
- 不以静态占位、虚构任务状态、模拟供应商回执或伪造成本冒充真实业务能力。

## 25. 产品最终定义

本项目是一套企业内部 AI 短剧制作系统：企业管理员工、组织、权限、项目归属、预算制度、合规和经营数据；员工自主配置个人 AI 模型与生产资源，并通过统一业务流程独立完成短剧制作；AI 执行创意辅助、剧本、导演规划、视觉、视频、音频、后期和质量检查；人工只在剧本审核、最终成片审核及异常决策等关键节点介入。

系统按明确业务域、业务对象、任务状态机和流程规则实现自动化，不引入智能体架构作为本期前提。
