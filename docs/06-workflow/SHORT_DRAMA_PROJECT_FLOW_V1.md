# 短剧项目制作流程基线 V1（P0–P7）

> 版本：V1  
> 日期：2026-11-27  
> 状态：待评审  
> 基线：AI 生成短剧 / 24 集 / 每集 90 秒 / 4 批 × 6 集 / 分批交付

本文是项目层制作流程的设计基线，不是页面实现说明。目标是把“季项目—批次—单集—镜头”四层关系定清楚，再进入单集流程与页面改造。

---

## 0. 整体任务规范

### 0.1 任务目标

为 AI 短剧项目建立一套可执行、可验收、可复用的项目级制作流程，明确：

- 项目从立项到交付要经过哪些阶段；
- 每个阶段由谁负责、输入什么、输出什么；
- 什么条件才算通过，什么情况退回哪里；
- 批次如何滚动，模型如何切换，返工如何控制；
- 这套流程如何映射到现有 9 段工作区。

### 0.2 范围

本版覆盖：

- 项目层 P0–P7 八个阶段；
- 批次 B1–Bn 的滚动规则；
- 模型变更与重新生成的三级规则；
- 项目状态与单集状态接口；
- 与现有 9 段页面的映射关系；
- 项目级角色、指标和验收标准。

本版不覆盖：

- 单集 E0–E7 的逐动作细化；
- 页面组件、接口字段和数据库表的最终实现；
- 真实模型供应商的能力与报价对比；
- 具体平台合同、分账和投流策略；
- 试跑数据与成本核算结果。

### 0.3 交付物

1. P0–P7 项目流程总图；
2. 8 张阶段设计卡；
3. 批次模型与批次门禁；
4. 模型变更规则；
5. 项目/单集状态机接口；
6. 现有 9 段页面映射；
7. 项目级角色与指标。

### 0.4 验收标准

- 每个阶段只有一个主交付物；
- 每个门禁都有可检查的证据；
- 每个不通过场景都有明确退回阶段；
- 项目层只卡“首批/批次”，不要求全季完成才推进；
- 单集是主要交互单位，批次不替代单集制作；
- 模型变更能定位到镜头、单集或批次，并有审批与重检范围；
- 已交付内容不因换模型被静默覆盖。

### 0.5 默认假设

- 制作形态：AI 生成；后续可扩展实拍或混合，不改变项目层框架；
- 集数与时长：24 集 × 90 秒；
- 批次：4 批 × 6 集；
- 首批内先做 3 集试跑，验证后再补齐 6 集；
- 单集是交互与执行单位；
- 批次是变更控制与交付单位；
- 季是商业交付单位；
- 模型可以在制作过程中更换，但必须留下版本与审批记录；
- 已交付剧集不自动重制，重制另开“重制批次”。

### 0.6 后续输出格式

后续每次推进任务，固定输出三块：

1. **整体任务规范**：目标、范围、交付物、验收标准；
2. **当前完成情况**：已完成、未完成、已知限制；
3. **后续推进计划**：下一步动作、输入、输出、决策点。

## 1. 设计理念与框架

### 1.1 五个设计原则

1. **以终为始**：从平台交付规格、上线节奏、预算和合规红线倒推流程。
2. **双层分离**：项目层管治理与调度，单集层管生产闭环。
3. **批次滚动**：首批锁死即开工，后续批次并行开发，不等待全季完成。
4. **交付物驱动**：每个阶段只有一个主交付物，门禁围绕交付物设置。
5. **版本与回流**：所有产物有版本、锁定人、变更记录；不通过必须退回明确阶段。

### 1.2 五层结构

| 层级 | 名称 | 核心问题 | 主要产物 |
|---|---|---|---|
| L1 | 商业与内容定位 | 为谁做、做多大、如何交付 | 项目章程、预算、合规清单 |
| L2 | 季项目治理 | 做几集、分几批、谁负责 | 创意圣经、全季大纲、批次计划 |
| L3 | 批次控制 | 这一批锁什么、何时开工、何时交付 | 批次计划、资产基线、模型基线 |
| L4 | 单集生产 | 这一集如何从剧本到母版 | 单集素材包、单集母版、QC 报告 |
| L5 | 镜头/素材任务 | 每个镜头如何生成、验收、返工 | 镜头契约、take、生成记录 |

### 1.3 四个单位

- **季**：商业交付单位；
- **批次**：变更控制与交付单位；
- **单集**：生产管理与交互单位；
- **镜头**：执行任务单位。

批次不是“批量生成 6 集”，而是 6 个独立单集任务共享同一套资产、模型基线、排期和验收规则。

### 1.4 项目流程总图

```text
P0 立项与项目定义
  ↓
P1 创意开发（创意圣经）
  ↓
P2 全季大纲 + 首批 6 集剧本锁定
  ↓
P3 首批镜头 / 资产 / 模型基线锁定
  ↓
P4 批次生产（B1…Bn，单集独立闭环）
  ↓
P5 单集后期包装
  ↓
P6 单集 QC + 批次抽检
  ↓
P7 单集入库 + 季包交付 + 复盘

并行：B2 剧本、B3 大纲、B2 预演可在 B1 生产期间推进
返工：P6 → P5 / P4 / P3 / P2
```

## 2. 项目流程 P0–P7

### 2.1 阶段总表

| 阶段 | 项目级目标 | 主交付物 | 项目级门禁 |
|---|---|---|---|
| P0 立项与项目定义 | 把商业意向变成可执行项目 | 项目章程、预算、合规清单 | 平台/受众/集数/时长/预算/上线日/负责人获批 |
| P1 创意开发 | 统一故事、人物、视觉、声音方向 | 创意圣经 v1 | 唯一方向、24 集钩子地图、风格与版权通过 |
| P2 剧本开发 | 全季大纲 + 首批剧本锁定 | 全季分集大纲、首批 6 集剧本锁版 | 大纲完整、首批剧本通过、连续性与合规通过 |
| P3 预演与资产 | 首批具备生产条件 | 镜头契约、资产包、模型基线、排期 | 每镜配置完整、关键资产锁定、试跑通过 |
| P4 分批生产 | 按批次生产单集素材 | 镜头素材、单集素材包、返工单 | 单集素材齐、镜头验收通过、批次开工门禁通过 |
| P5 后期包装 | 把素材变成单集母版 | 剪辑时间线、声音字幕、单集母版 | 画面锁定、声音字幕锁定、平台规格通过 |
| P6 质检合规 | 把问题拦在交付前 | 单集 QC 报告、批次抽检报告 | 单集全维通过、批次抽检通过、整改闭环 |
| P7 交付与复盘 | 单集入库、季包交付、沉淀经验 | 单集交付包、季包、复盘报告 | 全季完整、元数据与权利齐全、平台验收通过 |

### 2.2 P0 立项与项目定义

- **阶段目标**：把商业意向变成可执行、可核算、可合规的季项目。
- **输入与前置**：平台/渠道、受众、题材、集数、单集时长、预算、上线窗口、团队、合规红线、版权来源。
- **主交付物**：项目章程 v1、合规清单 v1、初步预算与里程碑、批次策略。
- **关键动作**：确定定位与受众；确定集数与时长；确定预算与上线日；确定 4 批 × 6 集策略；确认版权链与合规红线；确定负责人和 RACI。
- **硬门禁**：平台与受众明确；集数/时长/预算/上线日明确；合规红线清单完成；项目负责人明确；批次计划获批；版权链可追溯。
- **不通过退回**：退回商业定位、预算或合规评估。
- **责任角色**：制片人 A/R；内容总监 C；财务/法务 C；平台运营 C。
- **指标**：立项周期、预算偏差基线、合规阻断问题数。

### 2.3 P1 创意开发

- **阶段目标**：形成剧集级创意圣经，统一故事、人物、世界、视觉、声音和钩子。
- **输入与前置**：项目章程、市场/竞品参考、平台内容规范、合规清单。
- **主交付物**：创意圣经 v1，包含一句话卖点、人物小传、人物关系、世界观、24 集钩子地图、视觉风格、声音风格、参考图、版权与合规说明。
- **关键动作**：提出 2–3 个方向提案；选定唯一方向；完成人物与关系；完成 24 集钩子地图；确定视觉与声音风格；做角色/场景可资产化判断；完成版权与合规初筛。
- **硬门禁**：唯一创意方向；主角目标与阻力清楚；24 集钩子地图完整；视觉/声音风格可执行；角色和场景可资产化；版权与合规无阻断。
- **不通过退回**：退回 P1 方向提案或创意圣经。
- **责任角色**：创意总监 A/R；总编剧、导演、美术 C；制片人 C。
- **指标**：创意圣经评审周期、方向返工次数、设定冲突数。

### 2.4 P2 剧本开发

- **阶段目标**：锁定全季分集大纲，并锁定首批 6 集剧本，让首批具备预演条件。
- **输入与前置**：创意圣经 v1、项目章程、单集时长与平台规范、合规要求。
- **主交付物**：全季分集大纲 v1、首批 6 集剧本锁版、连续性表、剧本审核记录。
- **关键动作**：拆 24 集大纲；设计人物弧与每集钩子；写首批 6 集剧本；桌读；连续性检查；合规检查；编导审签；锁定版本。
- **硬门禁**：24 集大纲齐全；首批 6 集剧本齐全；单集时长符合；前 3 秒有钩子、30 秒有冲突、结尾有悬念；跨集连续性通过；合规通过；编导签字。
- **不通过退回**：退回 P2 大纲或单集剧本。
- **责任角色**：总编剧 A/R；创意总监 A；合规 C；导演 C。
- **指标**：剧本一次通过率、单集剧本周期、重写次数。

### 2.5 P3 预演与资产

- **阶段目标**：让首批 6 集具备生产条件，锁定镜头、资产、模型和排期。
- **输入与前置**：首批 6 集剧本锁版、创意圣经、平台技术规格、可用模型清单。
- **主交付物**：每集镜头契约、资产包（角色/场景/道具/音色/风格参考）、模型与生成配置、生产排期。
- **关键动作**：剧本拆解；分镜；写镜头契约；制作角色/场景/道具资产；确定音色；选择模型与参数；做 3–5 个试跑镜头；确认产能与排期；完成资产合规。
- **硬门禁**：每个镜头都有模型配置；角色/场景参考齐全；时长、对白、画幅明确；关键资产版本锁定；试跑镜头通过；排期与产能确认；授权链完整。
- **不通过退回**：退回 P3 镜头/资产；若属故事问题退回 P2 剧本。
- **责任角色**：导演 A/R；美术/资产、生成操作、配音 R；制片人 C。
- **指标**：镜头契约完整率、试跑通过率、资产锁定周期。

### 2.6 P4 分批生产

- **阶段目标**：按批次生产单集素材，每集独立跑完整的素材生产闭环。
- **输入与前置**：P3 锁定的镜头契约、资产包、模型基线、批次计划、产能。
- **主交付物**：镜头素材 vN、单集素材包、生成/拍摄记录、返工单、批次状态。
- **关键动作**：按集建任务；按镜头生成或拍摄；审片；接受/重试/换模型；做角色与场景一致性检查；完成单集素材验收；汇总批次状态。
- **硬门禁**：单集所有镜头已接受或有书面豁免；角色/风格/场景一致；技术规格符合；无未关闭的高风险问题；单集素材包完整。
- **不通过退回**：镜头问题退回 P4 重试；系统性问题退回 P3 资产/规划；故事问题退回 P2 剧本。
- **责任角色**：生产负责人 A/R；生成/拍摄操作 R；导演 C；QC C。
- **指标**：镜头一次通过率、重试率、单镜头成本、单集生产周期、模型切换率。

### 2.7 P5 单集后期包装

- **阶段目标**：把已接受的素材变成可质检、可交付的单集母版。
- **输入与前置**：单集素材包、剧本、镜头契约、配音与音乐资产。
- **主交付物**：剪辑时间线 vN、混音与字幕 vN、片头片尾、单集母版。
- **关键动作**：粗剪；精剪；音效与配乐；对白与口型；字幕；调色；混音；片头片尾；平台规格适配。
- **硬门禁**：画面锁定；声音锁定；字幕同步；响度达标；时长符合；片头片尾与 credits 齐全；平台技术规格通过；无缺失镜头。
- **不通过退回**：剪辑/声音问题退回 P5；素材缺失退回 P4。
- **责任角色**：后期负责人 A/R；剪辑、声音、字幕 R；导演 C。
- **指标**：后期周期、字幕缺陷率、响度合规率、重剪次数。

### 2.8 P6 质检合规

- **阶段目标**：用单集 QC 和批次抽检把问题拦在交付前。
- **输入与前置**：单集母版、剧本、资产、模型配置、合规清单。
- **主交付物**：单集 QC 报告、批次抽检报告、整改记录。
- **关键动作**：技术质检；内容与合规检查；角色/场景一致性检查；音频/字幕检查；跨集连续性检查；批次抽检；整改复验；QC 签字。
- **硬门禁**：所有强制维度通过；无阻断级问题；整改已验证；批次抽检通过；QC 负责人签字。
- **不通过退回**：按缺陷类型退回 P5 后期、P4 素材、P3 资产/规划或 P2 剧本。
- **责任角色**：QC 负责人 A/R；合规 C；导演 C；后期 C。
- **指标**：单集一次通过率、缺陷逃逸率、返工成本、批次抽检失败率。

### 2.9 P7 交付与复盘

- **阶段目标**：完成单集入库、季包交付，并把成本、周期、质量问题沉淀为下一季基线。
- **输入与前置**：QC 通过的单集母版、元数据、字幕、权利文件、平台交付规范。
- **主交付物**：单集交付包、季包、交付清单、复盘报告。
- **关键动作**：单集入库；季包打包；元数据与字幕整理；权利文件归档；平台验收；归档；复盘。
- **硬门禁**：全季集数完整；交付包完整；元数据与权利齐全；平台验收通过；最终审批通过；归档完成。
- **不通过退回**：QC 问题退回 P6；包内缺项退回 P7 打包。
- **责任角色**：交付制片 A/R；平台运营、法务 R；制片人 A。
- **指标**：按时交付率、交付包驳回率、单分钟成本、全季周期、复盘行动完成率。

## 3. 批次模型

### 3.1 批次划分

- B1：E01–E06；
- B2：E07–E12；
- B3：E13–E18；
- B4：E19–E24。

B1 内先做 3 集试跑（E01–E03），验证模型、资产、风格、节拍和产能；试跑通过后补齐 E04–E06。试跑是 B1 内的验证波，不改变 4 批口径。

### 3.2 两个批次门禁

**批次开工门禁**：

- 本批剧本锁定；
- 本批镜头契约与资产锁定；
- 模型基线与备用模型明确；
- 产能、预算、排期确认；
- 合规与授权无阻断。

**批次交付门禁**：

- 本批所有单集 QC 通过；
- 批次抽检通过；
- 交付包完整；
- 平台规格验证通过；
- 批次复盘记录完成。

### 3.3 滚动关系

- P2 只要求全季大纲锁定 + B1 剧本锁定；
- B1 生产期间，B2 剧本和 B3 大纲可并行开发；
- B1 试跑通过后锁定风格与模型基线，B2 可进入预演；
- B1 批次交付门禁通过后，才允许 B1 正式交付；
- B2 生产不得绕过自己的批次开工门禁；
- 任何批次发现系统性问题，暂停后续批次开工，先修基线。

### 3.4 批次边界

批次是治理单位，不是内容单位：

- 不把 6 集合成一个视频任务；
- 不要求 6 集同时生成；
- 不要求用户一次填写 6 集表单；
- 允许单集串行，也允许在产能允许时并行；
- 批次的价值是共享资产、统一模型、统一验收、统一交付。

## 4. 模型变更与重新生成

### 4.1 基本原则

模型版本是生产资产的一部分，不是临时参数。每次生成必须能回答：

- 用了哪个模型、哪个版本；
- 用了什么参考资产、seed 和参数；
- 为什么生成这一版；
- 哪一版被接受；
- 换模型影响了哪些镜头、单集或批次；
- 换完后重跑了哪些 QC。

### 4.2 三级变更

| 级别 | 场景 | 影响范围 | 审批 | 重检范围 |
|---|---|---|---|---|
| L1 镜头级 | 同模型重试、改 seed/参数 | 单个镜头 | 生成操作 + 导演抽检 | 该镜头 |
| L2 单集级 | 单集换模型或换风格 | 一集 | 生产负责人 + 导演 | 该集相关镜头与单集 QC |
| L3 批次/季级 | 全局换模型或换视觉基线 | 一批/全季 | 制片人 + 创意总监 | 试点集 + 批次抽检 |

### 4.3 变更规则

1. 同模型重试不覆盖旧版本，生成新 take，保留父子关系。
2. 单集换模型必须先做 3–5 个镜头的一致性试跑，再决定是否整集切换。
3. 批次换模型只在批次边界决策，不在批次中途静默切换。
4. 批次换模型需用 1 集或 5 个镜头做试点，比较画风、角色一致性、时长、成本。
5. 换模型后必须重跑受影响镜头的技术、角色、风格、音频/口型检查。
6. 已交付或已入库的集不自动重制；确需重制，另开“重制批次”，记录原因与范围。
7. 同一批次内如出现多次镜头级切换，升级为单集级变更；跨多集出现，升级为批次级变更。

### 4.4 变更记录字段

- `changeId`：变更单号；
- `scope`：shot / episode / batch；
- `reason`：失败、质量、成本、风格、供应商；
- `oldModel` / `newModel`：模型与版本；
- `affectedShots`：受影响镜头；
- `pilotResult`：试跑结果；
- `approver`：审批人；
- `qcResult`：重检结果；
- `effectiveBatch`：从哪一批生效。

### 4.5 禁止项

- 不记录模型版本就直接覆盖素材；
- 在批次中途无审批切换全局模型；
- 换模型后不重检就标记单集完成；
- 自动重制已交付集；
- 用“重试”掩盖资产或剧本问题。

## 5. 状态机接口

### 5.1 项目状态

```text
草稿 → 立项中 → 创意开发 → 剧本开发 → 预演准备
→ 批次生产中 → 后期包装 → 质量检测 → 交付中
→ 已完成 → 已归档
```

侧状态：`已暂停`、`已终止`、`异常`。

### 5.2 单集状态

```text
未开始 → 输入就绪 → 剧本锁定 → 规划锁定
→ 素材生成中 → 素材待审 → 素材齐
→ 剪辑锁定 → 音字锁定 → QC 中 → QC 通过
→ 终审入库 → 已交付
```

侧状态：`返工中`、`阻塞`。

### 5.3 镜头任务状态

```text
pending → queued → running → succeeded / failed
```

允许 `retry_wait`、`cancel_requested`、`cancelled`。每次重试创建新 attempt，不覆盖已接受 take。

## 6. 角色与指标

### 6.1 默认角色

| 角色 | 主要责任 |
|---|---|
| 制片人/项目负责人 | 立项、预算、批次、交付、跨部门协调 |
| 创意总监/编导 | 创意圣经、剧本方向、风格与终审 |
| 总编剧 | 全季大纲、分集剧本、连续性 |
| 导演/分镜 | 镜头契约、视觉执行、表演与节奏 |
| 资产/美术 | 角色、场景、道具、风格参考 |
| 生成/拍摄操作 | 生成任务、重试、换模型、素材整理 |
| 后期 | 剪辑、声音、字幕、包装 |
| QC/合规 | 技术、内容、一致性、合规检查 |
| 交付制片 | 单集入库、季包、平台验收 |

小团队可兼任，但 A（最终负责）不能缺位。

### 6.2 指标

**项目级**：按时交付率、预算偏差、批次周期、单集一次 QC 通过率、返工率、单分钟成本。

**单集级**：单集周期、一次通过率、返工次数、镜头接受率、字幕/音频缺陷率。

**镜头级**：一次通过率、重试次数、单镜头成本、模型切换次数。

## 7. 与现有 9 段页面的映射

| 现有阶段 | 对应流程 | 页面职责 |
|---|---|---|
| 项目概览 | L2 项目控制台 | 看批次、预算、风险、交付，不是生产阶段 |
| 创意策划 | P1 | 创意圣经与方向锁定 |
| 剧本创作 | P2 | 全季大纲 + 首批剧本锁定 |
| 导演规划 | P3 | 镜头契约、资产、模型基线 |
| 视频生产 | P4 | 单集素材生产与镜头任务 |
| 后期合成 | P5.1 | 单集剪辑与画面锁定 |
| 音频字幕 | P5.2 | 单集声音、字幕与混音 |
| 质量检测 | P6 | 单集 QC + 批次抽检 |
| 终审交付 | P7 | 单集入库 + 季包交付 |

阶段顺序统一为：创意策划 → 剧本创作 → 导演规划 → 视频生产 → 后期合成 → 音频字幕 → 质量检测 → 终审交付。单集 E0–E7、阶段管线与旧制作深链必须使用同一顺序，不得再出现“音频字幕先于后期合成”的反向映射。

页面方向：

- 顶部阶段轨保留 P0–P7 项目治理节点；
- 阶段工作区内部展示“批次 × 单集”矩阵；
- 点击某一集，进入该集工作台；
- 批次页只做分组、状态、资产锁、模型版本、抽检和交付，不做批量编辑表单；
- P4–P6 是循环区，不要按一次性线性进度展示。
