# 短剧平台任务推进与确认指令 V1

> 用途：约束“页面布局与交互优化”阶段的推进节奏，保证每次只做一个流程，用户手动核查确认后才进入下一流程。
> 适用仓库：`D:\works\AgentWorks\LocalDev\short-play-platform`
> 当前分支：`develop`，禁止新建分支。

---

## 1. 推进原则

1. **一次只推进一个流程**：同一轮只改一个页面或一个流程，不并行改多个页面。
2. **先页面后业务**：页面布局与交互未确认前，不接新的业务功能、不做真实后端。
3. **mock 即后端**：继续由 mock 模拟真实业务响应，保证后续只切环境配置即可对接真实后端。
4. **确认制**：每轮结束必须给出可手动核查的页面、路由、步骤和验收项，等待用户回执。
5. **可回滚**：每轮改动独立提交，用户可指定提交回滚，不覆盖用户已有文件。
6. **不夹带**：未在当轮范围内的优化、清理或重构，不顺手提交。

## 2. 每轮助手固定输出格式

每次任务完成后，按以下顺序输出，缺项视为交付不完整：

### 2.1 本轮定位

- 流程名称：如“项目概览”“批次看板”“单集 E3”
- 页面名称：如“项目详情 / 项目概览工作台”
- 核查地址：完整 URL，包含必要 query
- 关键路由：如 `/projects/workflow`

### 2.2 本轮变更

- 只列实际改动的页面、组件、数据或文案
- 每项写明“改前 → 改后”
- 不写实现过程细节

### 2.3 手动验收路径

- 从哪个页面进入
- 点击哪些位置
- 每一步应看到什么结果
- 给出至少 1 个反向检查点，如“不应出现横向滚动”

### 2.4 验收标准

- 必须通过的 3–6 项
- 区分“必须通过”和“建议观察”

### 2.5 实现与验证

- 本轮实际完成的代码/文档
- `npm run check`、`npm run test`、`npm run test:e2e`、`npm run build`、`npx eslint . --quiet` 结果
- 页面宽度检查结果
- 提交号与工作区状态

### 2.6 未做与风险

- 本轮明确未做的内容
- 已知限制
- 仍存在的风险或待确认项

### 2.7 下一流程候选

- 只给 **1 个**下一流程，不提前开始
- 写明进入条件和预期改动范围
- 结尾固定：**等待确认后再进入下一流程**

## 3. 用户回执指令

### 3.1 验收通过

短口令：

```text
确认通过，进入下一流程
```

完整口令：

```text
确认通过：<流程名称>。
页面 <URL> 已核对，验收项 1–N 通过。
进入下一流程：<流程名称>。
```

### 3.2 验收不通过

```text
验收不通过：<流程名称> / 页面 <URL>。
问题：<具体现象，可带截图位置>。
期望：<希望变成什么样>。
仅修此项，不进入下一流程。
```

### 3.3 保留当前流程，局部调整

```text
保留当前流程，只调整：<元素/区域/文案>。
其余布局和交互不动。
完成后重新给验收路径。
```

### 3.4 继续优化同一流程

```text
继续优化当前流程：<子项>。
不进入下一流程，完成后给验收清单。
```

### 3.5 暂停

```text
暂停推进，保留当前页面和提交。
不开始新的流程。
```

### 3.6 回滚

```text
回滚到提交 <commit>。
只回滚本流程的页面改动，不动其他文件和用户数据。
```

### 3.7 查询当前状态

```text
输出当前任务状态：
1. 当前流程与页面
2. 最近提交
3. 已完成项
4. 未完成项
5. 下一流程候选
```

### 3.8 重新整理任务规划

```text
重新输出整体任务规划、当前完成情况、后续推进计划。
保持一次一个流程，未确认不继续。
```

每次确认后，按下面格式追加一行，便于跨轮追踪：

| 轮次 | 流程 | 页面 / 路由 | 本轮实现 | 验证 | 用户结论 | 提交 | 下一流程 |
|---|---|---|---|---|---|---|---|
| R1 | 整体流程顺序 | `/projects/workflow` | 阶段顺序归一、卡片序号 | check / 108 unit / 12 E2E / lint | 待确认 | `5107278` | 项目概览信息层级 |

状态取值：

- `待确认`
- `已确认`
- `返工中`
- `暂停`
- `已回滚`

## 5. 固定验收口径

每轮页面类任务至少检查：

1. 目标页面能正常打开，无空白、无报错。
2. 主操作可点击，点击后有明确反馈。
3. 页面文案与业务顺序一致，无反向映射。
4. 1366 与 1600 宽度无页面级横向溢出。
5. 移动端或窄屏不出现内容遮挡。
6. 空态、加载态、错误态至少各检查一次。
7. 相关单测与 E2E 通过。
8. 工作区干净，提交只包含本轮范围。

---

## 6. 推荐推进顺序

1. 整体流程步骤顺序（已完成，待确认）
2. 项目概览的信息层级与批次入口
3. 批次看板：试跑、交付门禁、批次包
4. 单集工作区：E0–E2 输入与锁定
5. 单集工作区：E3 生产与 take 版本树
6. 单集工作区：E4–E5 后期与声音字幕
7. 单集工作区：E6–E7 质检与交付
8. 全链路回归与冗余清理

每个流程单独确认，不跳步、不并行。
