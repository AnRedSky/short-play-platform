# 完整流程重评估方案

- 状态：方案评估稿，待确认后实施
- 日期：二零二六年十一月二十八日
- 范围：项目级流程、单集八个执行阶段、批次编排、素材资产、人物与场景一致性
- 代码基线：开发分支最新提交

## 一、结论摘要

当前系统已经具备一条可运行的项目级阶段视图与单集执行链，但还不是完整闭环。主要问题不是页面缺失，而是四个业务对象没有真正连起来：

1. 项目阶段与单集步骤是两套口径，音频字幕阶段目前永远不会成为高亮阶段。
2. 镜头引用是自由文本，锁定资产时不校验引用是否存在、版本是否匹配、质检与授权是否通过。
3. 资产表与人物表、场景表、道具表是两套资产数据，彼此没有稳定关联。
4. 第三阶段的候选版本只是生产记录，不是资产；接受候选版本后不会形成正式镜头资产，也无法从资产库反查使用位置。

建议的目标流程不是新增一个资产阶段，而是在导演规划内增加视觉一致性基线门禁，并把素材资产中心作为项目详情的常设视图。这样既不改项目级只保留治理动作的原则，也能把一致性、资产、生产、后期、质检和交付串成一条可追溯链路。

需要明确边界：流程可以保证输入参考、版本和模型基线一致，不能单独保证生成画面一定一致。后者还需要生成模型支持角色身份条件、参考图或身份适配能力，以及独立的一致性检测。

## 二、评估方法

本次评估按以下顺序进行：

1. 以当前代码和初始演示数据为事实来源，核对阶段、状态、动作、资产与产物的真实行为。
2. 将项目阶段视图、单集状态机、素材资产对象分别建模，再检查三者之间的断点。
3. 对完整流程给出候选方案，比较改动量、业务代价和可验证性。
4. 对选定方案做数据模型、迁移、测试与真实能力边界评估。
5. 只提出可分阶段落地的范围，不把无法在当前仓库验证的能力写成已实现。

## 三、当前实现事实

### 一、项目阶段

- 项目阶段目前只依据项目状态计算当前阶段，不读取单集当前步骤。
- 初始演示数据的阶段顺序是剧本、导演、视频、音频、后期、质检、交付，但读取层会归一为剧本、导演、视频、后期、音频、质检、交付。
- 第四阶段和第五阶段都被映射为后期制作中，而后期制作中只映射到后期合成阶段。因此第五阶段不会让音频字幕成为当前阶段。
- 项目状态仍由最落后的未交付单集推导；项目级只放行治理动作，包括开始、提交与审核剧本、暂停、恢复、终止、归档。
- 动作配置中仍保留固化镜头计划、转入后期、提交质检、检测通过、终审通过、生成并交付等旧的生产推进动作。虽然这些动作已被治理白名单过滤，不再显示，但配置仍然是脏的。

### 二、单集状态机

- 单集八个阶段依次为输入确认、剧本确认、镜头与资产、素材生产、剪辑、声音字幕、单集质检、终审入库。
- 新项目在项目剧本审核通过后直接进入第二阶段；输入确认和剧本确认对新项目基本不构成实际门禁，主要留给导入、历史项目或单集补录。
- 第二阶段锁定资产时生成镜头计划版本；第三阶段任务绑定计划版本。
- 第三阶段接受候选版本时把任务置为已通过、镜头置为已通过并记录候选版本序号；不会在资产表中创建资产记录。
- 第四阶段时间线、第五阶段音频字幕、第七阶段交付包各自有阶段数据，但不自动回写资产库。

### 三、资产与产物

- 初始演示资产表共九条，当前演示项目五条：人物参考、场景参考、道具参考、分镜图集、第十六集成片。
- 人物表、场景表、道具表另有独立版本，例如人物甲第三版、场景甲第二版、道具甲第二版。
- 生成镜头时，镜头参考由人物和场景拼成字符串；道具没有进入自动参考。
- 第二阶段编辑器只有人物与场景参考自由文本，没有资产选择器，也没有道具引用。
- 锁定资产时只校验画面、人物、时长非空；不校验镜头参考是否存在、版本是否匹配、资产是否正式、质检与授权是否通过。
- 页面上的镜头参考已登记只判断字符串非空，不判断引用有效性。
- 资产库的引用关系按资产引用数量取项目前几个镜头或兜底对象，不是实际的镜头参考匹配。
- 资产表与人物表、场景表、道具表没有稳定关联；人物参考资产无法与镜头引用直接对齐。

### 四、一致性

- 质检矩阵已包含人物一致性和场景一致性维度，但质检执行目前默认通过，不读取矩阵逐项判定。
- 第三阶段候选版本的接受逻辑没有人物、场景、服装、道具连续性评分或阻断规则。
- 项目没有跨集视觉基线对象；角色或场景版本变化后，没有影响范围提示和显式沿用或升级选择。
- 单集内的计划版本冻结了镜头参考文本和镜头模型，因此输入可复现，但这不等于生成结果视觉一致。

## 四、问题分级

### 一、阻断完整流程

1. 第五阶段无法高亮音频字幕阶段，项目阶段与单集执行链脱节。
2. 视觉参考是自由文本，锁定门禁不校验有效性，无法保证进入生产的参考正确。
3. 资产表与领域资产表没有映射，资产库无法回答谁在用、用在哪一集哪一镜。
4. 第三阶段接受候选版本不形成资产，素材生产与资产库断开。

### 二、影响可维护性与验收

5. 项目阶段名视频生产与单集名素材生产不一致。
6. 资产库没有项目过滤，多个项目资产混排。
7. 资产库引用关系是占位逻辑，会误导审计。
8. 动作配置保留已废弃的生产推进动作。
9. 输入确认与剧本确认的适用边界没有在产品口径中说明。

### 三、需要外部能力才能闭环

10. 真实的人物与场景一致性评分依赖生成模型和检测模型，当前仓库无法验证。
11. 资产预览目前是文本卡片，没有真实图片、视频预览与引用图。

## 五、候选方案比较

### 方案甲：只做项目级素材产物中心

- 做法：把资产、任务、镜头、时间线、音频、字幕、交付包聚合到一个页面。
- 优点：改动小，可复用项目汇总数据。
- 缺点：解决看得到，不解决引用是否正确、版本是否漂移、接受候选版本是否成为资产。
- 结论：不能作为完整方案，只能作为后续一层。

### 方案乙：新增独立视觉资产阶段

- 做法：在导演规划后增加一个项目级阶段，专门做人物、场景、道具定稿。
- 优点：职责清晰，阶段卡直观。
- 缺点：增加项目级手动推进，和项目级只保留治理动作的既定方向冲突；现有第二阶段已经承担资产与模型锁定，重复。
- 结论：不采用。

### 方案丙：在导演规划内增加视觉一致性基线门禁

- 做法：第二阶段锁定资产时同时锁定项目级视觉基线；镜头结构化引用基线；计划版本和第三阶段任务绑定基线。
- 优点：不新增阶段；符合现有第二阶段；能把一致性输入固化到版本链。
- 缺点：需要新增基线对象和引用校验，会触及第二阶段与第三阶段数据契约。
- 结论：采用，作为核心改造。

### 方案丁：全项目统一一套基线，所有集完全共用

- 优点：最强一致性。
- 缺点：短剧存在换装、时间跳跃、场景状态变化，完全禁止变化不现实。
- 结论：不采用纯方案丁，改为项目身份基线加单集或场景造型覆盖。

### 最终选择

采用方案丙与方案丁的混合：

- 项目级视觉基线固定角色身份、场景基础、关键道具、风格和模型；
- 单集或场景允许显式造型覆盖或状态覆盖，覆盖必须记录版本和原因；
- 任何覆盖不能静默替换项目基线；
- 镜头计划版本和第三阶段任务同时绑定视觉基线。

## 六、目标完整流程

### 一、项目层

- 项目概览：立项、预算、团队、批次、风险；只读汇总，不承担生产推进。
- 剧本创作：自主编写、模型生成、小说改编，形成分集稿，提交审核，锁定后物化单集卡。
- 导演规划：新项目直达第二阶段；生成镜头契约，结构化引用，确认视觉基线，锁定资产与模型，形成第一版镜头计划。
- 素材生产：第三阶段；每镜任务绑定镜头计划与视觉基线；生成候选版本；审片与接受；接受后登记正式镜头资产。
- 后期合成：第四阶段；用正式镜头建立时间线；替换片段；产出时间线或片段资产。
- 音频字幕：第五阶段；配音、配乐、音效、字幕、口型；产出音频与字幕资产；完成音频门禁。
- 质量检测：第六阶段；单集质检；人物、场景、道具连续性作为独立维度；阻断项返工。
- 终审交付：第七阶段；终审、单集交付、批次包、归档。

项目级仍只保留治理动作；阶段切换由单集进度推导，不增加推进阶段按钮。

### 二、单集层

- 输入确认：新项目默认继承项目级输入；导入或补录项目才作为实际门禁。
- 剧本确认：项目剧本锁定后默认完成；小说改编或单集返工导致分集稿偏离时重新启用。
- 镜头与资产：镜头契约完整，引用可解析，视觉基线锁定，资产与模型锁定，生成第一版镜头计划。
- 素材生产：任务绑定镜头计划与视觉基线；候选版本可按镜头重试、换模型；接受需一致性门禁。
- 剪辑：只允许引用正式镜头资产；时间线片段变更需重新校验。
- 声音字幕：对白、配乐、音效、字幕、口型各自形成版本化产物。
- 单集质检：人物、场景、道具、视频、音频、字幕按维度出结论；阻断项必须返工。
- 终审入库：终审通过，生成单集交付包，进入批次包，最终归档。

### 三、批次层

- 批次是项目级编排视图，不替代单集状态机。
- 三集试跑只做门禁预检，不自动推进单集。
- 六集成包在全部单集交付后冻结。
- 批次视图展示瓶颈集、资产缺口、基线漂移和交付完整度。

### 四、门禁矩阵

- 剧本进入第二阶段：项目剧本正式版本锁定、单集卡已物化。
- 第二阶段进入第三阶段：镜头契约无缺项；引用全部可解析；视觉基线已锁定；关键资产正式且质检与授权通过；镜头模型属于基线允许集合。
- 第三阶段进入第四阶段：本集所有镜头有接受版本；人物、场景、道具一致性检查通过或无阻断。
- 第四阶段进入第五阶段：时间线完整、无过期片段。
- 第五阶段进入第六阶段：对白、字幕、口型、混音门禁通过。
- 第六阶段进入第七阶段：单集质检无阻断项。
- 第七阶段进入交付：终审通过；交付清单完整；资产授权有效。

## 七、视觉一致性基线

### 一、对象

建议新增视觉基线对象，包含：

- 基线编号、所属项目、版本号、范围、状态。
- 角色身份：人物编号、版本、参考资产、身份参考资产。
- 造型：人物、造型编号、版本、参考资产、说明。
- 场景：场景编号、版本、参考资产、场景状态。
- 道具：道具编号、版本、参考资产、道具状态。
- 风格：提示词、负面提示词、色彩、镜头倾向。
- 模型：图像模型、视频模型、口型模型等。
- 冻结时间与冻结人。

人物表、场景表、道具表保留为领域实体，不合并进资产表。资产表保留为文件、权利和质检层；新增实体资产关联表，建立实体与参考文件的对应。

镜头新增结构化引用，同时保留原参考文本用于显示，避免旧页面断裂。

### 二、锁定与漂移

- 第一次第二阶段锁定时，自动从当前实体版本生成项目级第一版视觉基线，并写入单集状态、计划快照和第三阶段任务。
- 镜头计划快照必须包含视觉基线编号和解析后的实际参考资产，不能只存显示文本。
- 实体版本变化后，第二阶段再次锁定会检测基线漂移：
  - 默认阻止并列出受影响的集、镜头、计划版本。
  - 用户可选择沿用旧基线或生成新基线。
- 旧计划和旧任务永远固定旧基线，不自动升级。
- 单集或场景允许造型覆盖，但必须写入原因和版本，不能直接改基线。

### 三、生成与质检

- 第三阶段生成请求携带镜头计划、视觉基线和参考资产；任务记录基线版本。
- 候选版本记录模型、基线、参考资产、随机种子或身份适配信息等可复现信息。
- 接受候选版本前做一致性门禁：人物身份、服装、场景、道具连续性；可自动评分加人工确认。
- 第六阶段复用质检矩阵的人物一致性和场景一致性维度，作为阻断项，而不是只展示文案。
- 交付前生成跨集一致性报告。

### 四、能力边界

- 当前仓库只能验证引用、版本、门禁和血缘的产品逻辑。
- 真实人脸、服装、场景相似度检测需要外部模型；如果生成模型不支持参考图或身份条件，流程只能降低漂移概率，不能承诺零漂移。

## 八、素材资产中心

### 一、数据来源

项目汇总数据已经包含资产、镜头、任务、计划、时间线、片段、音频、字幕和交付数据，因此项目级素材中心可以先用前端聚合，不新增后端接口。

### 二、视图分组

- 参考资产：人物、造型、场景、道具、分镜图。
- 候选版本：第三阶段任务与候选版本树。
- 正式镜头：已接受候选版本对应的镜头资产。
- 后期产物：时间线、片段、音频、字幕。
- 交付产物：单集成片、批次包、质检报告。

### 三、筛选与血缘

- 筛选：项目、批次、集、镜头、任务、候选版本、类型、模型、计划版本、基线版本、质检、授权、状态。
- 血缘：视觉基线、镜头计划、第三阶段任务、候选版本、接受镜头、时间线、音频字幕、交付包。
- 资产库增加项目过滤和本项目素材入口。
- 引用关系必须来自真实结构化引用和实体资产关联，不能继续使用取项目前几个镜头的占位逻辑。

## 九、数据模型与迁移

### 一、新增与扩展

- 视觉基线：项目级基线版本表。
- 实体资产关联：领域实体与资产的关联，包含实体类型、实体编号、资产编号、用途、版本。
- 镜头结构化引用：结构化引用数组；原参考文本继续保留显示。
- 单集状态记录当前基线版本。
- 任务记录绑定基线版本。
- 计划快照保存基线编号、结构化引用和模型配置。
- 资产增加集、镜头、任务、候选版本、计划版本、基线版本等可选字段，用于正式镜头资产回溯。

### 二、迁移策略

- 历史计划没有基线：标记为历史数据，不伪造绑定；下次第二阶段锁定时才生成视觉基线。
- 旧参考文本可解析为已知实体；解析失败保留原文并标记未关联资产，不删除。
- 资产库引用关系先停止返回占位镜头；解析不到就显示未关联。
- 旧项目阶段展示允许继续按项目状态回退，不强制一次性补齐。

## 十、可行性评估

| 项目 | 可行性 | 依据 | 风险 |
| --- | --- | --- | --- |
| 阶段映射修正 | 高 | 阶段推导可以增加单集状态参数；单集已有当前步骤 | 调用点较多，需要保持全局视图回退 |
| 视频生产改名 | 高 | 仅名称与测试文案，阶段标识可以保留 | 旧测试与截图文案需更新 |
| 清理旧动作配置 | 中 | 治理白名单已经过滤，删除不影响可见动作 | 需核对测试是否直接读原表 |
| 视觉基线对象 | 中 | 新增模拟数据表，第二阶段已有冻结逻辑 | 计划快照和历史计划迁移 |
| 结构化引用 | 中 | 可在生成、更新、锁定三处写入并校验 | 编辑器需要资产选择器，旧自由文本需兼容 |
| 素材产物中心 | 高 | 项目汇总数据已含所需数组 | 页面信息密度大，需要分组和筛选 |
| 接受候选版本自动资产化 | 中 | 接受逻辑已有任务与镜头关联 | 资产编号、去重、继承关系需要定义 |
| 一致性质检 | 产品逻辑高，真实检测低 | 质检矩阵已有维度 | 当前质检执行是占位实现，需外部检测能力 |
| 人物与场景零漂移 | 当前仓库不可验证 | 无生成模型参考图或身份条件接口 | 不能把流程承诺写成视觉结果承诺 |

## 十一、分阶段实施建议

### 第一阶段：流程口径修正

范围：

- 阶段从单集当前步骤推导，第五阶段正确高亮音频字幕。
- 统一素材生产命名；阶段标识保持不变。
- 清理或隔离动作配置中已废弃的生产推进动作。
- 明确输入确认与剧本确认对新项目为继承完成，对导入或补录项目才启用。

验收：

- 第四阶段进入第五阶段后，阶段卡从后期合成切到音频字幕。
- 项目状态仍由最落后单集推导；不新增项目级推进按钮。
- 现有单集流程不回归。

### 第二阶段：视觉基线与结构化引用

范围：

- 新增视觉基线对象与实体资产关联。
- 第二阶段生成镜头时写入人物、场景、道具结构化引用。
- 锁定资产时校验引用、版本、质检、授权、模型。
- 计划快照和第三阶段任务绑定基线。
- 基线漂移检测和影响范围提示。

验收：

- 引用不存在的资产时第二阶段锁定被拒。
- 同一集两个计划版本都绑定同一视觉基线；角色版本变化时明确提示。
- 第三阶段任务显示镜头计划与视觉基线。

### 第三阶段：项目素材产物中心

范围：

- 项目详情增加素材资产视图。
- 聚合参考资产、候选版本、正式镜头、后期与交付产物。
- 支持筛选、预览、血缘跳转。
- 资产库增加项目过滤；停止使用占位引用。

验收：

- 从第二阶段和第三阶段能跳到本项目素材。
- 每条正式镜头可追到计划版本、任务和基线。
- 多个项目资产不再混排。

### 第四阶段：产物资产化与一致性质检

范围：

- 接受候选版本自动生成正式镜头资产。
- 资产版本、授权、质检与引用关系写入。
- 第三阶段接受和第六阶段质检增加人物、场景、道具连续性维度。
- 交付前跨集一致性报告。

验收：

- 接受候选版本后资产库出现对应正式资产。
- 一致性不通过时不能接受或不能通过质检。
- 真实视觉评分如果未接入，必须明确标注为人工确认或未自动检测。

## 十二、测试策略

- 单测：阶段推导、引用解析、基线冻结、漂移拒绝、候选版本资产化、资产引用真实匹配。
- 端到端测试：第二阶段基线卡与锁定失败提示、第三阶段任务绑定、素材中心筛选、接受候选版本出现在资产库。
- 回归：现有单测、端到端测试、类型检查、代码检查、构建全部通过。
- 现有测试预期受影响：阶段名视频生产、第二阶段锁定流程、资产数量断言、项目阶段文案。

## 十三、待确认决策

1. 视觉基线采用项目级身份基线加单集或场景造型覆盖，还是按批次分别冻结？
2. 单镜头是否允许选择基线之外的模型？建议默认禁止，确需换模型时生成新候选版本并记录例外。
3. 人物表、场景表、道具表与资产表采用关联表，还是把领域实体并入资产表？建议保留领域实体并增加关联。
4. 素材中心放在项目详情的新视图，还是独立项目资产页？建议放在项目详情内，减少跳转。
5. 一致性质检首版只做人工确认与门禁，还是接入外部检测？建议首版先做人工确认与结构化记录，自动评分后置。

## 十四、建议的下一步

先实施第一阶段流程口径修正。它是后续基线、素材中心和质检的共同基础，改动面小且可独立验收。确认后再进入第二阶段视觉基线与结构化引用。
