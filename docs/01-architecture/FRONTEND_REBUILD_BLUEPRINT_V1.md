# 前端重建总纲

- 状态：决策稿，待确认后进入实施
- 日期：二零二六年十一月二十八日
- 适用范围：前端页面、组件、状态管理、数据访问、模拟数据适配、测试与文档基线
- 代码基线：开发分支最新提交

## 一、评估结论

当前前端具备可运行的页面与流程，但不适合继续在旧结构上叠加真实业务能力。主要原因不是页面数量多，而是业务规则、页面状态和模拟数据耦合过深：

1. 源码约八十七个文件、一万八千行，其中模拟数据服务约十四万字节，承担了大量本应属于领域层的状态判断。
2. 页面说明与规格文件约八万六千字节，核心工作区单文件约七万字节，页面同时承担展示、流程判断、数据拼装和状态回写。
3. 领域类型文件体量很小，项目、批次、单集、镜头计划、生产任务、候选镜头、正式资产之间缺少稳定的领域契约。
4. 旧文档中仍存在“必须保留现有目录结构”“不得整体搬迁”等限制，与真实业务长期迭代目标冲突。
5. 现有流程中仍有阶段映射错误、资产表与领域资产表脱节、引用关系占位、接受候选版本不生成资产等结构性问题。

结论：建议对前端核心链路执行受控重建，而不是继续在旧实现上做局部修补。受控重建指领域模型、状态机、接口契约、页面结构、模拟适配层和测试基线从零定义，旧代码只作对照，不作为新实现的依赖。

不建议直接删光旧代码再重新思考。那样会丢失已经验证过的业务规则和交互结论，容易从一个模糊实现跳到另一个模糊实现。

## 二、从零的边界

从零重定义的内容：

1. 业务对象、对象关系、唯一标识、版本规则和数据归属。
2. 项目级与单集级状态机、进入退出条件、允许动作和自动推导规则。
3. 每个流程的功能契约、权限、异常、审计和验收用例。
4. 页面职责、路由结构、组件边界和数据流。
5. 模拟数据适配层的接口、场景、失败注入和可替换边界。
6. 测试基线，包括领域规则测试、状态流转测试、契约测试和页面验收。

需要保留的内容：

1. 已由用户验收通过的流程结论，作为需求输入，不作为代码依赖。
2. 已确认的业务规则，例如项目级只保留治理动作、阶段自动推导、镜头计划版本不可变、旧任务不自动升级基线。
3. 已发现的真实业务断点，作为重建验收清单。

旧代码与旧文档的处置：

1. 新链路通过验收前，旧代码只作参考，不继续扩展。
2. 旧文档先标记为历史资料并注明替代关系，不立即删除。
3. 新链路覆盖旧能力并通过验收后，按迁移清单清理旧代码、旧页面和失效文档。
4. 旧数据清理或迁移必须可回退，不得直接删除业务数据。

## 三、目标分层

前端按以下分层重建，页面不得直接承载业务规则：

```text
web/src
  domain        领域对象、值对象、状态机、业务策略
  application   用例编排、流程服务、权限判断
  infrastructure 仓储接口、模拟适配、真实适配、数据映射
  presentation  页面、组件、布局、路由
  shared        通用错误、通用类型、通用工具
```

数据流固定为：

```text
页面 -> 应用用例 -> 仓储接口 -> 模拟适配或真实适配
```

约束：

1. 页面只负责展示、输入采集和调用用例，不直接拼装业务状态。
2. 模拟适配层只实现仓储接口，不承担业务规则，不成为业务事实来源。
3. 领域层不依赖页面、路由、浏览器存储和具体网络实现。
4. 真实后端接入时只替换适配层，页面契约和业务语义保持不变。

## 四、核心业务对象

重建必须先把以下对象定义清楚，再进入页面实现：

1. 项目：协作、授权和生产管理的顶层边界。
2. 批次：项目内的编排单元，承载集数范围和阶段推进。
3. 单集：生产管理的基本单元，拥有独立状态机。
4. 剧本版本：可审核、可锁定、可追溯的剧本事实。
5. 场次：剧本拆解后的空间与时间单元。
6. 人物、场景、道具：领域资产实体，拥有独立版本。
7. 视觉基线：项目级人物身份、场景基础、关键道具、风格和模型约束。
8. 镜头计划：单集镜头契约的不可变版本。
9. 镜头：景别、机位、运镜、时长、人物、画面、台词、参考和模型的最小生产单元。
10. 生产任务：绑定镜头计划版本和视觉基线的执行单元。
11. 候选镜头版本：一次生成产生的候选结果，不等同于正式资产。
12. 正式资产：通过接受或质检后形成的可引用资产，必须归属具体项目。
13. 时间线、音频字幕、质检记录、交付包：后期与交付阶段的事实对象。

关键不变量：

1. 资产必须归属具体项目，跨项目引用默认禁止。
2. 镜头计划版本一经固化不可修改，只能新增版本。
3. 视觉基线一经绑定，旧计划和旧任务固定旧基线，不自动升级。
4. 生产任务必须同时记录镜头计划版本和视觉基线版本。
5. 候选镜头被接受后才生成正式资产，正式资产必须能反查来源任务和计划版本。
6. 人物、场景、道具版本变化时，必须列出受影响集、镜头、计划和任务。

## 五、状态机原则

1. 项目阶段由单集状态自动推导，项目级只保留治理动作，不提供手工推进生产阶段的按钮。
2. 单集八个执行阶段依次为输入确认、剧本确认、镜头与资产、素材生产、剪辑、声音字幕、单集质检、终审入库。
3. 每个阶段必须有明确的进入条件、完成条件、阻断条件和回退条件。
4. 自动推导优先于手工操作。只有治理、审核、接受、返工等必须由人判断的动作才保留人工入口。
5. 第五执行阶段必须正确映射为声音字幕，不得与第四执行阶段合并为同一个高亮阶段。
6. 状态回退必须说明影响范围，不得静默把已生产内容改回草稿。

## 六、页面职责

重建后的页面按职责拆分，不再使用一个超大工作区承载全部流程：

1. 项目列表：项目检索、创建、状态概览。
2. 项目概览：阶段、批次、集数、风险、待办和治理动作。
3. 剧本工作区：自主编写、模型生成、小说改编、章节映射和剧本审核。
4. 导演工作区：视觉基线、人物场景道具、镜头计划、锁定与版本链。
5. 单集工作区：单集状态、镜头任务、候选版本、接受与返工。
6. 素材产物中心：参考资产、候选镜头、正式资产、时间线、音频字幕和交付包。
7. 质检中心：人物、场景、道具、技术、内容和交付检查。
8. 交付中心：交付包、版本、审核记录和回执。

页面边界要求：

1. 一个页面只承担一个主职责，复杂流程拆成子页面或抽屉。
2. 页面不得直接读写浏览器存储作为业务事实。
3. 同一业务对象只允许一个权威展示入口，避免多处口径不一致。
4. 每个页面必须有空态、加载态、失败态、无权限态和冲突态。

## 七、模拟数据适配层

模拟层只解决前端独立开发与联调，不解决真实业务规则：

1. 模拟适配层实现与真实适配层相同的仓储契约。
2. 模拟数据必须具备确定性种子，保证同一场景可重复验证。
3. 支持场景切换、失败注入、延迟注入和边界数据。
4. 模拟层不得直接改写页面状态，不得绕过应用用例。
5. 模拟层产生的数据必须明确标记来源，不能与真实业务数据混淆。
6. 真实后端接入时，只替换适配实现，不改页面契约和领域模型。

## 八、重建顺序

第一步，冻结与盘点。完成真实业务基线、对象清单、状态机、页面地图、功能契约模板和旧能力清单。此步不删除代码。

第二步，新骨架。建立领域层、应用层、适配层、表现层骨架，完成一个最小可用项目创建与项目概览链路。

第三步，项目与单集。重建项目阶段推导、批次、单集状态机和治理动作。

第四步，剧本与导演。重建三种剧本创作入口、章节映射、剧本审核、视觉基线、镜头计划和版本链。

第五步，生产与资产。重建任务、候选版本、接受、正式资产、素材产物中心和一致性门禁。

第六步，后期、质检与交付。重建时间线、声音字幕、单集质检、交付包和回执。

第七步，清理。新链路验收后删除旧页面、旧模拟逻辑、失效文档和冲突规则。

每一步都必须独立验收，未验收不得进入下一步。

## 九、功能契约模板

任何功能进入开发前，必须填写以下内容：

1. 目的：解决什么真实业务问题。
2. 使用角色：谁在什么权限下使用。
3. 入口：从哪个页面、哪个状态进入。
4. 前置状态：进入前必须满足什么条件。
5. 输入数据：字段、来源、校验规则。
6. 操作结果：成功后的业务结果和用户可见结果。
7. 后置状态：状态机如何变化，哪些对象被写入。
8. 失败处理：错误分类、提示、可恢复方式。
9. 权限要求：允许谁操作，拒绝时如何提示。
10. 审计要求：记录谁、何时、对什么对象做了什么。
11. 验收用例：正常、边界、失败、回退、无权限。

缺少上述内容的功能视为未定义，不得开始实现。

## 十、清理标准

旧代码或旧文档只有同时满足以下条件才可清理：

1. 新链路已覆盖对应业务能力。
2. 新链路的领域测试、契约测试和页面验收通过。
3. 旧数据已完成迁移或确认无需迁移。
4. 旧入口、旧路由、旧存储键和旧文档引用已全部排查。
5. 用户已验收新链路。
6. 清理清单、回退方式和影响范围已记录。

## 十一、待确认决策

1. 是否确认采用受控重建，而不是继续局部修补。
2. 是否确认旧代码在新链路验收前只作参考，不继续扩展。
3. 是否确认旧文档先标记替代关系，验收后再清理。
4. 是否确认第一步只做真实业务基线与功能契约，不立即删除旧代码。
