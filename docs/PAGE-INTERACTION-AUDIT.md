# 页面交互规范核对（P-01）

核对范围：24 个业务页 + `SpecPage`（33 条规格路由）。判定口径：跨页走路由；查看/轻编辑用抽屉；创建/批量/需填写原因用弹窗；不可逆操作必须二次确认并标危险。

## 一、结论

- 跨页跳转：全部为 `router.push` / `RouterLink`，无 `location.href`、无死循环跳转；404 与无权限页均有明确返回入口。
- 查看与轻编辑：项目、资产、镜头、生成任务使用 `AppDrawer`；创建、批量提交、需原因的动作使用 `ui.openDialog`。
- 不可逆操作：交付、终止、归档、取消任务已使用 confirm；退回类动作要求填写意见/原因。
- 本轮修复 3 处不一致：
  1. `projects/lifecycle` 的「暂停/终止/退回」原用 `window.prompt`，无法校验、样式不统一 → 改为 `ui.openDialog` 必填原因，提交后刷新。
  2. `projects/workflow` 的终止、交付、归档原先与普通推进共用无危险标识的 confirm → 按动作键加 `danger`，确认按钮显示危险色。
  3. `projects/lifecycle` 当前项目取值为非响应式快照，页头状态显示为空 → 改为 `computed`，状态与动作原因文案恢复正确。
- 规格页：行内查看统一用弹窗（组件层只提供 dialog），属于规格页的既定例外，不新增抽屉分支。

## 三、后续约束

新增页面必须复用 `useTableQuery`、`usePermission`、`useProjectScope`，交互形态按上表选择；新增不可逆动作必须同时声明 `danger` 与确认文案。
