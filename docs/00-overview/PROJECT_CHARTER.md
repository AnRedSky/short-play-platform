# 项目章程

## 1. 项目愿景

建设企业内部可控、可审计、可持续演进的 AI 短剧生产工作台，将创作资产、AI 生成任务、人工审核和媒体合成纳入同一条可追踪生产链。

## 2. 目标与成功标准

1. 用户能够在授权项目中创建剧集、维护剧本、角色、场景、道具和分镜。
2. 通过统一 Provider 接口发起文本、图片、视频、语音等外部模型调用，开发期可使用 Mock。
3. 生成过程异步执行、状态持久化、可查询、可重试、可取消，失败后能够从安全检查点恢复。
4. 素材统一入库并可追溯到项目、剧集、分镜和生成任务。
5. 使用 FFmpeg 在企业环境内完成音视频拼接、混音、字幕和 MP4 导出。
6. 企业管理员可管理用户、角色、权限、模型配置、密钥和审计记录。
7. 系统可通过 Docker Compose 部署到企业 Linux 主机，并具备备份恢复说明。

## 3. 非目标与明确边界

- 不建设 SaaS 租户隔离、租户计费、租户自助开通。
- 不在平台内运行 Ollama、vLLM、ComfyUI 或其他本地模型推理服务。
- 不建设面向公众的插件市场或任意第三方代码热加载。
- 不在 MVP 阶段拆分微服务、引入 Kubernetes 或复杂分布式编排。
- 不把完整视频生产流程塞进单个同步 HTTP 请求或单个不可恢复的 Celery 任务。

## 4. 主要用户

- 系统管理员：用户、组织、角色、模型服务、系统参数和审计。
- 项目负责人/制片人：项目、剧集、人员、生产流程与审核。
- 编剧/策划：故事设定、剧本、对白和版本。
- 美术/分镜：角色、场景、道具、镜头设计及图片审核。
- 视频制作人员：视频、音频、字幕、合成和导出。
- 审核人员：对剧本、素材、镜头和成片进行审核。

## 5. 关键约束

- 所有外部模型调用必须经过 Provider 层和数据外发策略。
- 模型凭据加密保存，接口响应、日志和异常中不得泄露密钥。
- 项目级授权在服务端强制校验，不能只依赖前端隐藏按钮。
- 业务状态和异步任务状态必须持久化，重试必须幂等。
- 媒体文件与数据库元数据分离；数据库只保存存储键、校验和及必要元数据。
- 所有 schema 变更通过 Alembic migration 管理。

## 6. 交付原则

按可运行、可验证、可回滚的小增量交付。每个开发任务必须有负责人、依赖、验收标准、测试证据和文档更新。设计、代码、测试和部署状态分别记录，不得将“已设计”标记为“已完成”。
