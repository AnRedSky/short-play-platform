# 安全基线

## 1. 身份与访问控制

- 密码使用 Argon2id 或经评估的现代密码哈希方案；禁止明文和可逆存储。
- JWT/Session 生命周期、刷新和注销策略明确；生产环境仅 HTTPS。
- RBAC 权限在后端执行；项目资源再做成员/项目角色校验。
- 管理员高风险操作、模型凭据变更、导出下载和权限变更写入审计。
- 登录限速、失败锁定/风险检测；避免账户枚举。

## 2. 外部模型 API

- 密钥加密保存，部署密钥通过安全渠道注入，不提交 .env。
- Prompt/素材按数据分类控制外发；默认拒绝未经授权的敏感数据外发。
- Provider 域名白名单、TLS 校验、SSRF 防护、重定向限制。
- 外部响应和文件下载限制大小、类型、时长和资源消耗。
- 对模型输出进行格式校验和安全处理，不将模型输出直接作为可信指令执行。

## 3. 文件与媒体安全

- 上传限制扩展名、MIME、文件签名、大小、分辨率、时长；随机化存储路径。
- 下载必须鉴权；避免路径穿越；临时文件定期清理。
- FFmpeg 使用参数数组调用 subprocess，禁止 shell=True 拼接用户输入。
- 限制 FFmpeg 超时、CPU/内存/并发；处理失败文件隔离。
- 归档/备份加密并限制访问。

## 4. 应用安全

- Pydantic 输入校验；SQLAlchemy 参数化查询；防止越权 IDOR。
- CORS 使用明确白名单；Cookie 使用 Secure/HttpOnly/SameSite。
- 日志脱敏，避免密码、Token、API Key、完整敏感内容。
- 依赖锁定并定期扫描；容器以非 root 用户运行，缩小镜像和权限。
- 生产配置禁止 debug；错误响应不暴露堆栈和内部地址。

## 5. 审计与事件响应

审计记录 actor、action、resource_type/id、timestamp、request_id、结果和必要的变更摘要。审计日志不应被普通业务用户修改。建立凭据泄露、模型外发异常、文件恶意内容、数据误删和服务不可用的应急处理流程。
