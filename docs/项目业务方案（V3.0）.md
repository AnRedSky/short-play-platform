# 第一章 项目概述与产品定位

## 1.1 项目背景

生成式人工智能已使剧本创作、人物与场景设计、分镜、视频生成、配音配乐、剪辑合成与后期处理等传统短剧制作环节具备由模型完成的能力。传统短剧生产依赖编剧、导演、摄影、美术、演员、剪辑、配音、后期等多岗位协同，组织复杂、周期长、人力成本高、沟通损耗大，且产能高度受制于人员规模与排期。

本项目建设一套面向企业内部使用的 AI 短剧制作平台，把上述专业环节收敛为「员工提需求与做决策 + AI 完成生产」的两段式结构：员工以单一账号即可独立完成一部短剧从创意到交付的全过程，企业以统一视角掌握人、项目、资产、质量、产能与成本。

## 1.2 产品定位

**一套服务于单一企业内部的 AI 短剧制作系统：企业统一管理组织、账号、角色权限、项目归属、预算制度、合规规则与经营数据；每位员工使用自己的账号并基于本人可用的 AI 资源，独立完成从创意输入到成片交付的完整制作；AI 承担专业生产执行，人工只在关键节点介入。**

定位包含三层不可混淆的含义：

1. **组织边界**：系统只服务一个企业主体，企业是最高级别的组织与数据根边界。企业内部按实际组织结构划分部门、团队与成员，这些组织单元属于企业内部治理结构，**不是** SaaS 租户，不具备独立注册、独立计费、独立部署能力。
2. **生产边界**：员工是独立制作操作者，一部短剧由一名员工独立推进；项目协作是授权行为，不是完成制作的前提。
3. **执行边界**：AI 模型与生产服务是实际生产执行主体，员工不承担编剧、导演、摄影、配音、剪辑等专业作业。

## 1.3 核心业务原则

1. 系统只服务一个企业主体，企业是组织管理与业务数据的根边界。
2. 企业内部可设多个部门与员工账号；员工凭单一账号即可独立完成整部短剧制作。
3. 不以编剧、导演、摄影、配音、剪辑等传统岗位分工作为生产前提，也不将其作为权限角色。
4. AI 模型与生产服务承担专业生产执行；员工负责创意输入、关键审核与异常决策。
5. 员工可使用本人配置的模型供应商、凭据、模型选择、路由与生产资源；个人凭据加密保存，企业任何角色均不可读取明文，也不得跨员工共享。
6. 企业可制定预算、合规、资源范围与安全策略，但不得代替员工配置或导出个人 API 凭据。
7. 任务、模型调用、生成资产、审核、交付与费用必须有真实记录；供应商成功回执不等于资产已下载、校验并持久化成功。
8. 预计成本与实际成本分开核算；失败、取消、超时与重试产生的费用均需保留。
9. 项目移交不转移个人凭据与个人资源，不改变历史执行人、资源配置人与历史费用归属。
10. 生产链路优先自动衔接；正式人工节点为剧本审核与最终成片审核，其余人工介入仅限异常决策。
11. 不引入智能体（Agent）平台、Agent 编排、Skill 市场或智能体生命周期管理。本期以业务域、业务对象、任务状态机、依赖关系与确定性规则实现自动化。
12. 项目、素材、成片与生产记录具备完整归属与版本追溯能力；人员与组织变动不导致数据丢失。

## 1.4 建设目标

| 目标域 | 建设目标 |
|---|---|
| 组织治理 | 企业、部门、员工、角色、权限与项目归属清晰可管，人员变动可追溯、可移交 |
| 独立制作 | 每位员工可凭单一账号独立完成一部短剧的全部制作环节，不依赖其他专业岗位 |
| 创意与剧本 | AI 完成创意、故事、分集、剧本与自检；剧本版本可控、可审核、可锁定 |
| 视觉与分镜 | AI 完成剧本拆解、镜头规划、人物/场景/服装/道具视觉档案，并保证跨集一致性 |
| 视频生产 | AI 按镜头生产单元生成镜头素材，支持参考约束、局部返工与版本保留 |
| 音频生产 | AI 完成配音、旁白、音乐、音效、字幕与口型同步，角色声音跨集稳定 |
| 后期交付 | AI 完成时间线编排、剪辑、混音、字幕合成、分集与整剧输出，并形成标准交付包 |
| 任务可靠 | 生产任务具备真实状态、依赖、重试、暂停、取消、异常恢复与结果回收 |
| 质量可控 | 建立资产级、镜头级、单集级、整剧级四级质量门禁，不合格内容可定位、可局部返工 |
| 成本可算 | 用量、预计成本、实际成本、费用承担方与预算规则可追溯，费用来源可区分 |
| 统计可信 | 企业可按员工、部门、项目、集、镜头、任务、模型能力统计真实产出、质量、效率与成本 |
| 资产可复用 | 数字资产具备类型、版本、来源、授权、引用与归档能力，复用不重复计量 |
| 合规可审 | 内容合规、第三方素材与真人授权纳入台账；关键操作形成不可由普通用户篡改的审计记录 |

## 1.5 非目标与产品边界

**平台负责的业务：**

- 企业、部门、员工、角色与权限管理。
- 项目立项、归属、成员授权、移交与生命周期管理。
- AI 创意、剧本、导演规划、视觉资产、视频、音频、后期、质量检测与交付。
- 生产任务编排、依赖调度、重试与异常恢复。
- 人工审核节点与异常决策。
- 数字资产、用量成本、预算与企业经营统计。
- 合规台账与审计。

**平台不以此为核心的业务（明确排除）：**

- 传统专业岗位（编剧/导演/摄影/剪辑/配音）的任务分配、人工交接与岗位绩效管理。
- 多部门、多岗位的制作审批流与多级会签。
- 面向多个互不关联企业的 SaaS 注册、租户入驻、套餐订阅与租户计费。
- 跨企业或跨项目的资产共享与检索。
- 专业级非线性编辑器、实时多人协同剪辑。
- 自建 GPU 推理集群、本地大模型推理服务或自研基础模型。
- 公开插件市场或将不可信插件代码直接加载进服务进程。
- 承诺第三方模型的质量、可用性、价格或生成结果可直接商用。
- 以 Agent / Skill 作为系统功能组织方式与运行主体。

外部 AI 模型、视频生成、语音、音乐与转码服务属于平台的生产能力来源，其接入方式不改变「员工单人独立制作」的业务体验。平台可调用第三方能力，但不得因第三方服务差异把制作责任转回员工。

# 第二章 总体业务架构

## 2.1 四层业务架构

平台按「企业治理 — 项目协作 — 员工制作 — AI 生产能力」四层组织。四层是业务职责分层，不是四套独立系统，也不以租户层作为隔离单元。

```text
企业内部 AI 短剧制作平台
│
├── 第一层：企业统一治理层
│   ├── 企业主体与基础信息
│   ├── 部门与组织单元
│   ├── 员工账号与身份
│   ├── 角色、权限与数据范围
│   ├── 企业策略（预算、合规、资源范围、安全）
│   ├── 企业级项目总览
│   ├── 企业经营与产出统计
│   └── 审计与运维隔离
│
├── 第二层：项目协作与授权层
│   ├── 项目归属与生命周期
│   ├── 项目成员与授权
│   ├── 项目负责人与移交
│   ├── 项目预算与合规要求
│   └── 项目内资产与交付边界
│
├── 第三层：员工独立制作层
│   ├── 个人工作台与指令入口
│   ├── 个人 AI 资源配置
│   ├── 创意与剧本
│   ├── 导演规划与视觉资产
│   ├── 视频与音频生产
│   ├── 后期与质量
│   ├── 审核与交付
│   └── 个人产出统计
│
└── 第四层：AI 生产能力层
    ├── 文本与推理能力（创意、剧本、结构化、逻辑检查）
    ├── 图像能力（人物、场景、道具、分镜）
    ├── 视频能力（镜头生成、编辑、修复、增强）
    ├── 语音能力（配音、旁白、克隆、识别）
    ├── 音乐与音效能力
    ├── 口型与数字人能力
    ├── 视觉理解与内容审核能力
    └── 媒体处理与转码能力
```

各层职责约束：

1. 企业治理层负责规则与边界，不承担日常制作，也不读取员工个人凭据明文。
2. 项目协作层以「项目」为授权与协作边界，项目是资产、任务、成本与交付的唯一归属容器。
3. 员工制作层以「镜头」为最小生产单元，员工的全部操作围绕项目与镜头展开。
4. AI 生产能力层只提供能力，不替代业务状态；能力调用必须由业务任务驱动并留下调用记录。

## 2.2 业务功能域总图

平台功能按 15 个业务域组织，域之间以业务对象引用，不以页面跳转耦合。

| 序号 | 功能域 | 主要子域 |
|---|---|---|
| 1 | 企业工作台 | 项目总览、员工产出、待处理事项、质量与成本汇总 |
| 2 | 组织与权限 | 企业主体、部门、员工、角色、权限码、项目成员授权、离职与移交 |
| 3 | 项目中心 | 项目列表、创建、详情、生命周期、成员、归档 |
| 4 | 员工制作工作台 | 项目任务、创作入口、阶段进度、待审核、异常 |
| 5 | 创意与剧本 | 多方式创意输入、方案生成、剧本生成、编辑、版本、审核 |
| 6 | 导演与视觉 | 剧本拆解、集场、镜头规划、人物/场景/服装/道具资产 |
| 7 | 视频生产 | 镜头生产计划、生成、参考约束、返工、可用素材 |
| 8 | 音频与字幕 | 声音配置、对白、旁白、音乐、音效、字幕、口型 |
| 9 | 后期与交付 | 时间线、剪辑、混音、合成、质量、终审、交付包 |
| 10 | 个人模型资源 | 供应商、凭据、模型能力、路由、连通性测试、调用记录 |
| 11 | 生产任务中心 | 计划、依赖图、队列、任务详情、重试、取消、异常 |
| 12 | 数字资产中心 | 分类检索、详情、版本、授权、引用、归档 |
| 13 | 用量与成本中心 | 用量、预计/实际成本、预算、费用承担方、账单 |
| 14 | 企业经营分析 | 企业/部门/员工/项目/作品/质量/效率/成本分析 |
| 15 | 合规、审计与系统设置 | 授权台账、风险记录、审计检索、基础设施、队列、存储、数据保留 |

平台管理端（基础设施与全局配置）与企业端、员工端共用同一套业务对象，但权限与可见范围不同。

## 2.3 核心业务链路

```text
企业 → 部门 → 员工 → 创作项目 → 剧本版本 → 生产计划
     → 镜头生产单元 → 音视频资产 → 分集成片 → 最终交付
```

链路中各环节的业务含义：

- **企业**负责组织管理与规则边界。
- **部门**承载组织归属与授权范围，用于人员组织与统计维度，不作为数据隔离租户。
- **员工**负责独立操作、创意输入、审核决策与个人资源配置。
- **项目**承载短剧制作过程，是资产、任务、成本与交付的归属容器。
- **剧本版本**是全部下游生产的基准，锁定后不可静默覆盖。
- **生产计划与镜头生产单元**把剧本转换为可执行、可计量、可返工的生产单元。
- **音视频资产**承载生产成果并保留版本与来源。
- **分集成片与最终交付**是正式产出，进入统计中的「有效交付数据」。

## 2.4 使用模式

| 使用模式 | 业务说明 |
|---|---|
| 企业统一治理模式 | 一个企业主体统一管理部门、账号、角色、策略、预算、合规与企业级数据 |
| 部门组织模式 | 按事业部、部门、制作中心或项目团队划分组织单元，承载人员归属与管理视图 |
| 员工独立制作模式 | 员工在授权项目范围内独立完成整部短剧 |
| 项目协作模式 | 通过项目成员授权支持多人查看、编辑、审核或管理，但不改变单人可完成制作的前提 |
| 跨部门管理视图 | 企业授权角色按职责查看多个部门或全企业汇总数据，默认不开放全量明细 |

本产品不提供跨企业共享的 SaaS 业务平台，也不以独立个人工作室作为主业务模式。

## 2.5 责任边界

| 主体 | 必须承担 | 明确不承担 |
|---|---|---|
| 企业 | 组织与账号治理、角色权限、预算与合规制度、项目归属、经营统计、审计 | 代替员工配置个人凭据、代替员工做内容审核决策 |
| 项目负责人 | 项目推进、成员授权、关键审核、异常决策、移交配合 | 读取他人员工凭据、绕过审核与预算规则 |
| 员工 | 创意输入、个人资源配置、剧本与成片审核、异常决策、交付确认 | 专业影视制作作业、为第三方模型质量背书 |
| AI 能力 | 生成、校验、修复、质量检测、结构化分析 | 替代人工审核结论、自行认定合规通过 |
| 平台 | 状态与记录一致性、任务调度、成本归集、审计留痕 | 用模拟数据或占位结果冒充真实生产能力 |

| | Notification | 通知与待办事项 |

对象命名与字段命名在数据模型、API 与前端之间必须一致；同一业务含义不得在不同层使用不同名称。

## 3.2 归属关系与归属字段

```text
Enterprise
  ├── Department（可选层级）
  │     └── Employee（成员关系）
  ├── Project（归属企业）
  │     ├── ProjectMember（成员与授权）
  │     ├── CreativeBrief → Story → ScriptVersion
  │     ├── ProductionPlan → ProductionTask → TaskAttempt → ModelInvocation
  │     ├── Episode → Scene → Shot → Asset
  │     ├── Review / QualityReport
  │     └── Delivery
  ├── ProviderConfig（仅企业托管模式，归属企业资源池）
  ├── UsageRecord / CostRecord
  ├── AuditEvent
  └── 企业统计与快照
Employee
  └── ProviderConfig / Credential / ModelProfile / RoutePolicy（个人自持模式，归属员工本人）
```

归属规则：

1. 项目、资产、任务、审核、交付与费用必须归属到具体企业；资产与任务还必须归属到具体项目。
2. **创建人、负责人、执行人、资源配置人、费用承担方分别记录**，不得用单一 user_id 代替全部归属关系。
3. 个人模型配置归属员工账号，不归属项目；项目移交不改变配置归属。
4. 任务执行时记录实际执行员工、所用配置 ID、模型标识、供应商任务 ID 与实际费用。
5. 资产记录创建人与执行人；复用资产创建引用关系，不转移历史归属。
6. 部门归属用于组织视图与统计维度，不作为数据隔离主键；数据隔离以企业根边界与项目授权为准。

## 3.3 版本与引用规则

- 需版本化的对象：CreativeBrief、ScriptVersion、ProductionPlan、ShotContract、AssetVersion、Timeline、Delivery、QualityReport。
- 新版本不覆盖旧版本；版本之间保留差异、修改人、时间与原因。
- 下游对象引用上游对象时必须锁定具体版本号，不得引用「当前最新」这类浮动指针作为生产输入。
- 上游版本变更后，按下游依赖快照计算受影响范围，标记过期（stale）而非自动重做。
- 已通过审核并锁定的正式版本不得静默覆盖；变更必须产生新版本并重新走审核。
- 正式交付版本冻结，后续修改另建版本，历史交付记录不可改写。
- 删除对象前必须检查引用关系；被镜头、时间线或交付引用的资产禁止直接删除。

## 3.4 状态机总则

1. 所有状态迁移必须由真实业务动作或系统回执触发，禁止页面手工随意改状态。
2. 每次状态迁移保留迁移记录：迁移前后状态、触发动作、操作者或系统主体、时间、关联任务或供应商回执。
3. 状态与业务结果分离：任务「成功」、文件「已下载」、资产「已持久化」、质量「已通过」是四个不同状态。
4. 统计口径读取状态快照与业务记录，不依赖可被人工修改的展示字段。
5. 终止、归档、取消为终态或准终态，进入后禁止回到进行中，只能另建新对象或新版本。

# 第四章 组织、账号与权限

## 4.1 企业主体

系统部署对应一个企业主体，企业是最高级别的组织与数据治理边界，不作为可由外部客户自行注册的 SaaS 租户。

企业主体基础信息包括：企业名称、企业标识、企业简介、企业状态、企业管理员、成员数量、部门数量、企业级预算与资源策略、企业级统计与审计配置。

企业统一治理功能：

1. 初始化并维护唯一企业主体信息。
2. 创建、调整、停用与归档部门及组织单元。
3. 管理企业全局账号、认证与安全策略。
4. 配置企业级预算制度、合规规则、模型与供应商允许范围、数据外发策略。
5. 配置项目创建规则、资源配额上限与跨部门授权策略。
6. 查看企业级项目、员工产出、质量与成本汇总。
7. 审计跨部门访问、数据导出与权限调整。
8. 维护系统级配置的边界，确保运维配置与员工个人凭据隔离。

企业状态变更（如停用）必须保留全部项目、资产、交付与历史记录，不得级联删除业务数据。

## 4.2 部门与组织单元

部门用于承载企业内相对独立的组织归属与管理视图，可按事业部、部门、制作中心、业务单元或项目团队划分。部门**不是**独立法人、不是独立部署实例、不是计费单元，也不作为数据隔离租户。

部门属性至少包括：部门名称、部门编码、上级部门、负责人、状态、成员关系、可访问项目范围、部门统计视图。

部门管理功能：创建、编辑、启用、停用、归档、层级调整、负责人配置、成员配置、部门视图授权、部门数据归档。

组织边界规则：

- 所有项目、任务、资产、生成记录、成本明细与交付记录必须归属一个企业；建议同时记录所属部门以便组织统计。
- 员工通过企业成员关系与项目授权获得访问权限；账号本身不代表可访问全部项目。
- 同一员工可归属一个主部门并按授权参与其他部门项目，但每次业务操作必须明确当前项目上下文。
- 部门之间默认不可互相检索、读取、修改或引用对方项目资产；跨部门查看必须经项目授权或企业级授权，并留审计。
- 部门停用或组织调整不得删除其项目、作品及历史记录；部门归档后数据只读可查。

## 4.3 员工账号与成员关系

员工账号是企业内的唯一身份，至少包含：账号、姓名或显示名称、所属企业、所属部门、账号状态、加入时间、可选登录凭据信息（不含密码明文）。

员工管理功能：添加员工、邀请加入企业、修改资料、分配角色、启用或禁用账号、设置项目访问权限、设置资源使用范围、查看负责项目、查看生产记录、查看产出统计、查看资源消耗、离职移交。

员工档案的业务统计字段：负责项目数量、已完成项目数量、已交付作品数量、生产成本统计、生产质量统计、个人贡献记录。

约束：

1. 员工离职不得导致项目、资产或交付被删除；必须先完成或挂起进行中任务，再移交。
2. 账号停用后立即失效登录与会话，但其历史执行记录保留并标注状态。
3. 员工不得自行修改企业级策略；企业不得代替员工创建个人凭据。
4. 同一员工可兼具多个业务角色，但权限按角色与项目授权共同判定。

## 4.4 角色体系

平台不以传统制作岗位定义角色，角色按管理职责与平台使用权限划分。

| 角色 | 主要职责 | 权限边界 |
|---|---|---|
| 系统运维管理员 | 部署、运行、监控、备份恢复、技术配置与故障处理 | 基础设施权限；默认不读取业务内容；运维访问业务数据须授权并留痕 |
| 企业管理员 | 企业主体、部门、账号、角色、项目归属、预算制度、合规与经营查看 | 企业全域按职责授权；个人凭据明文始终不可见 |
| 部门管理员 | 本部门成员、项目归属、部门资源与统计视图 | 本部门范围；不得跨部门读写 |
| 项目负责人 | 项目推进、成员授权、关键审核、异常决策、移交配合 | 负责项目范围；不得读取他人凭据 |
| 普通员工 | 独立制作短剧、维护个人 AI 资源、审核与交付 | 本人及被授权项目 |
| 审计与经营管理人员 | 查询操作、调用、成本、授权与交付追溯记录，查看授权范围经营指标 | 只读审计或指定部门/汇总视图；不自动获得内容修改权 |

各角色的关键职责说明：

- **系统运维管理员**：负责部署、运行、监控、备份恢复与技术排障；不因运维身份自动获得业务内容读取权限，必要的运维访问须经授权并留痕；不得读取任何个人凭据明文。
- **企业管理员**：维护唯一企业主体、部门与全局身份；制定角色权限基线与安全策略；配置预算制度、模型允许范围与资源策略；查看企业级汇总统计；批准跨部门授权并审计。
- **部门管理员**：管理部门资料、成员、部门内项目归属与部门统计；可配置部门内预算提醒阈值（在企业策略范围内）；不得查看其他部门明细。
- **项目负责人**：推进项目生命周期、维护成员授权、组织剧本与成片审核、处理异常、配合移交；对项目内任务与资产有管理权。
- **普通员工**：创建项目、输入创意、配置个人资源、审核剧本与成片、处理异常、确认交付；仅使用本人配置的资源。
- **审计与经营管理人员**：查看被授权范围的项目进度、产出、质量、效率与成本；执行审计检索与导出；不得修改项目内容，不得读取凭据明文。

## 4.5 权限模型

采用 **RBAC 权限码 + 项目成员授权 + 数据范围** 的三层校验，服务端在每次读取、修改、生成、审核与导出时校验。

1. **功能权限（RBAC）**：以权限码表达可执行动作，如项目创建、项目编辑、成员授权、剧本审核、成片审核、任务重试、任务取消、资产删除、成本导出、凭据配置、系统配置等。
2. **项目授权**：员工必须在项目成员关系中具备对应权限（查看、编辑、审核、管理）才能访问项目内对象；非成员即使持有功能权限码也不得访问项目内数据。
3. **数据范围**：按企业、部门、项目、本人四类范围裁剪可见数据集合，范围由角色与授权共同决定。
4. **凭据隔离**：个人凭据属于独立安全域，任何业务权限码均不授予凭据明文读取能力。

权限判定优先级：企业根边界 → 数据范围 → 项目授权 → 功能权限码 → 对象状态约束（如终态不可编辑）。任一环节不满足即拒绝，并返回可理解的拒绝原因。

## 4.6 权限基本规则

1. 平台运维数据与企业业务数据分离，运维身份默认不具备业务内容访问权。
2. 企业是系统部署级最高业务边界；企业内项目之间默认隔离，跨项目访问必须授权。
3. 员工必须通过有效企业成员关系与项目授权访问业务数据。
4. 部门管理员仅能管理本部门；企业管理员与跨部门角色的权限按职责最小化授予。
5. 经营、审计、管理人员仅可访问明确授权的范围与汇总指标，不得因拥有查看权而获得修改权。
6. 员工不能自行修改企业级资源配置与企业策略。
7. 员工离职不能导致项目和资产被删除。
8. 项目移交必须保留完整历史记录、历史执行人与历史费用归属。
9. 企业管理员的管理权限不能绕过内容合规规则与操作审计。
10. 导出、删除、移交、归档、凭据变更与权限调整必须产生审计事件。

## 4.7 凭据与运维隔离

1. 个人 API Key/Token 在传输与服务端存储过程中受保护，服务端以密钥管理机制加密，界面仅显示脱敏信息。
2. 凭据不进入前端日志、普通审计详情、导出文件、项目资产或通知内容；审计只记录变更元数据（配置 ID、时间、操作者、动作），不记录密钥值。
3. 更新凭据后新任务使用新版本，历史任务保留配置引用标识但不回显密钥。
4. 配置失效时暂停相关任务并通知配置人，禁止静默改用其他员工的凭据。
5. 系统运维人员可维护加密密钥材料与存储安全，但不得通过运维手段导出业务凭据明文；此类访问必须具备双人复核或等效控制并留痕。

## 4.8 人员变动处理

| 场景 | 处理要求 |
|---|---|
| 员工调岗 | 更新部门归属与项目授权；历史执行记录保持原归属 |
| 账号停用 | 立即失效会话；进行中任务按策略暂停；项目与资产保留 |
| 员工离职 | 项目移交、待办转交、授权回收；不得删除任何历史数据 |
| 部门归并 | 迁移成员与项目归属，保留原部门编码与历史统计 |
| 权限调整 | 即时生效并写审计；被撤销授权者不能通过旧链接继续访问 |

# 第五章 项目立项与创意策划

## 5.1 项目属性

项目创建时必须定义以下属性，缺失项在校验阶段定位到具体字段：

| 属性 | 说明与约束 |
|---|---|
| 项目名称 | 必填；企业内允许重名但编号唯一 |
| 项目类型/题材 | 必填；用于创意约束与统计维度 |
| 目标受众 | 必填；影响语言、节奏与尺度 |
| 计划集数 | 必填；正整数，受企业策略上限约束 |
| 单集时长 | 必填；与画幅、平台要求联动校验 |
| 画幅与分辨率 | 必填；决定后续生成与合成规格 |
| 语言 | 必填；影响对白、字幕与配音 |
| 风格要求 | 建议填写；影响视觉档案与提示词 |
| 内容禁忌与边界 | 建议填写；进入合规预检条件 |
| 预计预算 | 建议填写；按企业预算制度校验格式与额度 |
| 交付格式与交付要求 | 必填；决定交付包内容与编码参数 |
| 负责人 | 默认创建者；可指定其他有权限员工 |
| 所属部门 | 默认创建者部门；影响统计与授权视图 |
| 说明 | 可选 |

项目资产、任务、成本与交付全部归属该项目；个人资源与凭据不属于项目资产。

## 5.2 项目创建流程

前置条件：员工已登录；具备项目创建权限；如需立即调用 AI，至少有一项匹配的个人可用模型配置。

流程：

1. 进入「新建项目」，选择空白创建或从既有项目复制**非敏感**配置（题材、风格、规格、交付要求；不复制凭据与历史任务）。
2. 填写项目属性与创意要求。
3. 选择创意输入方式并填写创意内容。
4. 系统校验必填项、取值范围、预算格式、集数与时长组合、个人资源可用性。
5. 保存项目，生成唯一项目编号，归属当前企业，记录创建人、负责人与所属部门。
6. 进入项目工作台，显示创意 brief、当前阶段、待办事项与资源检查结果。

输出：项目档案、创意 brief 初始版本、项目成员关系、创建审计记录。

校验与异常规则：

- 必填缺失：定位字段并阻止保存，不生成半成品项目。
- 无可用 AI 配置：允许保存草稿，但阻止启动生成，并引导配置资源。
- 预算规则不满足：说明具体原因（超出制度上限、格式错误、额度不足）。
- 重复提交：使用幂等键避免生成重复项目。
- 项目创建本身不要求模型调用成功；创建成功与生成成功是两件事。

## 5.3 创意输入方式

| 方式 | 用户输入 | 系统处理 | 输出 |
|---|---|---|---|
| 自由描述 | 自然语言描述灵感、人物、冲突或场景 | 提取题材、主题、冲突、受众与约束 | 结构化创意 brief |
| 题材/类型选择 | 题材、类型、风格标签 | 按选择生成创作约束，不套用固定剧情 | 创意方向候选 |
| 故事梗概扩写 | 已有梗概或短篇内容 | 识别主线、人物、冲突、转折与结局 | 完整故事大纲 |
| 角色/关系驱动 | 人物设定、人物关系与核心矛盾 | 生成角色目标、关系变化与冲突线 | 人物关系与故事方案 |
| 场景/事件驱动 | 一个场景、事件或反转设想 | 扩展前因、冲突升级与后续影响 | 故事切入点与剧情线 |
| 参考资料辅助 | 用户有权使用的文本、图片或资料 | 提取参考特征并保留来源，不默认复制受保护表达 | 参考分析与创意建议 |
| 自定义结构化输入 | 用户填写题材、受众、时长、风格、禁忌等 | 校验必填项与互斥约束 | 可编辑创意 brief |

上述方式均为创意模块内的业务输入路径，不得实现为智能体入口或 Skill 调用。

## 5.4 创意方案生成流程

1. 员工选择输入方式并提交 brief。
2. 系统将 brief 版本化，记录操作者、输入内容与资料来源。
3. 检查文本模型能力、上下文长度、结构化输出要求与个人配置状态。
4. 生成题材定位、核心卖点、故事主题、世界观、人物关系、主线冲突、分集方向与风险提示。
5. 展示多方案对比，员工选择、编辑或要求调整。
6. 保存选定方案为项目创意版本，生成故事大纲与分集结构。
7. 将确认结果交剧本生成流程。

失败处理：

- 调用失败保留原输入与失败记录；重试生成新的调用记录，不覆盖原记录。
- 切换模型前必须验证能力、上下文长度与输出结构兼容。
- 禁止把「请求已发出」或「供应商返回成功」直接标记为创意资产成功；必须校验结果结构并保存后，才视为产出。
- 创意方案被驳回可直接重新生成，不消耗正式剧本版本。

## 5.5 项目状态机

| 状态 | 含义 | 进入条件 | 是否可终止 |
|---|---|---|---|
| 草稿 | 已创建，未启动生产 | 项目保存成功 | 是 |
| 创意策划中 | AI 正在生成创意方案与故事大纲 | 员工提交创意 brief 并启动 | 是 |
| 剧本创作中 | AI 正在生成或修订剧本 | 创意方案确认 | 是 |
| 待剧本审核 | 候选剧本就绪，等待人工审核 | 剧本生成完成且自检通过 | 是 |
| 生产准备中 | 进行剧本拆解、镜头规划与视觉资产准备 | 剧本审核通过并锁定正式版本 | 是 |
| 生产中 | 正在执行镜头视频与音频生成 | 镜头生产计划固化 | 是 |
| 后期制作中 | 正在剪辑、混音、字幕合成与分集输出 | 镜头与音频素材达到可用比例 | 是 |
| 质量检测中 | 正在执行单集级与整剧级检测 | 分集成片输出完成 | 是 |
| 待最终审核 | 成片就绪，等待人工终审 | 质量检测完成且无阻断项 | 是 |
| 已完成 | 终审通过，尚未交付 | 终审结论为通过 | 否（可退回返工） |
| 已交付 | 交付包生成并确认交付 | 交付执行完成 | 否 |
| 已归档 | 交付后完成资产归档 | 归档动作完成 | 否 |
| 已暂停 | 主动暂停，阻止新任务派发 | 员工或管理员执行暂停 | 可恢复 |
| 异常中 | 存在需人工处理的生产异常 | 任务达重试上限、资源不可用、预算触发、合规高风险等 | 可恢复或终止 |
| 已终止 | 项目终止，下游计划取消 | 终止动作并记录原因与确认人 | 终态 |

状态迁移规则：

1. 主流程状态按业务动作顺序推进，不允许跨阶段跳跃（如从「剧本创作中」直接进入「生产中」）。
2. 「质量检测中」由分集成片输出自动进入，检测完成且无阻断项自动进入「待最终审核」；不允许靠人工点按钮模拟。
3. 「已暂停」「异常中」为干涉状态，可挂在任一进行中状态之上；恢复时回到被挂起前的状态，并重新计算可执行任务。
4. 「已终止」时取消尚未执行的下游计划与任务，保留已产生记录与费用。
5. 「已完成」后如终审要求返工，可退回「后期制作中」或「生产中」，但必须保留原终审记录。
6. 状态变更必须写入项目生命周期记录，包含原因、操作者、时间与关联任务。

## 5.6 项目成员与授权

- 项目负责人或有权限的企业/部门管理员可邀请员工进入项目，指定查看、编辑、审核或管理权限。
- 项目成员授权按项目粒度生效，不授予企业级数据范围。
- 撤销授权后，员工立即不能通过旧链接或旧会话访问项目，但历史操作记录保留。
- 成员不得通过项目授权获得他人个人凭据；协作不等于共享资源。
- 成员变更写审计事件，并影响待办与通知的接收对象。

## 5.7 项目移交流程

1. 管理员或当前负责人选择待移交项目与接手员工。
2. 校验接手员工账号状态、项目访问权限与个人资源配置状态。
3. 生成移交预览：进行中任务、待审核事项、资产清单、交付状态、预算余额与风险项。
4. 确认移交，更新项目负责人与成员授权，记录移交时间与原因。
5. 未完成任务按策略暂停，或经接手人确认后恢复；**不得使用原负责人的个人配置发起新调用**。
6. 接手员工选择本人模型配置，并重新执行预算预检与资源可用性检查。
7. 保留原创建人、历史负责人、执行人、调用配置引用与费用归属。
8. 写入移交审计记录；历史数据不做重写。

移交约束：项目归属企业不变；资产与交付归属不变；个人凭据不随项目转移；未完成任务的费用仍归属原资源配置人与原费用承担方。

## 5.8 项目异常与终止

进入异常的情形至少包括：任务连续失败达上限、重要人物严重不一致、剧情与正式剧本严重偏离、内容合规风险较高、模型不可用且无可用备用能力、成本超出批准预算、版权或授权信息不明确、关键资产损坏或丢失。

异常处理要求：暂停受影响链路而非整项目全停；通知到项目负责人与资源配置人；给出原因、影响范围与可执行动作；处理后形成闭环记录。

终止要求：必须记录终止原因、确认人与时间；取消未执行任务；保留已完成资产、任务记录与已发生费用；终止后项目只读可查，允许复制为新项目重新立项。

# 第六章 剧本创作与审核

## 6.1 剧本生成

输入：已确认创意方案、项目规格（集数、单集时长、画幅、语言）、人物设定、内容边界与格式要求。

处理流程：

1. 故事结构拆分为主线、支线、人物弧光与关键转折。
2. 生成分集大纲：每集目标、核心冲突、情绪变化、集尾钩子。
3. 生成场次、场景、人物、动作、对白与必要旁白。
4. 检查人物动机、时间线、设定冲突、重复对白与剧情连续性。
5. 生成结构化剧本与可阅读文本两套表达。
6. 保存候选版本、生成参数、模型调用记录与关联输入。

输出：剧本版本、分集大纲、场次列表、人物与场景提取结果、剧本质量检查报告。

短剧剧本必须重点保证的要素：

- 开场前 3 秒冲突或强钩子。
- 核心人物目标清晰、动机成立。
- 每集情绪有起伏，避免平铺。
- 单集结构紧凑，符合竖屏观看节奏。
- 追剧动力持续，悬念可延续。
- 反转与悬念有铺垫，不靠偶然。
- 每集结尾留钩子，但不制造无解矛盾。
- 全剧形成闭环，主线有收束。

## 6.2 剧本编辑与版本管理

- 支持按集、场、对白段落编辑，编辑不破坏结构化数据。
- 每次保存形成可追溯版本或明确的修订快照。
- 展示版本差异、修改人、修改时间与修改原因。
- 版本可标记为草稿、待审核、已通过、退回、已废弃。
- 已通过版本为生产基准，不允许静默覆盖。
- 新版本通过后执行影响分析，识别受影响集、场、镜头、对白、音频与时间线。
- 仅重新生产受影响内容，保留未受影响的已验证资产。

## 6.3 剧本审核（正式节点 A）

审核内容：故事方向与题材定位、人物设定与关系、分集剧情与结构、故事逻辑、对白质量、内容合规、版权与授权风险。

操作流程：

1. 候选剧本生成完成，项目进入「待剧本审核」。
2. 员工逐集预览剧本，查看人物、场景与合规提示。
3. 可提交总体意见，或定位到具体段落添加批注。
4. **通过**：记录审核人、版本、时间与结论，锁定正式剧本版本，进入导演规划。
5. **退回修改**：必须填写修改意见，创建修订任务，项目回到「剧本创作中」。
6. **终止项目**：记录原因与确认人，取消尚未执行的下游计划。
7. 审核历史不可覆盖；重新审核产生新记录，不对旧记录做修改。

审核通过后形成正式剧本版本，作为后续全部生产活动的唯一基准。

## 6.4 剧本变更影响分析

正式剧本变更后，系统必须分析并输出：

| 分析维度 | 输出内容 |
|---|---|
| 人物 | 受影响人物、设定变更点、是否需重建视觉档案 |
| 场景 | 受影响场景、场次变化、是否需重建场景资产 |
| 对白 | 新增/修改/删除的对白条目及其音频影响 |
| 镜头 | 需重生成的镜头清单与其依赖资产 |
| 音频 | 需重配、重混或重做口型的音频范围 |
| 时间线 | 受影响分集、片段与合成任务 |
| 任务 | 需新建、需取消、可复用的生产任务 |
| 统计口径 | 返工量计入返工率，不计入新增生成量 |

影响分析结果必须到镜头级清单，不能只给汇总计数；确认后仅创建受影响的重生产任务。

## 6.5 剧本环节的校验与失败处理

- 剧本生成失败保留输入与失败原因，可重试或换模型；重试生成新调用记录。
- 结构化校验不通过（缺集、缺场、对白缺失、角色引用不存在）不得进入待审核状态。
- 合规预检给出风险项与位置，风险等级高的必须先处理再提交审核。
- 剧本导出与预览不得改变版本状态；仅审核动作可改变状态。

# 第七章 AI 导演规划与视觉资产

## 7.1 剧本结构化拆解

流程：读取已通过剧本 → 解析集/场/人物/场景/道具/服装/对白/动作 → 建立实体引用关系 → 检查遗漏与冲突 → 生成镜头规划草案 → 保存导演规划版本。

输出：集场结构、场景清单、人物出场表、道具服装清单、镜头清单、镜头间连续性约束。

拆解规则：

- 每个场景必须归属具体集与场次编号，且至少关联一个镜头。
- 每个人物出场必须有明确的场次与镜头归属，避免「幽灵角色」。
- 对白必须绑定角色与镜头，未绑定对白不得进入音频生产。
- 拆解结果与剧本版本强绑定，剧本换版后必须重新拆解或确认沿用。

## 7.2 镜头与分镜规划

每个镜头生产单元至少包含：

| 字段组 | 字段 |
|---|---|
| 标识与归属 | 项目、剧本版本、集、场、镜头编号、镜头顺序 |
| 场景与人物 | 场景、出场人物、人物状态（服装/情绪/道具） |
| 摄影设计 | 景别、机位/角度、镜头运动、构图、焦段倾向 |
| 表演与内容 | 画面描述、人物动作、表演情绪、对白、旁白 |
| 声音需求 | 环境音、动作音效、音乐提示、口型要求 |
| 时间 | 预计时长、前后镜头关系、转场意图 |
| 生成约束 | 参考资产版本、生成提示、模型能力要求、画幅与分辨率 |
| 质量要求 | 质量检查项、合格标准、允许返工次数 |
| 状态 | 生产状态、质量结果、当前采用版本 |

流程：

1. 根据场景与剧情节奏拆分镜头。
2. 规划景别、机位、运动、人物调度与时长。
3. 生成分镜图或视觉描述。
4. 检查镜头连续性、人物出入场、轴线关系与场景一致性。
5. 员工可在不改变正式剧本的前提下微调导演规划。
6. 固化镜头生产计划，进入视觉资产准备与视频生产。

约束：导演规划微调不得改变剧情事实与对白内容；如需改剧情，必须回到剧本变更流程并重做影响分析。

## 7.3 人物资产

流程：提取人物设定 → 生成外貌与视觉特征描述 → 生成多角度参考图 → 检查身份一致性 → 员工选定正式参考 → 建立人物档案。

人物档案包含：人物标识、姓名、年龄特征、外貌、体态、发型、服装方案、表情参考、视觉禁改特征、参考图版本、来源、生成参数与授权状态。

规则：

- 人物档案是跨集复用的视觉身份基准，重要人物生成必须优先使用参考图约束。
- 人物资产可跨集复用，但复用不重复统计生成量与成本。
- 人物设定变更必须产生新版本，并触发受影响镜头评估，不得直接覆盖旧参考图。
- 涉及真人形象或肖像素材时，必须有可核验授权。

## 7.4 场景资产

流程：提取场景 → 生成环境与空间描述 → 生成全景与多角度参考 → 校验空间布局、光线与时间连续性 → 固化场景版本。

场景档案包含：场景标识、类型（内景/外景）、空间布局、环境氛围、光线方案、色彩倾向、关键陈设、参考图版本、来源与授权状态。

## 7.5 服装与道具资产

服装：按人物、剧情时间与场次建立服装状态 → 生成参考图 → 检查跨场连续性 → 绑定人物与镜头。

道具：识别剧情关键道具 → 建立外观、尺寸、材质、使用状态与持有关系 → 生成参考图 → 绑定场次与镜头。

规则：关键道具在跨场次中必须保持外观与状态一致；道具损毁、转手等剧情变化必须显式记录状态，不能靠模型自行推断。

## 7.6 视觉一致性与连续性

连续性检查维度：人物外貌与年龄、发型与服装、场景空间与光线、道具外观与状态、镜头间位置与动作衔接、全片视觉风格统一。

一致性控制手段：

1. 重要人物优先使用参考图与身份嵌入约束。
2. 关键场景优先使用场景参考资产与视角约束。
3. 每个镜头引用具体资产版本，不使用浮动引用。
4. 生成后执行一致性检测，不合格进入修复或重生成。
5. 跨集复用资产时记录复用关系，便于回溯问题来源。

## 7.7 视觉资产验收

- 人物、场景、服装、道具资产必须可被引用，且有稳定标识与版本。
- 资产必须记录来源（模型、参数摘要、参考输入）与授权状态。
- 视觉资产进入正式生产前需经一致性抽检；抽检不合格不得固化。
- 资产固化后变更需新版本，旧版本保留以支持历史项目复现。

# 第八章 视频镜头生产

## 8.1 镜头生产计划

系统根据镜头清单拆分生产任务，每个任务记录：前置资产、输入素材版本、所需模型能力、预计时长、预计成本、优先级、依赖关系与质量标准。

计划规则：

- 可并行镜头并行生产；受同一人物或场景参考资产约束的镜头在资产就绪后并行。
- 存在镜头衔接要求的镜头（同一场景连续动作）按顺序生产，避免风格漂移。
- 单集内镜头按叙事顺序优先，集与集之间可并行。
- 任务拆分粒度到镜头，不得以整集为单个任务，否则无法局部返工与成本归集。
- 计划固化后变更必须走计划版本，不允许直接改任务列表导致依赖错乱。

## 8.2 镜头生成流程

1. 校验正式剧本版本与镜头生产单元状态（是否已固化、是否引用了有效资产）。
2. 校验人物、场景、道具等引用资产是否可用且版本有效。
3. 依据员工个人或企业托管的模型路由，选择支持对应输入模式、时长、分辨率、参考图与商业许可的模型。
4. 估算成本并按项目预算规则预检。
5. 提交供应商任务，记录本地任务 ID、供应商任务 ID、模型配置 ID 与请求摘要。
6. 轮询或接收回调更新供应商执行状态。
7. 下载生成结果，校验文件类型、大小、时长、分辨率、完整性与可播放性。
8. 保存到资产存储，生成资产版本与校验摘要。
9. 执行画面、人物一致性、动作、时长与合规检测。
10. 合格镜头进入可用素材；不合格进入局部修复或重新生成。

**四状态分离原则（强制）：** 供应商任务成功、文件下载成功、资产持久化成功、质量检测通过是四个独立状态，不得合并为一个「成功」。任一步失败都必须保留失败原因与已发生费用。

## 8.3 镜头返工

- 返工需指定问题镜头与问题类型（画面异常、人物不一致、动作不符、时长不符、合规风险等）。
- 保留旧版本及其费用；重新生成创建新任务与新资产版本。
- 成功后更新「当前采用版本」，不删除历史结果。
- 不得因单个镜头问题无条件重做整集或整剧。
- 返工次数达到上限后进入待人工处理，由员工决定调整策略、换模型或接受现状（接受现状必须记录理由）。

## 8.4 视频生产能力清单

平台视频生产能力至少覆盖：文生视频、图生视频、参考人物视频、人物动作生成、人物表情生成、多人物互动、对白口型同步、镜头运动、场景动态生成、视频延展、镜头衔接、视频修复、镜头重新生成。

视频生成必须与后期制作区分：

- **视频生成**负责生产单个镜头素材。
- **后期制作**负责把多个镜头与音频组织为完整作品。

不得把后期合成能力计入视频生成能力的完成度。

# 第九章 音频、字幕与口型

## 9.1 角色声音配置

为项目人物选择可用语音模型与声音方案，记录声音配置、语言、音色描述、语速、情绪范围、授权来源与适用镜头范围。

规则：

- 同一人物跨集使用同一声音档案，保证音色稳定。
- 真人声音克隆必须具备可核验授权；无授权不得生成、不得交付。
- 声音方案变更必须新建版本，并触发受影响对白的重新配音评估。

## 9.2 对白与旁白生成

流程：读取正式剧本对白 → 识别角色与情绪 → 生成语音 → 校验音频文件（格式、时长、采样率、可解码）→ 语音识别回听或文本比对 → 调整发音、重音与停顿 → 保存音频资产及时间信息。

输出：角色对白音频、旁白音频、语音时间轴、对白与人物匹配关系。

失败处理：单条对白失败只重做该条；不得因一条对白失败重做整集配音。

## 9.3 音乐与音效

根据场景情绪与动作生成或选择背景音乐、环境音与动作音效，记录来源、授权、使用区间、音量与混音参数。

约束：不得默认将第三方音乐视为可商用；来源不明的音乐不得进入正式交付包。

## 9.4 字幕

由正式对白生成字幕文本与时间轴，执行 ASR 校对、错字检测、时间轴检查与角色匹配。

规则：

- 字幕文本必须与最终采用的对白音频一致，不以剧本文字为唯一依据。
- 字幕时间轴以整数时间精度存储，避免累计漂移。
- 字幕样式（字号、位置、安全区、断句）按项目规格统一。

## 9.5 口型同步

口型同步任务需校验：视频输入可用性、语音输入可用性、模型能力兼容性、时长匹配关系。

失败处理：只重做受影响的对白或镜头；口型与画面严重不符时按镜头返工处理。

## 9.6 音频质量与返工

音频质量问题类型：爆音与削波、底噪过高、音量不平衡、采样率不符、对白与角色不匹配、字幕与语音不一致、音乐版权不明。

处理原则：可自动修复的问题（降噪、增益、重采样）进入修复任务；不可修复的重新生成；修复与重生成均需记录费用。

# 第十章 后期制作与成片输出

## 10.1 时间线编排

时间线按集管理，至少包含：视频轨、对白轨、音乐轨、音效轨、字幕轨、特效轨。

每个片段记录：源资产与版本、入点、出点、时长、顺序、转场、音量、速度与字幕内容。

规则：

- 时间线唯一权威时间基准为整数时间刻度（如 PTS + 有理数时基），浮点秒不作为权威字段。
- 片段引用源资产版本，源资产变更不自动改写时间线，而是标记片段过期待确认。
- 时间线版本化，正式输出绑定具体时间线版本。
- 轨道顺序与层级在项目内统一，避免不同集风格不一致。

## 10.2 自动剪辑

流程：读取镜头顺序与时长目标 → 选择合格镜头（仅使用通过质量门的素材）→ 按剧情节奏编排 → 对齐对白与音频 → 生成转场 → 检查黑帧、静音、音画不同步与重复片段 → 生成预览版本。

剪辑规则：

- 未通过质量门的镜头不得进入正式时间线。
- 单集时长偏离规格超过阈值时必须提示并说明原因。
- 同一镜头重复使用需显式记录，避免误判为自动填充。
- 预览版本与正式输出版本区分管理。

## 10.3 调色、特效与片头片尾

- 调色按项目整体风格基准执行，集间色彩偏移需在容差内。
- 特效仅用于叙事或风格需要，不得用于掩盖生成缺陷。
- 片头片尾按项目模板生成，模板版本随项目记录。
- 字幕、台标、水印等叠加元素需在合规审查范围内。

## 10.4 合成输出规格

合成按项目规格执行：画幅、分辨率、帧率、编码格式、码率、音频采样率、声道布局、字幕烧录策略。

合成任务必须记录：输入资产版本、处理参数、执行日志、输出文件与校验结果。

强制约束：

- 输出未通过播放完整性检查（可解码、时长一致、音视频流完整）前，不得标记为正式成片。
- 合成过程不得覆盖源资产；导出先写临时文件，校验通过后原子发布。
- 失败输出保留日志与部分产物，便于定位；不静默删除失败记录。

## 10.5 分集与整剧输出

- 分集成片是单集级质量检测与交付的基本单位。
- 整剧输出按交付要求合并或打包，保留分集独立文件。
- 集数完整性必须核对：计划集数、已生产集数、已通过集数、已交付集数。
- 缺集、错序、重复集必须在交付前拦截。

## 10.6 后期制作能力清单

平台后期能力至少覆盖：镜头筛选、镜头排序、自动剪辑、镜头时长调整、转场、画面裁切、画幅与比例调整、调色、画面增强、字幕生成与合成、特效、片头片尾、音频混合、视频合成、成片输出。

# 第十一章 质量检测与返工

## 11.1 检测层级

| 层级 | 检测对象 | 主要检查内容 |
|---|---|---|
| 资产级 | 单个文件/资产版本 | 文件完整性、格式、分辨率、时长、可解码性、校验摘要 |
| 镜头级 | 镜头生产单元 | 画面异常、人物一致性、动作与表情、构图、时长、音画质量 |
| 单集级 | 分集成片 | 剧情完整、镜头顺序、字幕、对白、音乐、混音、节奏 |
| 整剧级 | 全剧 | 人物弧光、故事连续性、风格统一、集数完整、合规、交付完整 |

## 11.2 检测维度矩阵

| 检测维度 | 资产级 | 镜头级 | 单集级 | 整剧级 |
|---|---|---|---|---|
| 剧本质量（逻辑、人物关系、完整性） | — | — | ✓ | ✓ |
| 内容合规（敏感、违规、风险提示） | — | ✓ | ✓ | ✓ |
| 人物一致性（外貌、服装、年龄、身份） | — | ✓ | ✓ | ✓ |
| 场景一致性（场景、道具、环境连续性） | — | ✓ | ✓ | ✓ |
| 视频质量（清晰度、闪烁、画面异常） | ✓ | ✓ | ✓ | — |
| 表演质量（动作、表情、口型） | — | ✓ | ✓ | — |
| 音频质量（清晰度、音量、噪声） | ✓ | ✓ | ✓ | — |
| 字幕质量（内容、时间轴、错别字） | — | — | ✓ | ✓ |
| 剪辑质量（衔接、节奏、重复） | — | — | ✓ | ✓ |
| 成片质量（集数、播放、交付格式） | — | — | ✓ | ✓ |

## 11.3 质量结果与门禁

| 结果 | 含义 | 后续动作 |
|---|---|---|
| PASS | 全部检查项通过 | 允许进入下游环节 |
| REVIEW_REQUIRED | 存在需人工判断项 | 阻止自动推进，转人工确认 |
| FAIL | 存在明确不合格项 | 进入修复或重生成，不可进入下游 |

约束：质量分数只用于辅助排序与趋势判断，不替代合规结论、版权判断与人工审核。质量检查不得仅由生成该内容的同一模型自我评价，必须使用独立检测能力与明确标准。

## 11.4 质量流程

1. 生产任务输出资产后自动触发对应层级检测。
2. 生成结构化检测项：检查项、问题位置（集/场/镜头/时间点）、严重等级、建议动作。
3. 可自动修复的问题进入修复任务。
4. 需重新生成的问题关联原任务与原资产，建立新任务。
5. 质量通过后才允许进入下游。
6. 质量不通过且达到自动重试上限时进入「待人工处理」。
7. 质量报告与被检对象版本绑定，版本变更后报告失效并需重检。

## 11.5 返工规则

1. 返工必须定位到最小单元：镜头、对白、音频片段或时间线片段。
2. 返工保留旧版本、旧费用与旧检测报告。
3. 返工产生新任务与新版本，成功后更新当前采用版本。
4. 返工量计入返工率，不计入新增生成量。
5. 返工不得绕过预算规则；超预算返工需按预算规则处理。
6. 质量豁免通道在 MVP 阶段不开放；确需例外时必须记录理由、批准人与风险说明。

## 11.6 质量报告

质量报告至少包含：被检对象与版本、检测层级与维度、检查项清单、问题位置与等级、结论、生成时间、检测能力来源、后续处理记录。

报告用于：审核依据、返工依据、交付包组成、企业质量统计与对外交付说明。

# 第十二章 生产任务、调度与异常恢复

## 12.1 任务模型

每个生产任务必须记录：

| 字段组 | 字段 |
|---|---|
| 标识 | 任务 ID、项目、集、场、镜头、任务类型、所属阶段 |
| 依赖 | 前置任务、后续任务、并行组、依赖资产版本 |
| 输入输出 | 输入资产、输出资产、预期产出规格 |
| 执行主体 | 实际执行人、资源配置人、模型配置 ID、模型标识 |
| 外部关联 | 供应商任务 ID、请求摘要、回调或轮询状态 |
| 状态 | 状态、优先级、重试次数、最大重试次数 |
| 成本 | 预计成本、实际成本、失败成本、费用承担方 |
| 时间 | 创建、开始、结束、最后更新时间 |
| 异常 | 错误码、错误摘要、日志引用、处理结论 |

任务粒度必须到可独立返工、可独立计量的最小单元（镜头、对白、音频片段、单集合成、单集检测等）。

## 12.2 任务状态定义

| 状态 | 含义 |
|---|---|
| 待执行 | 已创建，依赖未满足或未入队 |
| 排队中 | 依赖满足，等待执行资源 |
| 执行中 | 已提交或正在本地执行 |
| 成功 | 输出校验通过并已进入质量流程 |
| 失败 | 执行失败且未恢复 |
| 取消中 | 已发出取消请求，等待供应商确认 |
| 已取消 | 取消完成 |
| 暂停中 | 已发出暂停请求，等待运行中步骤收口 |
| 已暂停 | 暂停生效，不能再派发 |
| 重试中 | 因失败或质量不合格正在新建尝试 |
| 待人工处理 | 达重试上限或触发异常策略，等待决策 |

规则：状态迁移由任务服务与供应商回执驱动；每次迁移保留记录；「成功」不得由前端或人工直接置入；取消与暂停以供应商确认与本地状态共同判定。

## 12.3 调度流程

```text
创建生产计划 → 构建依赖图 → 检查前置资产就绪 → 选择模型路由
→ 预算预检 → 入队 → 提交供应商 → 监控执行 → 回收结果
→ 文件校验 → 资产持久化 → 质量检测 → 标记成功并释放后继任务
```

各环节失败必须停留在对应环节，不得跳过校验直接标记成功。

## 12.4 依赖与并行规则

- 依赖关系必须显式建模：前置任务、后续任务、可并行组、可复用资产、需审核任务。
- 上一阶段完成且达到质量标准后，自动触发下一阶段，不要求员工在模块间手动搬运数据。
- 下游任务启动前必须校验上游产出已持久化且版本有效。
- 存在人物/场景参考依赖的镜头，等待资产就绪后再进入队列。
- 任务失败不阻塞无依赖关系的其他分支；受影响分支暂停。
- 已成功任务不得因分支重跑而被无条件重做。

## 12.5 重试与备用模型

重试前必须识别失败类型：可重试（超时、限流、临时不可用）、不可重试（参数错误、内容违规、授权缺失）、供应商拒绝、下载失败、文件损坏、质量不合格。不同类型采取不同策略，不得统一盲重试。

规则：

1. 每次重试新建 Attempt，保留原失败记录与原费用。
2. 不得无限重试；必须有最大重试次数与退避策略。
3. 切换备用模型前必须检查能力、输入输出模式、参考素材支持、时长与分辨率限制、商业许可、质量要求与费用差异；不得仅因供应商不同就视为兼容。
4. 每次模型切换创建独立调用记录，注明切换原因。
5. 达重试上限后暂停受影响任务并通知项目负责人与资源配置人，进入待人工处理。

## 12.6 暂停、取消与恢复

- 项目或任务暂停时阻止新任务派发，并按供应商能力取消或等待运行中任务收口。
- 取消结果以供应商确认与本地状态为准；无法立即取消的标注「取消中」并持续跟踪。
- 恢复时重新计算可执行任务集合，不重复提交已成功任务。
- 取消、暂停与超时产生的费用仍须入账，不得因未产出结果而丢弃记录。
- 恢复后必须重新做预算预检与资源可用性检查。

## 12.7 生产衔接门禁

每个生产阶段必须有明确输入、输出与质量标准，衔接条件为：

1. 上游对象处于有效版本且未被标记过期。
2. 上游质量结果为 PASS（或 REVIEW_REQUIRED 已经人工确认）。
3. 下游所需资产、配置与预算均可用。
4. 未处于暂停、异常或终止状态。

门禁不满足时任务保持「待执行」，并给出具体阻塞原因，不允许以「跳过」方式强行推进。

## 12.8 异常类型与处理路径

| 异常类型 | 典型原因 | 处理路径 |
|---|---|---|
| 任务连续失败 | 模型不稳定、提示词不适配 | 有限重试 → 调整参数或换模型 → 转人工 |
| 人物严重不一致 | 参考资产缺失或约束不足 | 重建参考 → 局部重生成 → 抽检 |
| 剧情偏离正式剧本 | 提示词或上下文越界 | 回溯镜头与剧本比对 → 重生成 |
| 内容合规高风险 | 敏感内容、违规表达 | 阻断下游 → 人工判断 → 修改或终止 |
| 模型不可用 | 供应商故障、配额耗尽、凭据失效 | 切备用 → 暂停并通知配置人 |
| 预算超出 | 实际成本高于批准额度 | 暂停受影响任务 → 请示调整或缩减范围 |
| 授权不明确 | 肖像、声音、音乐、字体授权缺失 | 阻断交付 → 补授权或替换素材 |
| 关键资产损坏 | 存储异常、文件损坏 | 标记损坏 → 使用历史版本 → 重生成 |

## 12.9 自动化的实现边界

- 自动化由业务规则、状态机、依赖图与任务服务实现，不引入自主智能体做流程决策。
- 「自动衔接」指规则触发的任务创建与放行，不是模型自由编排。
- 「自动失败恢复」指按失败类型映射预设策略，不是模型自行发明修复方案。
- 自动能力必须有可观测状态、可复现的规则与可审计的调用记录，否则不得标记为已实现。

# 第十三章 AI 模型与资源配置

## 13.1 资源供给模式

平台支持两种资源供给模式，由企业策略决定项目或部门采用哪一种；同一企业内允许并存。

| 模式 | 资源归属 | 适用场景 | 关键约束 |
|---|---|---|---|
| 企业托管模式 | 企业资源池，凭据由企业集中管理 | 企业统一采购、统一结算、统一合规审查 | 员工不接触凭据明文；按配额与优先级分配；用量归企业 |
| 个人自持模式 | 员工个人，凭据由员工本人维护 | 员工自带模型账号、按个人额度生产 | 凭据不可被他人读取或共享；费用归属个人或按制度报销 |

无论采用哪种模式，以下规则一致：调用必须留痕、成本必须归属、凭据必须加密、权限必须最小化、能力必须声明。

## 13.2 模型能力分类

| 能力类别 | 主要用途 |
|---|---|
| 文本生成 | 创意、剧本、大纲、结构化内容 |
| 推理 | 剧情逻辑、连续性、复杂内容分析 |
| 图像生成 | 人物、场景、道具、分镜 |
| 图像编辑 | 参考图修正、局部重绘、风格统一 |
| 视频生成 | 镜头与动态表演 |
| 视频编辑 | 延展、修复、增强、裁剪 |
| 语音合成 | 角色配音、旁白 |
| 语音识别 | 台词识别、字幕校对、配音回听 |
| 音乐生成 | 配乐 |
| 音效生成 | 环境音、动作音效 |
| 口型同步 | 对白与画面口型匹配 |
| 数字人 | 人物表演驱动 |
| 视觉理解 | 画面审核、人物与场景一致性判断 |
| 内容审核 | 合规与风险识别 |
| 视频处理 | 调色、增强、修复 |
| 媒体转码 | 格式、码率、封装转换 |

## 13.3 模型选择原则

模型能力选型必须综合考虑：生成质量、稳定性、商用授权、API 或产品可用性、生成时长、参考图与参考视频支持、人物一致性表现、任务成功率、使用成本、服务地域与可访问性、数据外发合规要求。

供应商与型号属于可调整业务配置，不得把单一供应商固定为平台唯一生产依赖。

## 13.4 三级模型策略

- **主生产模型**：承担主要生产任务，按能力与项目要求选定。
- **辅助模型**：协助生成、检查、优化与对照。
- **备用模型**：主模型不可用或质量不达标时切换，切换前完成兼容性校验。

路由依据包括能力匹配、质量要求、成本、可用性、时延、个人偏好与项目要求；每次调用保存最终选择理由与配置版本。

## 13.5 个人配置流程

1. 员工进入个人模型设置，选择内置供应商适配器或自定义兼容接口。
2. 填写供应商名称、API Endpoint、认证方式、API Key/Token、区域与备注。
3. 凭据在传输与服务端存储过程中受保护，服务端加密保存，界面仅显示脱敏信息。
4. 声明模型能力类型、输入输出模式、限制与参数。
5. 发起连通性测试，验证鉴权、模型可用性与能力响应。
6. 保存配置，记录创建人、更新时间、测试结果与配置版本。
7. 员工可禁用、更新、删除或设为默认；被任务引用的配置保留历史快照。

## 13.6 企业模型治理

企业可以配置：允许的供应商与模型范围、必须声明的能力、数据外发策略、费用上限、资源配额、并发与优先级、默认预算、备用模型要求、允许的凭据类型。

企业治理边界：

- 企业可定义策略与白名单，但不得导出、读取或向他人共享个人凭据。
- 企业托管模式下，企业可统一结算与分配配额，但员工仍只能看到本人在用配置的脱敏信息。
- 模型白名单变更需审计；已在执行的任务不因白名单收紧而中断，但新任务必须符合新策略。

## 13.7 配置安全与异常

- API Key 不进入前端日志、审计详情、导出文件、项目资产与通知正文。
- 更新凭据后新任务使用新版本，历史任务保留引用标识但不回显密钥。
- 配置失效时暂停相关任务并通知配置人；禁止静默使用其他员工凭据。
- 未配置可用能力时返回明确的「未配置」错误，不得静默回退到演示模型或伪造结果。
- 演示与测试用途的模型适配器只能用于开发测试环境，不得作为生产默认。

# 第十四章 数字资产中心

## 14.1 资产分类

| 类别 | 包含资产 |
|---|---|
| 创意与剧本资产 | 创意 brief、故事大纲、世界观设定、人物关系、分集剧情、正式剧本、剧本修订版本、合规预检报告 |
| 人物资产 | 人物设定、人物参考图、表情与多角度参考、人物服装方案、人物声音档案 |
| 场景资产 | 场景设定、场景参考图、空间与光线方案、场景陈设 |
| 服装与道具资产 | 服装方案与变化、关键道具外观与状态 |
| 分镜与镜头资产 | 分镜图、镜头提示词与契约、原始视频、合格视频、重生成视频、采用版本 |
| 音频资产 | 角色对白、旁白、配乐、音效、混音文件、语音时间轴 |
| 字幕与时间线资产 | 字幕文件与时间轴、时间线版本、剪辑工程 |
| 成片与交付资产 | 分集成片、最终成片、封面、宣传素材、交付包、质量与生产报告 |

## 14.2 资产详情字段

资产必须包含：类型、名称、企业与项目归属、创建人、执行人、来源（模型调用与参数摘要）、版本、存储位置与校验摘要、格式、时长或尺寸、质量状态、授权信息、引用关系、创建与更新时间。

正式资产与临时素材必须区分管理：临时生成素材可清理，正式资产参与生产与交付，不得随意删除。

## 14.3 版本规则

- 新版本不覆盖旧版本；版本号单调递增或使用不可比较但可追溯的标识。
- 展示版本差异与使用位置（被哪些镜头、时间线、交付引用）。
- 资产被引用时删除前必须检查引用关系；有引用则禁止直接删除，需先解除引用或归档。
- 项目移交不改变资产历史归属与来源。
- 正式交付资产锁定历史版本，后续修改创建新版本。
- 资产来源与生成参数需可回溯，以支持项目复现与问题定位。

## 14.4 复用与引用

- 复用资产创建引用关系，不复制文件本体，不重复统计生成量与成本。
- 跨集复用人物、场景、服装、道具资产是默认策略，复用记录用于一致性维护。
- 项目内可复用；跨项目共享与检索为明确非目标，需要时以显式导出再导入方式处理并留审计。
- 引用关系必须可查询，支持「某资产被哪些对象使用」的反向检索。

## 14.5 删除与归档

- 删除需具备权限，并区分「逻辑删除」「物理删除」。
- 已被引用、已进入交付或已归档的资产不得物理删除。
- 项目归档后资产只读可查，支持导出与恢复。
- 归档不等于删除，归档数据仍参与历史统计与追溯。

## 14.6 资产管理规则

1. 每个资产关联所属企业与项目。
2. 每个资产具备明确资产类型与稳定标识。
3. 资产保留生成来源、参数摘要与版本信息。
4. 资产可关联人物、场景、道具、镜头与剧本版本。
5. 正式生产资产与临时生成素材区分管理。
6. 重要资产修改保留历史版本。
7. 删除资产遵守权限与引用关系规则。
8. 项目移交时保留资产完整性与历史来源。
9. 企业可在权限范围内复用历史资产。
10. 涉及第三方素材与模型生成内容时，保留必要的授权及来源信息。

# 第十五章 用量、成本与预算

## 15.1 计量维度

Token、图片张数、视频生成秒数、音频时长、音乐曲目数、转码分钟、存储量与供应商其他计费单位。同时保留供应商原始计量与平台统一计量，两者不可互相替代。

## 15.2 费用归属维度

必须分别记录：资源配置人、实际执行人、项目归属、部门归属、费用承担方、供应商账户归属、费用来源。

费用来源区分：员工个人账户实际扣费、企业承担、企业报销、赠送额度、免费额度、其他来源。

不得假定所有个人 API 费用均由企业承担；也不得把企业托管资源费用记到员工个人。

## 15.3 成本流程

```text
任务提交前估算预计成本 → 预算规则预检 → 调用完成读取供应商用量/账单
→ 计算实际成本 → 记录失败/重试/取消费用 → 关联项目、员工、配置人、承担方
→ 汇总至项目成本与报表
```

要求：

- 预计成本与实际成本分栏展示，不混为一项。
- 未取得可靠账单时标记「待核实」，不得伪造实际金额。
- 费用调整必须保留原值、调整人、原因与凭据。
- 失败与重试费用必须入账，不得因无产出而丢弃。

## 15.4 成本统计维度

项目成本、单集成本、单镜头成本、图像生成成本、视频生成成本、音频生成成本、后期处理成本、失败任务成本、重试成本、存储与转码成本。

## 15.5 预算规则与控制

1. 每个项目可设总预算。
2. 每个项目可设单集预算，单集预算之和不得超过总预算（或按企业策略允许弹性，需显式声明）。
3. 记录每次模型调用的实际成本与计费依据。
4. 记录失败、重试与取消产生的成本。
5. 优先用低成本方式做预生成与验证（如低分辨率、短时长、草图）。
6. 重要镜头允许使用高质量模型，但需计入预算。
7. 已合格资产优先复用，避免重复生成。
8. 预算接近阈值时自动提醒项目负责人与员工。
9. 超过批准预算时暂停受影响的生产任务，而不是整项目静默继续。
10. 企业管理员可统一配置员工资源额度与部门预算，但不得删除已发生费用记录。

预算状态建议分为：未设置、正常、接近阈值、已超限、已冻结。预算冻结时禁止派发新任务，已发生费用仍可入账。

## 15.6 成本真实性要求

- 不得以估算成本替代实际成本参与结算。
- 不得把供应商成功回执当作计费完成；计费以用量或账单为准。
- 不得因任务失败而将费用置零。
- 不得把免费额度与赠送额度记为现金成本。

# 第十六章 人工审核、合规与审计

## 16.1 审核原则

AI 负责生产，人工负责关键决策。审核不是多岗位审批流，正式节点仅两个：剧本审核与最终成片审核。其他人工介入限定为异常决策。

审核必须具备：明确对象、明确版本、明确结论、明确意见、明确后续动作、可追溯记录。

## 16.2 剧本审核（节点 A）

审核内容：故事方向、题材与内容定位、人物设定与关系、分集剧情与结构、故事逻辑、对白质量、内容合规、版权与授权风险提示。

审核结果：通过、退回修改、终止项目。

退回时必须填写修改意见并定位到集/场/段；通过后锁定正式剧本版本，形成下游唯一基准。

## 16.3 最终成片审核（节点 B）

审核内容：整体剧情完整性、成片质量、人物一致性、视频画面、音频质量、字幕准确性、集数完整性、剪辑与节奏、内容合规、交付完整性。

审核结果：

| 结果 | 后续动作 |
|---|---|
| 通过交付 | 进入交付流程，生成交付包 |
| 指定镜头/片段返工 | 建立局部返工任务，仅重做指定内容 |
| 退回后期 | 回到后期制作，重做时间线或合成 |
| 终止交付 | 记录原因，取消交付，保留全部记录 |

审核意见必须关联具体版本与问题位置（集、场、镜头、时间点），不允许只写整体评价。

## 16.4 审核记录

审核记录必须包含：审核对象、所属项目、审核版本、审核人、审核时间、审核结果、调整意见、关联问题位置、相关生产任务、后续处理记录。

审核历史不可覆盖；重新审核产生新记录；审核记录与对象版本绑定，版本变更后原审核结论不再适用于新版本。

## 16.5 异常决策

员工只需作出处理决策，不承担具体制作执行。可决策项包括：调整生成策略、切换模型、缩小或扩大返工范围、调整预算、补授权或替换素材、接受当前质量并记录理由、终止项目。

每个异常决策必须记录：问题、决策、理由、影响范围、后续任务。

## 16.6 合规范围与授权台账

合规检查覆盖：创意、剧本、人物形象、场景、道具、视频、配音、声音克隆、音乐、音效、字体、字幕、后期与最终交付。

授权记录必须包含：素材来源、权利主体、授权证明、用途范围、地域、期限、商用范围、限制条件、复核状态。

模型商用条款按供应商与模型版本留档；不得因内容由 AI 生成就默认具备完整商业使用权。

## 16.7 版权与第三方素材

必须关注：生成内容合规、第三方素材授权、人物肖像使用授权、真人声音克隆授权、音乐与字体授权、作品商业使用范围、第三方模型服务商商业条款。

无授权的肖像、声音、音乐与字体素材不得进入正式交付包；授权到期需提前提醒并可阻断交付。

## 16.8 审计事件

必须审计的事件类型：登录与身份变化、角色与权限调整、项目创建/移交/归档/终止、个人凭据配置变更（仅记录元数据）、模型路由变化、任务提交/重试/取消/暂停、预算与费用修正、资产下载/删除/导出、审核结论、交付执行、数据导出。

审计记录要素：时间、操作者、对象、动作、结果、来源（IP/终端）、关联 ID。

要求：重要记录不可由普通用户修改或删除；审计检索支持按项目、员工、对象类型、时间范围、动作筛选；审计导出本身也是审计事件。

## 16.9 审核边界

- MVP 阶段不做多级会签、类型化审核角色与质量豁免通道。
- 审核权限按项目级统一审核权限授予，不按岗位类型细分。
- 审核不得被跳过：未通过终审的作品不得标记为已交付。
- 审核结论不得由系统自动生成替代。

# 第十七章 通知与异常中心

## 17.1 通知类型

待剧本审核、待最终审核、生产完成、任务失败、质量不通过、资源失效、预算提醒与超限、授权到期、项目移交、交付完成、归档完成、异常升级。

## 17.2 通知要素

每条通知必须指向具体项目、任务或资产，并包含：触发原因、影响范围、当前状态、建议动作、可执行入口、责任对象（项目负责人/资源配置人/员工）。

不允许只推送「有异常发生」这类无定位信息。

## 17.3 异常处理闭环

```text
识别异常 → 判断自动恢复规则 → 可自动处理则执行有限次数恢复
→ 更新任务与费用记录 → 无法恢复则暂停受影响链路
→ 通知项目负责人与资源配置人 → 员工作出决策
→ 恢复或终止 → 记录处理闭环
```

闭环记录必须包含：异常类型、首次发生时间、处理次数、处理动作、决策人、结果、最终状态。

## 17.4 通知渠道与升级

- 站内通知为默认渠道，支持未读标记、批量处理与跳转定位。
- 关键阻塞类通知（预算冻结、合规阻断、交付失败）建议支持邮件或企业即时通讯渠道。
- 超过阈值未处理的异常升级至项目负责人，仍未处理升级至企业管理员。
- 通知不得包含凭据、密钥、敏感业务明细或超出接收者权限的内容。

# 第十八章 交付与作品管理

## 18.1 标准交付内容

- 完整短剧成片（整剧打包或合集）。
- 分集视频文件。
- 字幕文件（含时间轴）。
- 封面图片与宣传素材。
- 项目剧本与分集大纲。
- 人物设定与视觉档案摘要。
- 生产报告、质量报告、成本报告。
- 合规与授权资料（肖像、声音、音乐、字体、模型条款）。
- 交付清单与校验摘要。

## 18.2 作品与交付状态

| 状态 | 说明 |
|---|---|
| 制作中 | 正在生产 |
| 待审核 | 已完成生产，等待最终审核 |
| 返工中 | 正在重生成问题内容 |
| 已通过 | 已通过最终审核 |
| 已交付 | 已完成正式交付 |
| 已归档 | 已完成资产归档 |

## 18.3 交付规则

1. 未通过最终审核的作品不能标记为正式交付。
2. 交付作品必须关联最终剧本版本、采用的时间线版本与正式音视频资产。
3. 交付记录保留审核结论、质量报告、成本报告与交付清单。
4. 交付前必须核对集数完整性与文件可播放性。
5. 交付包必须包含校验摘要，便于接收方验证完整性。
6. 交付后仍可创建新版本，但新版本不得覆盖历史正式交付版本。
7. 企业管理员与授权管理角色可查看企业交付情况。
8. 交付动作、下载与导出必须写审计。

## 18.4 版本与归档

- 一次交付对应一个冻结的交付版本，记录版本号、时间、交付人与接收方。
- 归档包含资产清单、报告、交付包与必要配置快照（不含凭据明文）。
- 归档后如发现质量问题，可基于历史版本新建修复版本，历史交付记录保持原样。
- 归档项目数据只读，恢复生产需显式开启新版本并记录原因。

# 第十九章 企业经营分析与产出统计

## 19.1 建设目标

企业需要准确了解：每名员工创建了多少项目、实际完成了多少短剧、完成了多少集、交付了多少作品、生产效率如何、作品质量如何、消耗了多少 AI 资源，以及企业整体产能与成本结构。

统计必须能回答「哪些是真实交付」「成本花在哪里」「质量问题集中在哪」，而不是只给总量。

## 19.2 统计维度

企业、部门、员工、项目、短剧、集、镜头、任务、模型能力、供应商、费用承担方、时间范围。

## 19.3 企业整体指标

| 指标组 | 指标 |
|---|---|
| 项目 | 项目总数、进行中、已完成、已终止、项目完成率 |
| 作品 | 完成短剧数、完成集数、交付作品数、成片总时长、视频生成总时长 |
| 质量 | 剧本审核通过率、终审通过率、镜头生成成功率、视频返工率、音频异常率、作品质量评分 |
| 效率 | 平均项目制作周期、平均单集周期、平均单集成本、单位时间完成集数、任务成功率 |
| 成本 | 企业 AI 总消耗、各项目实际成本、各员工资源消耗、单集成本、失败任务成本、预算使用率 |

## 19.4 员工个人指标

| 指标 | 业务口径 |
|---|---|
| 创建项目数 | 成功创建的项目数量 |
| 有效生产项目数 | 至少有一项真实生产任务启动的项目数量 |
| 完成项目数 | 达到项目完成条件的数量 |
| 完成短剧数 | 终审通过并交付的作品数量 |
| 完成集数 | 终审通过并交付的集数 |
| 视频生产量 | 实际生成的视频素材数量与有效时长 |
| 任务成功率 | 成功任务数 / 终态任务数（明确是否排除取消） |
| 作品通过率 | 终审通过作品比例 |
| 返工率 | 产生返工任务的镜头或集数占比 |
| 平均制作周期 | 正式生产启动到正式交付的平均时长 |
| AI 使用成本 | 员工项目实际发生的生产成本 |
| 贡献分解 | 按创建、执行、审核、交付等角色分别统计，不以最后负责人覆盖历史贡献 |

## 19.5 统计口径定义

- 生成量：真实供应商调用与实际生成并持久化的资产数量，不含失败请求与重复引用。
- 任务成功率：以终态任务为分母，取消任务是否计入需在报表中显式声明。
- 返工率：返工镜头或集数 / 已生产镜头或集数。
- 制作周期：正式生产启动至正式交付的时长，不含长期暂停时间（暂停需单独披露）。
- 实际成本：已确认供应商扣费或可核验计费金额，待核实部分单列。

## 19.6 统计规则与防失真

1. 统一区分三类数据：生产过程数据（生成量与素材）、项目完成数据（完成的生产工作）、有效交付数据（终审通过并交付）。
2. 只有达到交付标准的内容才纳入正式有效产出统计。
3. 资产复用不重复计生成量。
4. 失败调用费用不丢失，也不计入有效产出。
5. 同一交付版本不重复计数。
6. 项目移交不重写历史贡献与费用归属。
7. 测试任务与演示数据必须与正式生产分开统计，不得混入经营报表。
8. 已删除或归档项目的历史数据保留在统计快照中，避免历史数据突变。
9. 禁止通过手工修改项目状态伪造完成数量。
10. 统计结果必须可下钻到任务、调用与账单来源。

## 19.7 快照与下钻

- 关键统计指标按周期生成快照（项目数、交付作品、集数、质量、成本、失败成本），快照不可被后续状态修改回溯篡改。
- 快照支持对比，用于观察产能与质量趋势。
- 所有汇总指标支持下钻至项目、集、镜头、任务与费用记录。
- 未取得可靠数据的指标应显示为「待补充」，不得以估算值填充为确定值。

# 第二十章 员工工作台与页面功能域

## 20.1 工作台目标

为每位员工提供一个统一制作入口。员工不需要理解模型差异与专业工具，只需输入需求、确认内容、处理异常、查看结果。

工作台围绕业务流程组织，不把 AI 能力拆成大量互相独立、需要员工手动衔接的工具页。任何需要员工「导出再导入」才能推进流程的设计都属于缺陷。

## 20.2 工作台入口

| 模块 | 主要功能 |
|---|---|
| 创作项目 | 创建、查看、管理本人项目与授权项目 |
| 创意与剧本 | 创意输入、方案生成、剧本生成、编辑、版本、提交审核 |
| 导演与视觉 | 集场拆解、镜头规划、人物/场景/服装/道具资产 |
| 视频与音频 | 镜头生成监控、配音、音乐、音效、字幕、口型 |
| 后期与交付 | 时间线、剪辑、合成、质量、终审、交付 |
| 生产监控 | 生产进度、任务状态、失败与异常 |
| 素材中心 | 人物、场景、镜头、音视频资产与版本 |
| 个人模型资源 | 供应商、凭据、模型能力、路由、测试、调用记录 |
| 个人统计 | 项目、集数、质量、效率、成本 |

## 20.3 工作台信息展示

必须展示：项目总览、当前制作阶段、已完成集数与比例、生产任务进度、待审核事项、生产异常、AI 生成消耗、预算使用情况、最近生成素材、最近交付作品、个人资源可用状态。

## 20.4 指令式生产助手

工作台提供一个指令入口，支持员工用自然语言发起操作，例如：

- 创建一部 60 集都市情感短剧。
- 根据当前创意生成完整剧本。
- 检查当前剧本的人物与剧情逻辑。
- 按剧本开始自动制作。
- 检查人物视觉一致性。
- 重新生成第 8 集不合格镜头。
- 优化第 10 集剧情节奏。
- 暂停当前视频生产。
- 检查整部短剧的音视频质量。
- 把审核通过的内容整理成交付包。

实现边界：

1. 指令解析结果是**结构化业务动作**（对象 + 动作 + 参数），不是自主任务编排。
2. 执行前必须识别操作目标、影响范围与风险，并向员工回显将要执行的动作。
3. 高风险操作必须二次确认：预算超限、正式剧本重大变更、删除已确认资产、批量返工、项目终止、交付执行。
4. 无法唯一确定目标时必须追问，不得凭猜测执行。
5. 指令执行同样受权限、项目授权、状态机与预算规则约束，不因「自然语言」而绕过校验。
6. 本能力属于交互入口，不构成 Agent 架构。

## 20.5 页面功能域清单

1. **企业工作台**：企业项目总览、员工产出、待处理事项、质量与成本汇总。
2. **组织与权限**：企业主体、部门、员工、角色、权限、项目成员授权、离职与移交。
3. **项目中心**：项目列表、创建、详情、生命周期、成员、归档。
4. **员工制作工作台**：项目任务、创作入口、阶段进度、待审核、异常。
5. **创意与剧本**：多方式创意输入、方案生成、剧本生成、编辑、版本、审核。
6. **导演与视觉**：剧本拆解、集场、镜头、人物、场景、服装、道具。
7. **视频与音频**：镜头生成、对白、配音、音乐、音效、字幕、口型。
8. **后期与交付**：时间线、剪辑、合成、质量、终审、交付。
9. **个人模型资源**：供应商、凭据、模型能力、路由、测试、调用记录。
10. **生产任务中心**：计划、依赖、队列、任务详情、重试、取消、异常。
11. **数字资产中心**：分类检索、详情、版本、授权、引用、归档。
12. **用量与成本中心**：用量、预计/实际成本、预算、费用承担方。
13. **企业经营分析**：企业、部门、员工、项目、作品、质量、效率、成本分析。
14. **合规与审计**：授权台账、风险记录、审计检索与导出。
15. **系统设置**：基础设施、存储、任务队列、服务健康、数据保留。

## 20.6 三端页面分工

**平台管理端（系统层）：** 平台总览、企业主体视图、平台用户与身份、平台资源与队列、模型能力字典、平台生产与成本统计、平台业务配置、系统健康与备份。

**企业管理端：** 企业工作台、企业信息、部门管理、员工管理、角色与权限、项目中心、项目详情、产出统计、绩效与贡献统计、成本统计、资源配置、项目移交、资产管理、合规审计。

**员工工作台：** 个人工作台、指令入口、我的项目、创意与剧本、导演与视觉、视频与音频、后期与交付、内容审核、生产监控、素材资产、个人统计、个人模型资源。

## 20.7 页面设计原则

- 以业务流程为主线，不用能力清单替代流程。
- 关键决策点必须能看到依据（版本、质量报告、成本），不能只给「通过/不通过」。
- 状态展示必须来自真实状态字段，不得用前端文案模拟。
- 任何「已完成」标记必须有对应业务记录与验收证据。
- 未实现能力必须显式标注，不得以占位页面冒充完成。

# 第二十一章 平台管理与系统设置

## 21.1 平台管理端

包括：平台总览（企业主体、成员规模、生产与成本概况）、平台用户与身份、平台资源与任务队列视图、模型能力字典、供应商适配器注册、平台生产统计、平台成本统计、平台业务配置（默认预算、集数上限、重试上限、并发上限、提醒阈值、数据保留期、模型白名单）。

平台管理与企业管理的边界：

- 平台管理层负责基础设施与全局参数，不介入具体项目内容。
- 企业管理员负责企业内组织、账号、制度与经营视图。
- 平台运维配置不得包含员工个人凭据，也不得成为绕过企业权限的通道。

## 21.2 系统设置与基础设施

包括：企业基础设置、账号与认证安全、文件存储、任务队列、供应商适配器注册、模型能力字典、日志、监控、备份与恢复、数据保留策略。

要求：

- 系统运维配置与员工个人 AI 凭据域隔离。
- 供应商适配器只提供统一调用接口，不得把供应商凭据变成企业公共资源。
- 存储与队列的健康状态可观测；队列积压、失败率、重试率、供应商延迟、磁盘容量纳入监控。
- 备份覆盖数据库、媒体存储与必要配置；密钥恢复材料单独保管。

## 21.3 能力字典与适配器治理

- 模型能力字典统一定义能力类别、输入输出模式、限制与计费单位，供模型声明与任务匹配使用。
- 适配器按能力契约实现，业务模块不直接依赖供应商 SDK。
- 新增能力或适配器必须登记能力、限制、授权与计费方式，未登记能力不得被任务引用。
- 适配器异常必须返回明确错误码，不得静默降级到其他实现。

## 21.4 数据保留与归档策略

- 明确业务数据、资产文件、日志、审计记录与临时素材的保留期。
- 临时素材可设置较短保留期并自动清理，正式资产与交付记录按业务要求长期保留。
- 审计记录保留期不得短于业务追溯要求。
- 清理任务必须可审计，不得清理仍被引用的对象。

# 第二十二章 数据管理、追溯与隔离

## 22.1 数据归属结构

```text
平台
  └── 企业
       ├── 部门（可选层级）
       ├── 企业成员
       ├── 企业项目
       │    ├── 创意 brief 与故事设定
       │    ├── 剧本版本
       │    ├── 人物、场景、服装、道具
       │    ├── 镜头生产单元
       │    ├── 生产任务与调用记录
       │    ├── 音视频资产与时间线
       │    ├── 审核与质量报告
       │    └── 最终交付
       ├── 企业资源配置与预算
       ├── 用量与费用记录
       ├── 审计事件
       └── 企业统计与快照
```

## 22.2 生产数据追溯字段

每项生产任务必须可追溯：所属企业、所属部门、所属员工（执行人）、资源配置人、所属项目、所属集、所属场、所属镜头、使用的模型能力、模型配置、供应商任务 ID、输入资产版本、输出资产版本、执行状态、执行时间、实际成本、质量结果、重试记录。

要求：追溯字段在数据模型中落表，不能只存在于日志文本；日志用于辅助定位，不作为唯一追溯依据。

## 22.3 统计准确性要求

必须统一项目、集数、镜头、交付作品与成本的统计口径，避免：

- 同一作品重复统计。
- 失败生成任务被计入正式交付。
- 已删除或归档项目造成历史数据缺失。
- 员工移交导致产出记录错误归属。
- 通过修改项目状态伪造完成数量。
- 演示或测试数据混入经营报表。

历史数据应保留原始业务记录与必要的统计快照。

## 22.4 数据隔离边界

1. 企业是最高隔离边界；跨企业数据不共享、不检索、不导出。
2. 项目是业务隔离与授权边界；非项目成员不得读取项目内任何业务对象。
3. 部门是管理视图维度，不是隔离主键；部门间跨项目访问需授权。
4. 个人凭据是独立安全域，任何业务角色与业务权限均不能读取明文。
5. 导出、下载与批量查询必须校验范围并留审计。
6. 未授权访问返回明确拒绝原因，不泄露对象是否存在之外的敏感信息。

# 第二十三章 实施阶段规划

实施顺序围绕业务闭环建设，不以「页面做完」或「单次模型调用成功」作为阶段完成标志。

| 阶段 | 建设内容 | 阶段目标（DoD） |
|---|---|---|
| R1 企业身份、组织与项目基础 | 企业内部账号、部门与组织、RBAC 与权限码、项目与成员授权、个人供应商配置基础、凭据加密、创意输入、创意方案生成、剧本生成、剧本版本、人工剧本审核、基础审计与费用记录骨架 | 企业可建部门与员工，员工可独立建项目并完成创意、剧本生成与审核锁定；任务、资产、调用、费用、审计基础数据从 R1 即建立，不推迟到后期 |
| R2 导演规划与视觉资产 | 剧本拆解、集场结构、镜头生产单元与镜头契约、分镜生成、人物/场景/服装/道具资产、资产版本、一致性检查 | 正式剧本可自动转换为结构化镜头计划，并形成可复用、可校验版本的视觉资产 |
| R3 视频与音频生产 | 个人/企业模型路由、视频任务、参考图约束、配音、音乐、音效、字幕、口型、任务依赖、真实回执、文件回收、质量检测、成本统计 | AI 可按镜头计划稳定产出合格视频与音频素材，供应商成功到资产可用全链路可核验 |
| R4 后期、终审与交付 | 时间线、自动剪辑、混音、字幕合成、分集输出、整剧输出、质量报告、人工终审、交付包、资产归档 | 员工可完成分集制作、终审与正式交付，交付包可校验、可追溯 |
| R5 自动化、成本与经营分析完善 | 任务自动调度与衔接、失败恢复、备用模型兼容检查、预算规则与超限暂停、实际成本核算、预算冻结、企业统计、员工贡献分析、快照、全链路审计完善 | 形成稳定、可监控、可恢复、可统计、可审计的企业级生产体系 |

阶段约束：

- 后续阶段不得以「先做页面后面补数据」方式跳过业务对象、状态、版本、成本归属与审计设计。
- 每个阶段必须有可运行的端到端链路与可验证证据，不以设计文档、原型截图或演示数据作为阶段完成依据。
- 阶段之间允许并行开发，但依赖关系与数据契约必须先确定。

# 第二十四章 验收标准

## 24.1 组织与权限验收

- 可创建唯一企业主体并维护基础信息。
- 可创建部门、调整层级、配置负责人、停用与归档。
- 可添加多个员工，分配角色，启用与禁用账号。
- 员工可独立登录，且只能访问本人或明确授权的项目。
- 部门间与项目间默认隔离，跨范围访问必须授权并留审计。
- 企业管理员可查看企业项目、产出与成本汇总。
- 员工离职后可完成项目移交，数据不删除、归属不丢失。
- 企业统计数据与实际业务记录一致，可下钻验证。

## 24.2 独立制作验收

必须验证单个员工能够独立完成：创建项目 → 输入创意 → 生成创意方案 → 生成剧本 → 剧本审核 → 分镜与镜头规划 → 人物与场景视觉 → 视频镜头生成 → 配音配乐音效 → 字幕与口型 → 自动剪辑合成 → 质量检测 → 终审 → 交付。

不能依赖其他员工或人工专业制作人员完成上述任一步骤。

## 24.3 资源与凭据验收

- 员工可独立配置并测试自己的供应商与模型。
- 管理员无法读取任何个人 API Key 明文，界面仅显示脱敏信息。
- 凭据更新后新任务使用新配置，历史任务保留引用标识且不回显密钥。
- 配置失效时任务暂停并通知配置人，不静默改用他人凭据。
- 企业托管模式下配额与用量可追溯到员工与项目。

## 24.4 生产与自动化验收

- 生产任务可自动衔接，具备明确状态与迁移记录。
- 失败任务可按类型自动重试，达上限转人工处理。
- 备用模型可按规定切换，切换前完成兼容性校验。
- 不合格镜头可局部重生成，已合格资产可复用。
- 剧本修改可识别受影响镜头、音频与时间线并生成清单。
- 预算超限可暂停受影响任务，预算冻结生效。
- 生产异常可通知到人并形成闭环记录。
- 任务失败不会被伪装为成功。
- 供应商成功、文件下载、资产持久化、质量通过四项分别可验收。

## 24.5 交付与资产验收

- 交付作品关联最终剧本版本、采用的时间线版本与正式资产。
- 交付包内容完整、可校验、可播放，集数完整。
- 交付后新版本不覆盖历史正式交付记录。
- 资产版本、来源、授权、引用关系可追溯。
- 删除被引用资产前的引用检查生效。

## 24.6 成本与经营验收

- 企业可查看项目总数、完成短剧数、完成集数、交付作品、成片总时长。
- 企业可查看员工个人产出，并可区分创建、执行、审核、交付贡献。
- 企业可比较员工与部门的生产效率与质量。
- 企业可查看 AI 成本、失败成本、单集成本与预算使用率。
- 预计成本与实际成本分栏展示，待核实项单独标记。
- 失败、取消与重试费用均有记录。
- 统计结果可追溯到原始任务、调用与账单。

## 24.7 合规与审计验收

- 授权台账覆盖肖像、声音、音乐、字体、第三方素材与模型条款。
- 无授权素材无法进入正式交付包。
- 审计覆盖权限调整、项目移交、凭据变更、任务操作、费用修正、审核结论、交付与导出。
- 审计记录包含时间、操作者、对象、动作、结果与关联 ID，普通用户不可篡改。

## 24.8 端到端验收

```text
创建企业 → 创建部门与员工账号 → 员工登录
→ 配置个人模型资源并测试 → 创建短剧项目 → 输入创意
→ AI 生成创意方案与剧本 → 人工剧本审核 → 锁定正式版本
→ AI 视觉与分镜 → AI 视频生产 → AI 配音配乐字幕口型
→ AI 后期合成 → AI 质量检测 → 人工最终审核
→ AI 生成交付包 → 资产归档
→ 企业查看员工产出 → 企业统计项目、作品、质量与成本
```

只有完成完整业务链路，且各阶段具备真实可用生产能力，才能认定达到相应验收标准。

## 24.9 真实性红线

不得使用静态占位、预设假数据、虚构任务状态、模拟供应商回执、伪造成本或人工代做来冒充 AI 自动生产能力。以下行为一律视为未通过验收：

1. 用前端固定文案模拟状态流转。
2. 用演示数据充当真实生成结果。
3. 把模型请求成功当作资产已成功。
4. 把未实现能力标记为已完成。
5. 用人工制作内容冒充 AI 产出。
6. 修改统计数据以匹配预期指标。

# 第二十五章 核心业务决策

1. **产品模式**：单一企业内部私有化部署 + 部门组织承载 + 员工单人独立制作 + AI 全流程生产。不做 SaaS 多租户与平台商业运营。
2. **组织模式**：企业按部门、事业部、制作中心或项目团队组织人员；部门用于组织归属与管理视图，不作为数据隔离租户。企业可以管理员工与组织，但不按传统影视专业岗位组织短剧制作。
3. **生产模式**：员工是独立操作者与决策者，AI 是实际生产执行主体；镜头是最小生产单元，项目是授权与协作边界。
4. **人工参与**：仅四个介入点 —— 创意方向输入、剧本内容与合规审核、最终成片审核、必要异常决策；不要求人工执行专业制作任务。
5. **资源归属**：支持企业托管与员工自持两种资源供给模式；个人凭据加密保存、明文不可读、不可共享、不随项目转移。
6. **自动化实现**：以业务域、业务对象、状态机、依赖图与规则调度实现自动化，不引入智能体架构与 Skill 体系。
7. **成本原则**：预计与实际分开，失败与重试必记，费用归属到人、到项目、到任务，费用来源区分承担方式。
8. **统计原则**：严格区分生成过程数据、项目完成数据与有效交付数据，只有终审通过并交付的内容计入正式产出。
9. **真实性原则**：状态、回执、资产、成本、统计必须来自真实业务记录；不得以演示、模拟或人工代做替代。
10. **演进原则**：任何后续调整不得重新引入传统岗位依赖、不得把单人流程拆成必须多人协作、不得把 AI 能力做成互不相干的工具集、不得混淆管理与制作权限、不得让人员变动造成数据丢失。

# 附录 A 版本合并与冲突处理说明

本附录记录 V1.0 与 V2 的差异项及 V3 的裁决依据，便于评审与追溯。此后以 V3 为唯一生效版本，前两版不再作为操作入口。

| 序号 | 差异点 | V1.0 主张 | V2 主张 | V3 处理与理由 |
|---|---|---|---|---|
| 1 | 组织隔离单元 | 企业内部「租户空间」，含租户管理员、租户配额、租户预算、租户间隔离 | 部门/团队组织单元，明确「不是 SaaS 租户」 | 采用部门模型，取消「租户」业务实体。理由：企业内部门本身不具备独立计费、独立开通、独立部署特性；同时项目基线明确不使用 tenant 维度做权限注入。V1 的隔离与配额要求改为「项目隔离 + 部门配额 + 企业策略」表达，能力不丢失 |
| 2 | AI 资源归属 | AI 能力由企业统一接入和治理，按租户配额与权限分配 | 员工自主维护供应商、API Key、模型与路由；企业不得读取明文 | 采用双模式并存：企业托管模式（保留 V1 的统一接入、配额、结算）与个人自持模式（保留 V2 的个人凭据与路由）。两者共享同一条安全底线：凭据加密、明文不可读、不可共享、不随项目转移 |
| 3 | 调度主体 | 「AI 项目统筹与生产调度中心」具备识别目标、拆解任务、规划顺序、评估成本等自主能力 | 以任务状态机、依赖图与规则调度实现，不引入 Agent | 采用规则驱动调度，职能清单完整保留（依赖识别、并行规划、重试、备用模型、预算控制、报告），但表述为确定性规则与状态机，不使用智能体、自主决策等表述。理由：V2 明确排除 Agent 架构，且自主编排无法满足可审计与可复现要求 |
| 4 | 项目状态 | 12 状态，「已完成」= 审核通过并完成交付 | 状态链含创意策划、剧本创作，交付与归档单列 | 合并为 12 个主流程状态 + 3 个干涉状态，拆出「已完成 / 已交付 / 已归档」，补充质量检测自动进出与终止原因结构化 |
| 5 | 角色体系 | 平台运维、企业级管理员、租户管理员、审计经营管理、普通员工 | 系统运维、企业管理员、企业管理人员、项目负责人、普通员工、审计人员 | 合并为六角色：系统运维管理员、企业管理员、部门管理员、项目负责人、普通员工、审计与经营管理。以部门管理员承接原租户管理员职责，新增项目负责人承接 V2 的项目级职责 |
| 6 | 创意输入 | 仅在流程中列出题材、方向、受众等输入项 | 七种结构化输入方式 + 校验与异常规则 | 保留 V2 的七种方式与校验规则，并纳入 V1 的创作要素（题材、方向、受众、集数、时长、风格）作为项目属性 |
| 7 | 质量体系 | 十维检测 + 四级质量 | 四级检测层级 + 结果分级 | 以「层级 × 维度」矩阵整合：十维不丢，四级不丢，并增加 PASS / REVIEW_REQUIRED / FAIL 门禁与报告绑定版本规则 |
| 8 | 成本口径 | 成本维度九项 + 十条控制规则 | 计量单位、费用承担方、费用来源、预计与实际分离 | 合并：九项成本维度全保留，增加费用承担方与来源、待核实标记、账单依据；控制规则合并为十条并新增预算冻结状态 |
| 9 | 审核结果表述 | 剧本：通过/退回/终止；成片：通过/指定返工/调整要求/终止 | 剧本：通过/退回/终止；成片：通过交付/指定返工/退回后期/终止交付 | 采用 V2 表述（更精确区分返工层级），保留 V1「调整制作要求」作为退回后的可选动作 |
| 10 | 资产分类 | 六类（剧本、人物、场景、视频、音频、成片） | 更细粒度（含创意 brief、服装、道具、时间线、质量报告、交付包） | 合并为八类，覆盖两版全部资产形态，并明确正式资产与临时素材分级 |
| 11 | 模型能力分类 | 十类 | 十六类（增图像编辑、视频编辑、音效、数字人、视觉理解、审核、转码） | 采用十六类能力字典，V1 十类全部映射其中 |
| 12 | 统计指标 | 企业四组 + 员工十一项 + 分析维度 + 三类数据区分 | 指标口径定义 + 贡献分解 + 统计规则 | 全部保留：指标合并为企业五组与员工十二项（新增贡献分解），口径定义与防失真规则合并为十条 |
| 13 | 页面规划 | 平台端 8、企业端 12、员工端 14 | 15 个功能域 | 以 15 功能域为主结构，三端页面清单作为视图分工保留 |
| 14 | 文档管理 | 需维护十类文档 + 八条原则 | PRD 十二项描述模板 | 合并为第二十六章文档表、26.3 模板与 26.4 原则，三者在同一章内互为补充 |
| 15 | 实施阶段 | R1–R5 按能力中心划分 | R1–R5 按业务域划分，强调基础数据不可推迟 | 采用 V2 的阶段划分与 DoD 要求，保留 V1 各阶段的全部建设内容，补齐「基础数据从 R1 建立」的约束 |
| 16 | 工作台助手 | 自然语言生产助手 | 未涉及（且排除 Agent 架构） | 保留为「指令式生产助手」，明确其为结构化动作解析与确认执行，不构成 Agent，并增加二次确认与权限约束 |

- V1 的 22 章内容全部有对应落点：概述、架构、组织、制作模式、八大能力、流程、生产规则、工作台、项目管理、产出统计、资产、模型、质量与成本、审核合规、交付、数据管理、页面规划、产品边界、实施阶段、验收、核心决策、文档管理。

| 有效交付数据 | 终审通过并完成正式交付的作品与集数，计入正式产出 |

| 个人自持模式 | 由员工本人配置并维护模型资源与凭据的供给模式 |
| 审计事件 | 对关键业务与安全动作的不可篡改记录 |
