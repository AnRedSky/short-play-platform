# 从静态原型到真实业务开发：前置条件与快速迁移方案

版本：2026-11-25 ｜ 对象：`prototype/v9`（9.7.8，56 路由 / 17 域 / 329 动作）→ 真实可交付系统

## 一、结论

1. **可迁，且成本低于预期。** 这个仓库不是"原型 + 空地"。后端已经是真实骨架：`src/app/domains` 11 个域、39 个 SQLAlchemy 模型、40 张表（7 个 Alembic 迁移）、73 个 REST 端点、Celery worker/beat、Outbox 事件、工作流引擎（definition/version/run/node_run/checkpoint）、RBAC（role/permission/grant）、审计日志、生成任务与用量记录。
2. **真实缺口是可量化的：9 个业务域的后端 + 46 个页面的前端 + 一层契约对齐。** 前端目前是"带鉴权的壳"：`web/src/router` 仅 10 条路由、16 个 view，除 `ProductionModule.vue`（40.6KB 单文件）外多数页面 <10KB。
3. **原型不该被"改造上线"，应被当作契约源与验收基准。** 它把 15 个项目状态、8 个阶段、36 个权限码、60 个实体的字段口径、329 个动作的跳转/弹窗承载都写死了——这是最贵的资产；而它的运行形态（`DB.state` 内存态、无鉴权、无持久化、无并发）完全不能上线。
4. **排期与人力：6 人 10–12 周可达"可交付 MVP"**（单人能从头到尾跑完一部短剧）；17 域全量约 16–18 周。

## 二、三方家底对照

| 维度 | 原型 `prototype/v9` | 真实后端 `src/app` | 真实前端 `web/src` |
| --- | --- | --- | --- |
| 规模 | 322 文件 / 12MB | 235 个 .py / 39 模型 / 40 表 | 16 个 .vue / 10 条路由 |
| 组织 | 17 域 / 6 一级菜单 | 11 域（含 health） | 10 模块 |
| 交互 | 56 路由 / 329 动作 / 6 身份 | 73 端点 | 路由级页面稀薄 |
| 数据 | 60 个实体数组 / ~700 字段 / 36 权限码 | Postgres + Alembic | mock.ts（5KB） |
| 状态 | 15 项目状态 + 8 阶段 + 门禁 | 工作流引擎 + 幂等键 | 无业务状态 |
| 任务 | 内存 job 面板（同步假进度） | Celery + Outbox + UsageRecord | 无 |
| 结论 | 需求与口径的**事实标准** | 可用的**地基** | 需**重铺** |

## 四、真实业务开发需要具备的条件

### 4.1 业务口径（不冻结就无法并行开发）

1. **状态机唯一真相**：15 个状态 + 8 个阶段 + 每个关卡（通过/退回/终审/交付）的准入条件与责任人。原型已给出，需转成后端 `workflow definition` 版本化 JSON，禁止前后端各写一份。
2. **成本口径**：按"镜头/任务/重试/模型"哪一级计费、预算超限是硬拦还是告警、重试是否重复计费。
3. **质量口径**：4 档质量 × 10 项矩阵的判定规则，谁签字，返工如何回到上游。
4. **权限口径**：36 个权限码与 6 个身份的映射，项目级 vs 组织级边界。
5. **交付口径**：交付物清单 9 项、成品验收标准、渠道规格（分辨率/时长/字幕/审核）。
6. **审核口径**：AI 生成内容的人工复核节点与留痕要求。

### 4.2 内容与版权（最容易在上线前卡死）

- 小说/剧本改编授权链（原文授权 → 改编权 → 衍生形象），逐项目存档。
- 人物形象与声音：真人肖像、声音克隆需单独授权书；AI 生成形象需可追溯的生成记录。
- 音乐/音效/BGM 商用授权与到期管理（原型 `rights` 只有 6 条样例，需真实台账）。
- 素材入库时的授权字段强制校验（后端 `assets` 域加 `rights_status`）。

### 4.3 AI 供给侧

- 模型清单与能力矩阵：文生视频/图生视频/配音/口型/超分/字幕，每项要有可替代供应商（原型 `providers 8 / capabilities 16` 即为此）。
- 配额与并发：单项目并发任务上限、账号级 RPM/日额度、排队策略。
- 成本可控：单集成本上限、模型单价版本、预算告警阈值。
- 降级路径：主模型不可用 → 备选模型 → 降质量档 → 挂起并通知，四级别明确。
- 长任务可靠性：任务幂等键（project+shot+attempt）、断点续跑、超时回收、失败原因码。

### 4.4 合规

- 生成内容标识（显式水印 + 元数据隐式标识）；深度合成服务备案与用户实名。
- 个人信息：声纹/人脸的单独同意、保留期与删除通道。
- 审计不可篡改：所有写操作经 `audit` 域落库，交付包附校验和。
- 数据分级：素材/成片/成本/身份数据的访问边界与导出管控。

### 4.5 团队与基础设施

- 角色配置（6 人起）：后端 2、前端 2、产品/业务口径 1、测试/验收 1；AI 工程 1 人可兼后端。
- 环境：Postgres 16 + Redis + Celery + MinIO/S3 + 反向代理；私有化部署需 GPU 推理节点或外部 API 出口。
- 观测：结构化日志、任务耗时/失败率、成本日报、告警通道（原型 `notify/incidents` 对应）。
- 发布：main/develop 保护 + Conventional Commits + CI 四门禁（backend/frontend/e2e/compose）+ 迁移回滚脚本。

### 4.6 必须先拍板的 10 个决策

| # | 决策 | 当前默认 | 影响 |
| --- | --- | --- | --- |
| 1 | 部署形态：SaaS 多租户 / 私有化单租户 | 代码按组织多租户建模 | 影响计费、隔离、运维 |
| 2 | 模型来源：自建推理 / 第三方 API / 混合 | 未定 | 影响成本与合规 |
| 3 | 成本是否硬拦（预算耗尽即停） | 原型为告警 | 影响业务可行性 |
| 4 | 审核责任人：客户方 / 平台方 | 未定 | 影响流程与法务 |
| 5 | 是否开放外部创作者（UGC） | 未定 | 影响审核与风控成本 |
| 6 | 成片分发渠道（自有 / 平台代投） | 未定 | 影响交付规格 |
| 7 | 数据保留期与删除承诺 | 未定 | 合规必答 |
| 8 | 并发规模目标（同时在线项目/任务） | 未定 | 影响队列与容量 |
| 9 | 单集时长/镜头数上限 | 原型样例 ~分钟级 | 影响成本模型 |
| 10 | 是否保留"演示数据"模式 | 原型 7 项目样例 | 影响种子与演示 |

## 五、三条迁移路线对比

| 方案 | 做法 | 判断 |
| --- | --- | --- |
| A 照页面重写 | 以原型 56 页为设计稿，前后端从零按页实现 | 慢（20 周+），口径会在重写中丢失，返工多 |
| B 原型直接改造上线 | 在 `prototype/v9` 上加真实接口 | 不可行：内存态 60 实体、无鉴权、无持久化、无并发、无迁移 |
| **C 契约先行 + 影子并行（推荐）** | 原型产出机器可读契约；后端按域补齐；前端复用原型视觉与交互，逐域从 mock 切真；原型持续作为验收基准 | 最快且可控：口径不丢、可并行、每域可独立验收 |

**为什么 C 最快**：原型已经把"做什么、什么顺序、什么条件、什么权限"全部写死，团队不需要再讨论需求，只需要把口径**机械地**翻译成 schema + 状态机 + 组件。真正的工作量是搬砖，不是设计。

## 六、推荐路线：S0–S4

| 阶段 | 周期 | 交付物 | 验收 |
| --- | --- | --- | --- |
| **S0 契约冻结** | 1 周 | `contract.json`（56 路由 / 329 动作 / 36 权限 / 15 状态 / 8 阶段 / 60 实体字段）；OpenAPI 对齐清单；parity 测试骨架 | 三方（原型/OpenAPI/前端路由）逐项差异为 0 或白名单 |
| **S1 数据与状态机落地** | 2 周 | 迁移 `0008–0012`（新增 9 域约 20 张表）；workflow definition JSON seed（状态×阶段×门禁）；幂等键；7 项目种子数据 | 状态机单测覆盖 15 状态全部迁移；重复提交不产生重复任务 |
| **S2 后端补域** | 4 周（2 人并行） | audio / post(timeline,delivery) / quality / cost / models(provider,capability) / notify / compliance(rights,risks) / analytics / ops 的 model+service+router+测试 | 每域 OpenAPI 与 contract 一致；单域 e2e 通过 |
| **S3 前端铺页 + 逐域切真** | 3 周 | 原型 `U.*` 渲染器 → 12 个基础 Vue 组件；46 页路由；Pinia + 查询层；`VITE_DATA_MODE=mock\|real` 灰度开关 | 每页与原型的动作数、权限显隐、空态一致 |
| **S4 验收与上线** | 2 周 | 原型 20+ 审计脚本转 contract tests；40 条 e2e 迁移；并发/成本/降级压测；私有化部署包 + 运维手册 | 真实账号跑完一部剧全流程；成本台账与预算一致 |

**关键依赖顺序**：S0 不完成不启 S2（否则 9 个域会各写一套口径）；S1 的状态机必须先于 S2 的任何关卡动作。

## 七、本周就能做的 5 件事

1. **导出契约**（1–2 天）：写 `tools/export_contract.mjs`，从原型模块直接抽取路由、动作、承载方式（跳转/弹窗/抽屉/状态）、权限、状态机，产出 `contract.json`。
2. **冻结状态机**（2 天）：15 状态 × 8 阶段 × 门禁 → `workflow_definition.json`，接进现有 `workflow` 域的 definition/version 表。
3. **补 3 张最关键的缺失表**（2 天）：`budget`、`quality_report`、`delivery`——它们卡住 S2 的三个域。
4. **拆前端单文件**（3 天）：把 `ProductionModule.vue`（40.6KB）按域拆成路由级页面，先让 56 路由有骨架映射。
5. **加 contract-parity 到 CI**（1 天）：原型 路由/动作 ↔ OpenAPI ↔ 前端路由三方比对，差异即红灯。

## 九、风险与陷阱

1. **双写状态机**：前端也判关卡、后端也判 → 必然不一致。只允许后端判，前端只读 `status/allowed_actions`。
2. **成本重复计费**：重试与超时回收各记一次。幂等键必须含 `attempt`，用量以 provider 回执为准。
3. **长任务中断**：视频生成 10 分钟级，必须可续跑；不能把进度放在前端内存。
4. **演示数据污染**：7 个样例项目要作为 seed 明确标记 `is_demo`，否则进生产库。
5. **素材版权缺失**：入库不校验授权 → 上线后无法追溯，法务风险最高。
6. **模型不可用无降级**：单供应商 = 单点。
7. **权限语义漂移**：36 个权限码在原型是字符串，后端必须枚举化并与路由 guard 一一对应。
8. **原型视觉直接搬**：原型是三列密集信息布局，搬到真数据后长列表会溢出，需先用真实量级回归。
9. **迁移顺序错**：先做 analytics/ops 这类"好看但非闭环"的域，会挤占 MVP 时间。
10. **CI 只跑原型**：`prototype-quality` 与后端门禁分离，contract-parity 必须两边都卡。

## 十、MVP 砍单（先不做）

组织/权限后台细化、经营分析（analytics）、平台管理（ops）、预算规则引擎（budgetRules 37 字段）、多渠道分发、多语言。

**MVP 保底范围**：立项 → 创意 → 剧本 → 分镜/镜头 → 视频生成 → 配音/字幕 → 剪辑时间线 → 质检返工 → 交付，共约 24 页、9 域、单租户、单模型 + 1 备选。

## 十一、验收口径（DoD）

- 真实账号、真实数据库，从新建项目跑完整部剧到交付包下载，全程无 mock。
- 每个关卡动作在后端有审计记录，在 UI 有 `allowed_actions` 驱动而非硬编码。
- 任务失败可重试、可续跑、成本台账与 provider 用量对账误差为 0。
- contract-parity、后端单测、前端 e2e、compose 启动四门禁全绿。
