# 全局布局框架实现说明

面向：后续要在这个外壳上继续开发业务模块的前后端同学。
范围：`web/src` 内的全局外壳、暗色主题、基础组件与四个一级入口页面。业务页面的路由与数据结构未改动。

## 二、八条规范的落地与验收证据

**1. 左侧固定 + 右侧自适应**

侧栏使用 `position: fixed; inset: 0 auto 0 0; width: var(--nav-width)`；主内容用 `margin-left: var(--nav-current)`。侧栏不参与文档流，因此主内容滚动时它不动。
实测（1440×900，主内容已滚动 539px）：侧栏 `top=0`、`bottom=900`、`width=240`，即贴顶且保持满屏高。

**2. 全局暗色主题**

`theme.dark.css` 最后导入，定义 `--ds-*` 一组语义令牌，并把旧页面仍在用的 legacy 变量（`--bg/--surface/--ink/--line/--accent` 等）全部指向同一套色值，因此 50 多条既有业务路由切换过来后不需要逐个改色即落到暗色。对比度按 WCAG 2.1 相对亮度公式逐个核算，数值写在文件头注释里，并由 `tests/unit/theme-contrast.test.ts` 在每次测试时回归。

正文 #e9edf3 / 卡片 #12161d = 15.43:1（AAA）
次要 #aab4c2 / 卡片 = 8.65:1（AAA）
辅助 #8d97a4 / 卡片 = 6.13:1（AA）
禁用文字 #737d8b / 输入底 #1e242e = 3.74:1（禁用控件 WCAG 豁免，此处仍按 3:1 兜底）
控件边框 #646f7d / 卡片 = 3.55:1（非文本对比度 1.4.11 达标）
主交互 #f0a35e / 卡片 = 8.73:1，按钮上的深字 #14100a / #f0a35e = 9.12:1
焦点环 #f0a35e / 页面底 = 9.30:1
状态：成功 #5ed6a4 = 10.04:1、警告 #ecc46a = 10.94:1、危险 #ff8f8f = 8.27:1、信息 #8fb8ff = 9.04:1

说明一处刻意的取舍：`--ds-border` #2a313c 对卡片仅 1.38:1，定位是纯装饰性分割线；凡需要被看见的控件边界与选中描边都用 `--ds-border-strong` #646f7d（3.55:1），所以“看得见的边界”都满足 3:1。

**3. 卡片式内容容器**

统一使用 `.card`（全局）或 `AppCard`（组件）。卡片间距走 `--space-*`：页面区块之间 24px，卡片内部 16px，紧凑区块 8px；圆角 `--radius-m: 8px`，大面板 `--radius-l: 12px`，输入与标签 `--radius-s: 6px`。主内容区通过 `.app-content` 统一施加 `max-width: var(--content-max)`（1600px）与 `padding: var(--space-3) var(--page-gutter) var(--space-6)`，因此新页面不需要自己写外边距。

**4. 模块化与样式隔离**

外壳、基础组件、页面三层分离：布局只管骨架与路由，基础组件只管观感与插槽，页面只管数据与文案。`src/layouts/` 与 `src/components/ds/` 下 8 个单文件组件全部使用 `<style scoped>`，跨组件只通过 `--ds-*` 令牌通信，没有互相穿透的选择器；全局样式只存在于 `src/styles/` 下的 6 个样式表。

**5. 响应式与小屏抽屉**

断点 1024px（`matchMedia` 监听 + 媒体查询双通道）。桌面 240px；1024px 以下侧栏 `transform: translateX(-102%)` 隐藏、宽度 `min(280px, 82vw)`，点顶栏汉堡滑入并加 `--shadow-3`，同时铺一层可点击的 `.nav-backdrop`（背景模糊）、锁 `body` 滚动、Esc 可关闭；主内容 `margin-left: 0` 占满宽度。
实测（390×844）：默认 `x=-285.6 / width=280`；点汉堡后 `x=0 / width=280`；点遮罩后回到 `x=-285.6`。

**6. 折叠/展开交互**

侧栏折叠按钮在品牌区右侧，折叠后宽度 240 → 72px，仅保留图标（`title` 提供可读名称），品牌文字与菜单文字以透明度收起；`width / transform / margin-left / box-shadow` 统一走 `--motion-nav: 300ms`、`--ease-out: cubic-bezier(0.22, 0.61, 0.36, 1)`。折叠状态写入 `localStorage`，下次进入保持。
实测：折叠前 240、折叠后 72，主内容左偏移同步变为 72。

**7. 8px 间距与三级阴影**

间距：`--space-half: 4px`（仅用于图标与文字的贴合间距），`--space-1..8 = 8 / 16 / 24 / 32 / 40 / 48 / 56 / 64`。阴影：`--shadow-1` 静态卡片、`--shadow-2` 悬浮（下拉、提示、hover 卡片）、`--shadow-3` 抽屉与弹窗。三级各只有一处定义，页面不自造阴影。

**8. 可直接作为基础框架**

新增页面只需三步：在 `src/router/index.ts` 加路由 → 页面内部用 `AppPage` + `AppCard` + `AppButton` 组织 → 颜色与间距全部取 `--ds-*` / `--space-*`。若要新增一级菜单，改 `src/layouts/navigation.ts` 一处即可同步侧栏、顶栏面包屑与高亮判定。

## 三、导航结构与业务映射

一级菜单严格四项，映射到现有路由，不新建业务页：

- 首页 → `/home`（新建仪表盘；`/` 重定向到此处）
- 工作台 → `/workspace/home`（复用既有工作台页，右栏补“工作台模块”卡片）
  - 项目管理 → `/projects/workflow`
  - 项目文件管理 → `/post/delivery`
  - 创作任务管理 → `/tasks/list`
- 素材库 → `/assets/library`（复用资产页，标题与术语改为“素材库”，八类素材统一管理）
- 插件市场 → `/plugins`（新建）
- 底部固定功能区（`margin-top: auto`）：设置 → `/settings`，下接当前身份卡；设置内含个人信息、账号安全、系统偏好

顶栏右侧保留“功能索引”入口，把原来挂在侧栏的 52 条业务路由按权限分组收进抽屉。这样既满足“四个一级菜单 + 底部设置”的规范，又不牺牲任何既有页面的可达性；面包屑对未归属到四个菜单的页面显示“功能索引 / 页面名”。

关于“插件市场”的产品边界：项目章程明确不开放第三方公网市场，因此这里落地为“内部插件中心”——只登记平台内置与内部团队维护的插件，安装仅记录本机启停状态、不加载任何外部代码，页面上写明了这条边界。

## 五、样式导入顺序（改样式前必读）

`src/main.ts` 的顺序是 `studio/base.css → studio/components.css → studio/studio.css → styles/app.css → studio/theme-light.css → styles/theme.dark.css`。

`theme-light.css` 仍在链路里，是因为它除了配色还定义了 `status-strip`、`asset-thumb`、`script-paper` 这些组件的版面结构；直接摘掉会让统计条塌成单列、素材缩略图失去边框。现在它的角色是“结构基线”：只贡献布局，配色由后面的 `theme.dark.css` 覆盖。凡是发现新的亮色块，处理方式是在 `theme.dark.css` 末尾追加同名选择器覆盖，而不是回头去改结构基线。

## 七、已知限制

- `/home` 现在是默认落地页，原来直接进工作台的用户会先看到仪表盘；如需恢复“进站即工作台”，把 `router/index.ts` 的重定向目标改回 `/workspace/home` 即可，其余不用动。
- 侧栏折叠态只显示图标，52 条业务入口在折叠态下需通过顶栏“功能索引”进入；这是为满足“四个一级菜单”规范做的取舍。
- 结构基线里仍有少量深底浅字的字面量（如 `.frame-tag`）在暗色下反而正确，故未覆盖；后续新增组件请一律用 `--ds-*`。
